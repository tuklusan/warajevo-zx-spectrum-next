# CR-0218 Keep EAR_MIC Reserved and Unavailable

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Keep `EAR_MIC` representable as the third networking-mode enum value.
- Reject attempts to activate `EAR_MIC` before Architecture #3 certification.
- Reject the request before changing machine state, preserving the prior mode
  and canonical hash on failure.
- Preserve valid `NONE` and `INTERFACE1` selection behavior.
- Keep Interface-1, Microdrive, original ZX Net, routed MIC/EAR behavior, and
  any resident stack activation out of this CR.
- Provide deterministic test coverage for rejected activation on the supported
  48K and 128K profiles where applicable.

## Upstream Completeness Gate

Compare the mode setter, initialization/destruction, serialization validation,
UI availability rules, architecture sections 24.1 and 24.6, CR-0215/0216, and
the preserved `OPTIONE`/Interface-1 activation behavior. Confirm that a reserved
mode is visible to state/schema code but cannot falsely activate routed hardware
or mutate the current machine before its downstream architecture gate.

## Upstream Discovery

The preserved implementation activates Interface 1 only after its external ROM
and configuration checks. The new architecture explicitly reserves `EAR_MIC`
until the Architecture-#3 48K Issue-2 profile is certified and requires a
machine-readable unavailable result without state mutation. The current setter
checks only enum range, leaving this boundary incomplete.

## Disposition

- Reject pre-certification `EAR_MIC` activation with
  `WZ_RESULT_UNSUPPORTED_OPERATION`: `IMPLEMENT_NOW`.
- Preserve enum representation and native-state recognition: already present.
- Interface-1 device activation and cold reconfiguration: ordered follow-on
  CRs.
- Architecture-#3 router, resident stack, and physical acceptance: `DEFERRED`.

## Zero-Gap Exit Scan

Before closure, rescan every mode setter/getter, initialization/destruction
path, serializer/deserializer, hash path, UI availability reference, and test.
Confirm rejected activation leaves the entire machine state unchanged and does
not introduce an emulator-only networking implementation.

## Evidence and Exit Gates

- Exact-SHA CODE, DOCUMENTATION, and independent bootstrap reviews pass with
  zero confirmed findings.
- Static repository gates and `git diff --check` pass locally; no local build or
  test is performed.
- Remote Linux, Windows 10/11, Intel Mac, and hosted matrix validation pass.
- A second upstream zero-gap scan is recorded before closure.
