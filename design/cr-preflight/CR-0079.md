# CR-0079 Migration Preflight

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Keep partial ULA port-FE decoding enabled for ordinary machine execution.
- Add an explicit deterministic CPU-vector fixture mode that routes synthetic
  I/O through its provider without claiming to validate hardware decode.
- Make the fixture mode opt-in and visible in test setup; never silently infer
  it from a callback or port address.
- Preserve bus request addresses, timing, observer ordering, and all ULA
  behavior when hardware decoding is enabled.

## Upstream Discovery

The preserved Spectrum reference decodes port `254` as the ULA path, while the
pinned Fuse corpus supplies CPU-level I/O expectations through a synthetic
provider. Neither defines this project-owned separation between CPU-vector
conformance and hardware I/O certification.

## Zero-Gap Exit Scan

Re-scan machine initialization, I/O read/write dispatch, CPU-vector runner
setup, project-owned port-FE tests, provider fallback, and every state reset.
Close only when hardware decode remains the default and the complete Fuse
corpus passes through an explicit fixture mode.

## Disposition

Add a machine flag defaulting to hardware decode. The Fuse runner explicitly
disables hardware decode for its flat CPU fixture; project-owned machine tests
retain the default and verify partial port-FE routing.

## Closure Evidence

Closure status: CANDIDATE
