# CR-0292 Snapshot save destination workflow

Status: IN_PROGRESS
Priority: high
Execution order: architecture_2_phase_12o
Blocking: no

## Functional Inventory

- Track the current host snapshot destination separately from machine state.
- Let `snapshot.save` reuse the current destination when one exists.
- Request a destination for `snapshot.save` when none exists.
- Make `snapshot.save_as` always acquire a new destination.
- Commit a newly acquired destination only after successful acquisition.
- Keep destination acquisition host-only and independent of remote execution.

## Upstream And Architecture Discovery

- UI Architecture Sections 8.3 and 13.1 require the distinct Save Snapshot and
  Save Snapshot As parameter-acquisition behavior.
- The legacy snapshot workflow retains a selected save filename and reports
  cancellation or write failure without replacing the prior destination.
- Core serialization and format-specific writers already exist; this CR owns
  only the application destination state seam.
- No deterministic core, transport, local/hosted harness, or wrapper changes
  are allowed.
