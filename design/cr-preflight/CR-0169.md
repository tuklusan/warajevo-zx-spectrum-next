## CR-0169: Migrate the serialized review gate to NVIDIA NIM

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Replace the depleted external review service with NVIDIA NIM while retaining
the evidence-bound review protocol, serialized execution, fail-closed behavior,
and all existing queue authorization boundaries.

## Functional Inventory

- Preserve the existing CLI commands, review types, immutable snapshot identity, and fail-closed verdict contract.
- Preserve complete bounded evidence packets, requirement authority, private-scope handling, and untrusted-data framing.
- Read the reviewer credential only from `NVIDIA_API_KEY_CODING`; never include it in prompts, errors, telemetry, or artifacts.
- Use the NVIDIA NIM chat-completions endpoint and exact model `nvidia/nemotron-3-ultra-550b-a55b`.
- Map disabled/enabled reasoning to `extra_body.chat_template_kwargs.enable_thinking` and map phase budgets to `reasoning_budget`.
- Preserve non-streaming JSON response validation, truncation handling, schema repair, deadline enforcement, lock cleanup, and serialized reviews.
- Retry transient transport/service failures with bounded exponential backoff; HTTP 429 and HTTP 404 are retryable, while permanent authorization and billing failures remain terminal.
- Preserve per-call telemetry without secrets, exact review receipts, bootstrap compatibility, and remote/hosted validation requirements.
- Add deterministic mocked coverage for the new request envelope, exact environment variable, HTTP 404/429 retry behavior, exponential delay sequence, and permanent failure behavior.

## Upstream Discovery

The upstream source was checked for this infrastructure-only change. No upstream product behavior is being replaced; the existing review protocol is retained unchanged. NVIDIA's official NIM model card, build instructions, and NIM API reference were read before implementation. They establish the exact model identifier, compatible chat-completions route, configurable reasoning template, and service-status behavior used by this migration.

## Disposition

Implement the provider migration in the existing gate entrypoint and preserve
the established CLI and telemetry schema. Do not alter product behavior or
reclassify earlier non-green review evidence.

## Upstream and Existing-Gate Comparison

The existing adapter's packet construction, validation, lock, deadline, and
receipt paths remain authoritative. The NVIDIA NIM documentation supplies the
new endpoint, model identifier, reasoning template, and service-status rules;
none of those replace upstream product behavior.

## Zero-Gap Exit Scan

Before closure, rescan the adapter, bootstrap path, tests, workflow references,
tracker, and official NIM contract to confirm no old provider request fields,
credential names, retry gaps, or untested failure paths remain.
