# CR-0089 Preflight: Memory and I/O Safety Fuzzing

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Fuzz and sanitizer-check the memory and I/O access helpers for bounds,
overflow, invalid-state, null, and arbitrary-address safety without changing
the defined 48K bus behavior.

## Functional Inventory

- Exercise all 16-bit memory and I/O addresses, including ROM/RAM boundaries.
- Exercise arbitrary master ticks, T-state durations, and contention inputs.
- Exercise every bus cycle kind and invalid enum value.
- Exercise null machine, null request, null callbacks, and uninitialized
  optional providers through their public contracts.
- Verify no out-of-bounds access, integer overflow, undefined behavior, or
  sanitizer report occurs.
- Preserve defined fallback values, ROM protection, ULA partial decode, source
  classifications, and deterministic trace/observer output.
- Keep fuzz generation and sanitizer execution on remote build/test machines;
  local work is limited to source edits and static gates.

## Upstream Completeness Gate

Architecture section 46 requires controlled invalid and unsupported paths, and
task 075 requires bounds, overflow, and invalid-state safety with clean
sanitizer runs. The preserved Warajevo source was scanned for address masking,
memory-map boundaries, port conversion, and invalid dispatch assumptions. The
portable WZSN helpers use fixed-width addresses but need adversarial execution
evidence across their public boundaries.

Authorities are architecture sections 7, 12, 36, 44, and 46; task 075;
`design/machine-timing-evidence.md`; CR-0088; and the preserved source under
`reference/original-warajevo/source/`.

## Upstream Discovery

Memory helpers accept `wz_word_t` addresses and guard null machine access;
bus dispatch applies contention before cycle-specific memory/I/O operations
and rejects unknown cycle values. Existing tests cover selected boundaries but
do not yet provide sanitizer-backed adversarial coverage for every public
helper and invalid request combination.

## Disposition

Add a deterministic fuzz-style safety fixture and a sanitizer-enabled remote
verification path. Keep valid behavior unchanged and classify any discovered
failure as an implementation defect rather than weakening the input domain.
Do not add model-specific bus behavior in this CR.

## Zero-Gap Exit Scan

Before closure, rescan memory read/write, ROM protection, I/O read/write,
interrupt acknowledge, contention arithmetic, source callbacks, observers,
traces, null handling, invalid enums, and state reset. Every discovered path
must be implemented, covered by the fixture, or explicitly deferred to a
named later task.

## Verification Plan

- Local static gate and source scan only; no local build or test execution.
- Remote Linux sanitizer-enabled CMake/CTest and complete pinned Fuse suite.
- Hosted platform smoke across Linux, Windows, and macOS targets.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote sanitizer/fuzz execution with deterministic seed and recorded logs.
