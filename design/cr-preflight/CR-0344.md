# CR-0344 Phase 12F ROM/Firmware Identity Boundary

Status: APPROVED_FOR_IMPLEMENTATION
Review-Base: 904c827285c136bc38b7ad135c13d7479f6c57dd
Priority: high
Execution order: ARCHITECTURE_2_PHASE_12F
Blocking: YES

## Functional Inventory

- Provide an explicit ROM/Firmware identity model for the Settings surface.
- Keep machine-model selection separate from ROM selection.
- Apply the core architecture's ROM hash and licensing policy before a ROM is
  accepted or exposed as selectable.
- Report unavailable, invalid, unlicensed, or hash-mismatched ROMs without
  mutating the active machine.
- Keep ROM bytes and host paths out of generic remotely discoverable settings
  metadata unless an explicit safe identity is available.

## Upstream Discovery

The authoritative preserved upstream source is commit
`94f69bd8f4acb6c0c320ae34f9b1c3ee29bc5545` of
`https://github.com/tuklusan/warajevo-spectrum-2.50.git`, imported under
`reference/original-warajevo/source/src/`. The zero-gap scan covered the broad
ROM/firmware/license domains and these exact files/symbols:

- `environment/SETUP.PAS`: `ROMsetting`, `ROM`, `Parse`, `SaveCfg`, and the
  `OldRom`/`Spec2`/`FastBas`/`Invcur` settings fields.
- `environment/WARAJEVO.PAS`: `cm_ROM`, `cm_tromwara`, and command dispatch
  around the legacy ROM/settings dialogs.
- `spectrum-kernel/SPECSIM.ASM`: `ROMLOAD`, `IME`, `IMEI1`, `IME1`, `IME2`,
  `IMEP1`, `IMEP2`, `LRERROR`, `LRIERROR`, and the ROM file-open paths.
- `zx-compiler/CONVROM.PAS`: `ZX48.ROM` input and `ROM48.ASM` conversion.
- `reference/original-warajevo/README.md`: imported-source provenance and
  exclusion of upstream ROM images.

Individual dispositions from that scan:

- `IMPLEMENT_NOW`: explicit byte identity/hash validation and licensing gate
  in the WZSN core/application boundary.
- `REIMPLEMENTED_DIFFERENTLY`: legacy filename-driven ROM loading in
  `ROMLOAD`, `IME*`, and `CONVROM`; WZSN accepts caller-owned bytes and a
  profile-owned expected identity, with no host path in settings metadata.
- `NOT_APPLICABLE`: legacy `ROMsetting` patch toggles (`Spec2`, `FastBas`,
  `Invcur`) and machine/Interface-1 ROM switching; these are not the explicit
  ROM identity contract in UI §23.4 and are not silently reproduced.
- `DEFERRED_WITH_CR`: legacy ROM variants, Interface-1 firmware selection, and
  any redistribution packaging decision beyond the current licensing input;
  they require their own architecture-scoped CR.

The current repository scan also covered `src/core/wz_machine_profile.h`,
`src/core/wz_machine.c`, `src/app/wz_rom_settings.*`, `src/app/wz_ui_layout.c`,
and `tests/wz_rom_settings_tests.c`. No harness, wrapper, or Architecture #3
work is in scope.

## Disposition

`IMPLEMENT_NOW`: define the smallest explicit ROM identity and validation
boundary required by the architecture, then expose it through one shared host
settings surface. Preserve active machine state on every rejected selection and
keep selection separate from machine model changes.

The implementation boundary is `src/app/wz_rom_settings.*`, backed by the
existing profile identity contract in `src/core/wz_machine_profile.h` and
`src/core/wz_machine.c`; regression coverage is in
`tests/wz_rom_settings_tests.c`.

## Zero-Gap Exit Scan

The repeated scan accounts for identity, byte/hash verification, licensing
state, valid/invalid/unavailable selection, active-state immutability, model
separation, safe metadata projection, keyboard/cancel/error behavior, and
remote/hosted evidence. The dispositions above cover every discovered
upstream ROM behavior; no undispositioned behavior remains. Re-run this scan
before closure and record any newly discovered path here.
