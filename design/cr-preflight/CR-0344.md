# CR-0344 Phase 12F ROM/Firmware Identity Boundary

Status: APPROVED_FOR_IMPLEMENTATION
Priority: high
Execution order: ARCHITECTURE_2_PHASE_12F
Blocking: YES

## Functional Inventory

- Provide an explicit ROM/Firmware identity model for the Settings surface.
- Keep machine-model selection separate from ROM selection.
- Apply the core architecture's ROM hash and licensing policy before a ROM is
  accepted or exposed as selectable.
- Report unavailable, invalid, unlicensed, or hash-mismatched ROMs without
  mutating the active machine.
- Keep ROM bytes and host paths out of generic remotely discoverable settings
  metadata unless an explicit safe identity is available.

## Upstream Discovery

- UI Architecture Section 23.4 requires explicit ROM identity and a core-owned
  hash/licensing policy; machine selection may not be hidden in ROM settings.
- The preserved upstream source and tracked reference ROM material were
  inspected for ROM loading and identity behavior. They do not provide a
  portable WZSN settings API or an already-integrated identity policy.
- The current repository contains no `src` ROM/Firmware identity, validation,
  or settings module. This is therefore a genuine implementation gap, not a
  safe reconciliation with an earlier CR.
- The implementation must establish the core/application ownership boundary
  before a GUI settings surface is added. No harness, wrapper, or Architecture
  #3 work is in scope.

## Disposition

`IMPLEMENT_NOW`: define the smallest explicit ROM identity and validation
boundary required by the architecture, then expose it through one shared host
settings surface. Preserve active machine state on every rejected selection and
keep selection separate from machine model changes.

## Zero-Gap Exit Scan

The implementation must account for identity, byte/hash verification, licensing
state, valid/invalid/unavailable selection, active-state immutability, model
separation, safe metadata projection, keyboard/cancel/error behavior, and
remote/hosted evidence. Re-scan the preserved ROM paths before closure.

## Exit Gates

Close only after focused CODE and DOCUMENTATION review, remote validation,
hosted matrix validation, inspected evidence, and publication inspection for the
exact published commit. No local build or test is permitted.
