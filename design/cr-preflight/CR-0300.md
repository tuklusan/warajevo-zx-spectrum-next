## Change Request
CR-0300: Bind toolbar Screenshot to the GUI screenshot workflow

Status: APPROVED_FOR_IMPLEMENTATION
Priority: high

## Functional Inventory
- Activate the toolbar Screenshot item through the shared command registry.
- Use the stable command ID `host.screenshot.save` and its registered GUI handler.
- Preserve the GUI screenshot workflow's destination acquisition and PNG encoder delegation.
- Do not call the Telnet `SCREENSHOT` temporary-path or timestamp-naming behavior.
- Use the same registry availability predicates and result/error semantics as menus and other front ends.
- Reject an invalid toolbar index or unavailable registry without invoking a handler.
- Preserve handler arguments and handler context unchanged.
- Do not mutate deterministic machine state or duplicate screenshot/file-writing logic.

## Upstream Discovery
The UI architecture Section 24.2 requires the toolbar Screenshot action to
invoke the GUI save-screenshot workflow and explicitly excludes the Telnet
temporary-path naming rule. Section 24.3 requires toolbar state to use the
command-registry predicates. Task 295 is the derived implementation task.
The preserved upstream source was searched for toolbar, screenshot, and
temporary-path behavior; no portable toolbar or GUI command-registry seam is
present there. The legacy screenshot behavior remains represented by the
architecture contract, with no additional undispositioned upstream behavior.

## Disposition
`IMPLEMENT_NOW`: add a generic registry-backed toolbar activation seam. The
toolbar's existing stable command ID selects the registered GUI handler, so
the Screenshot item naturally reaches `host.screenshot.save` without any
Telnet-specific path. Native widget event translation remains host integration
work and is deferred with the existing host UI implementation.
