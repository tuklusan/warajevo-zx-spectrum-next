# CR-0091 Preflight: Phase-3 Bus, Contention, and Interrupt Evidence

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Run the Phase-3 evidence suite for the shared bus, 48K contention model, and
maskable-interrupt path. The work is complete only when every timing-visible
divergence is reproduced, classified against preserved Warajevo behavior and
hardware evidence, or assigned to an explicitly deferred architecture task.

## Functional Inventory

- Exercise memory-read, memory-write, I/O-read, I/O-write, and interrupt-
  acknowledge bus requests through the shared dispatch path.
- Cover 48K PAL contention at the documented contended/uncontended boundaries,
  including exact delay, request tick, and same-edge ordering.
- Cover profile-driven interrupt assertion, deassertion, CPU sampling, and
  interrupt-acknowledge ordering across frame and instruction boundaries.
- Verify request direction, data source, contention delay, interrupt state, and
  trace event classifications remain deterministic and serializable.
- Repeat representative workloads and compare canonical state, trace, and
  master-tick results without host-dependent fields.
- Include negative and boundary cases for unmapped I/O, contention edges,
  disabled interrupts, HALT, and an interrupt arriving on a sampling edge.
- Capture unexplained divergences as machine-readable evidence; do not weaken
  assertions to make a reference comparison pass.

## Upstream Completeness Gate

Architecture sections 13, 14, 36, 44, 49.1, and 51 require bus ownership,
contention, interrupt timing, trace visibility, and evidence-backed treatment
of differences. The preserved source under
`reference/original-warajevo/source/src/spectrum-kernel/` is the source-level
authority, while real-hardware evidence is authoritative when the legacy
reference is an approximation.

Authorities are architecture sections 13, 14, 36, 44, 49.1, and 51; task 077;
`design/machine-timing-evidence.md`; CR-0082 through CR-0090; and the
preserved `SPECSIM.ASM` and `Z80.ASM` source paths.

## Upstream Discovery

Existing CRs provide isolated contention, interrupt scheduling and sampling,
timed data-source, trace-classification, controlled-I/O, sanitizer, and
differential fixtures. A combined Phase-3 evidence suite is still required to
prove that these boundaries compose without an unexplained timing divergence.
The discovery scan must include every preserved bus, contention, interrupt,
sampling, HALT, frame-boundary, and trace path relevant to the scoped 48K
behavior and name every later-phase exclusion.

## Disposition

Add or extend project-owned evidence fixtures and the remote harness so the
combined suite exercises the production path, not test-only shortcuts. Bind
each result to the preserved reference identity, documented hardware evidence,
and a canonical result schema. Classify matches, WZSN defects,
legacy-reference approximations, and hardware-authority overrides.

## Zero-Gap Exit Scan

Before closure, rescan preserved bus dispatch, memory/I/O contention tables,
ULA and fallback sources, interrupt edges, CPU sampling, HALT behavior, frame
boundaries, trace serialization, canonical state/hash participation, and
divergence reporting. Every discovered behavior must be implemented, covered,
classified, or explicitly deferred to a named later task.

## Verification Plan

- Local static gate and source/document scan only; no local build or test.
- Remote Linux evidence suite with sanitizer option where applicable, all CTest
  targets, and the complete pinned Fuse corpus.
- Remote Windows smoke and screenshot path where the interactive application
  surface is exercised.
- Hosted repository gates and platform smoke across the supported matrix.
- CODE, DOCUMENTATION, and TEST_ARTIFACT advisory reviews against this
  preflight and immutable evidence receipts.
- Repeat the combined suite and compare canonical machine-readable results.

## Closure Evidence

To be completed only after implementation, advisory reviews, remote validation,
hosted validation, and the final upstream zero-gap scan all pass.
