# CR-0249 Implement Minimum Breakpoint Support

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Provide a shared breakpoint API over the one live machine and existing
  scheduler/CPU, without a debugger-owned executor or second memory model.
- Install, replace, remove, and inspect a bounded set of address breakpoints
  with deterministic validation and duplicate handling.
- Preserve the original instruction byte and mapped-page context before any
  instrumentation; restore it exactly on removal or replacement.
- Detect a breakpoint at the correct fetch boundary, stop before executing the
  target instruction, and emit deterministic trace evidence.
- Define ROM, 48K/128K mapping, address-wrap, already-installed, capacity, and
  invalid-argument behavior without mutating canonical state on failure.
- Keep stepping, continue, conditional expressions, UI presentation, and
  breakpoint persistence outside this minimum API.

## Zero-Gap Exit Scan

The broader scan covers breakpoint lifecycle, duplicate/capacity behavior,
instruction-fetch timing, original-byte restoration, 48K/128K mapped-page
context, ROM protection, failure atomicity, trace emission, and neighboring
step/continue paths. No undispositioned behavior remains.
