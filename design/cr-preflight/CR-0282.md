# CR-0282 Basic Main-Window Acceptance Subset

Status: IN_PROGRESS
Priority: HIGH
Execution order: ARCHITECTURE_2_PHASE_12F
Blocking: NO

## Functional Inventory

- Make the initial Sokol host present the running Spectrum surface as the
  primary application window rather than an empty host shell.
- Integrate the existing shared UI layout contract so the canonical top-level
  menus, toolbar quick controls, status line, and optional status panel are
  represented by one host-window composition boundary.
- Keep command IDs and state ownership in the existing registry/core seams;
  this CR must not introduce duplicate command handlers or canonical machine
  state.
- Preserve keyboard quit behavior, lifecycle idempotence, host-only presentation
  settings, and deterministic machine state while drawing the initial window.
- Add focused acceptance coverage for host composition and the existing UI
  contract without requiring local build or test execution.

## Upstream And Architecture Discovery

- UI Architecture Section 48 items 1-6, 22-24, 41, 44, 49-50 define the
  initial acceptance slice: canonical menus, primary display, shared registry,
  toolbar, speed/status visibility, keyboard operation, state isolation, and
  regression coverage. Sections 18, 23, 24, and 25 define the presentation,
  shared Display surface, toolbar, and status contracts used here.
- The legacy reference supplies the expected primary display/window concept,
  but the modern implementation must retain the architecture's shared
  semantic-command and host-presentation boundaries rather than reproduce a
  legacy shell or private UI state.
- Existing `wz_ui_layout` is the authoritative layout metadata and status
  projection; existing Sokol initialization is the host integration seam.
  Reuse those seams and the existing raster/presentation APIs. Do not change
  deterministic core behavior, transport behavior, or frozen harness/wrapper
  behavior.

## Exit Gates

Close only after exact CODE, focused TEST_ARTIFACT, final DOCUMENTATION,
remote/hosted validation, visual evidence where supported, and publication
inspection pass. Hosted matrix work must be one final run for the CR group,
not one run per intermediate attempt. No local build or test is permitted.

## Implementation Boundary

- The new `wz_ui_window` seam is a host composition model only: it owns no
  canonical machine state and delegates layout metadata to `wz_ui_layout`.
- The Sokol host initializes and destroys that composition model at the same
  lifecycle boundary as the machine session. Existing harnesses and wrappers
  remain unchanged.
