# CR-0342 Phase 12F Audio Settings Reconciliation

Status: CLOSED
Priority: medium
Execution order: ARCHITECTURE_2_PHASE_12F
Blocking: NO

## Functional Inventory

- Keep Audio settings in the host output/presentation layer.
- Preserve emulated beeper and AY state as machine truth.
- Apply the frozen host-audio policy at 0.5x through 2.0x inclusive and mute
  host delivery outside that range, including Unlimited mode.
- Expose the resulting host-audio state in the UI without mutating machine
  state or emulated time.
- Treat invalid speed values as host-audio-disabled.

## Upstream And Architecture Discovery

- UI Architecture Section 23.2 defines host-only Audio settings and forbids
  turning historical host sound devices into emulated settings.
- Core Architecture Sections 10.10, 20, and 21 freeze the runtime-speed policy,
  canonical audio timeline, and push-delivery boundary.
- The preserved upstream source was inspected for its sound and presentation
  paths. It has historical host sound handling but no portable modern settings
  API to transplant.
- CR-0149 already implemented the pure host-audio policy, and the current UI
  status projection reports its audible/muted result. The existing speed-boundary
  and host-audio tests cover the complete defined contract.
- No additional volume, device-selection, or historical host-device setting is
  authorized by the architecture; no duplicate audio state is warranted.
