## Change Request
CR-0324: Expose cross-process Microdrive ownership outcomes in UI workflows

Status: CLOSED
Priority: medium

## Functional Inventory
- Preserve one exclusive writable claim per resolved Microdrive image across
  processes and path aliases.
- Surface a stable unavailable/ownership reason when another process holds the
  writer claim; never silently create a second writer.
- Permit only an explicit read-only fallback when the caller requests it and
  expose that fallback in manager state and labels.
- Release claims deterministically on eject, failure, and process shutdown;
  preserve existing OS-level locking semantics on Windows and Unix.
- Keep claim acquisition outside deterministic machine state and outside GUI
  parameter dialogs; route manager commands through the shared registry.
- Ensure destructive commands remain disabled for read-only claims and denied
  through the initial unauthenticated remote policy.

## Upstream Discovery
Upstream `MDRIVE.ASM` preserves cartridge write-protection state and the UI
architecture Section 44.1 requires interprocess exclusive ownership for
writable media based on resolved host identity. Sections 14, 15.2-15.4, 39,
45, 47, 48, and 51 define manager availability, disabled reasons, explicit
confirmation, and registry projection. The current host primitive is
`src/app/wz_host_media_ownership.c`; developer task 319 is the scope.

## Disposition
`IMPLEMENT_NOW`: add explicit claim outcomes and manager-facing availability
reasons, with tests for writable exclusion, requested read-only fallback, and
release. Do not weaken or replace the existing OS lock primitive.

Record zero unresolved gaps before validation.
