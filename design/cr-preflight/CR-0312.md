## Change Request
CR-0312: Expose applicable Warajevo-native tape maintenance operations

Status: APPROVED_FOR_IMPLEMENTATION
Priority: low

## Functional Inventory
- Represent applicability of exclude, linearize, implode, decompress, and
  compression-efficiency analysis for Warajevo-native tape media.
- Keep these operations out of ordinary TAP/TZX controls and expose them only
  through an Advanced Warajevo Tape or Compatibility Tools surface.
- Preserve deterministic operation ordering and explicit unsupported reasons.
- Do not mutate media or machine state merely by evaluating applicability.
- Keep the surface toolkit-neutral and leave transactional file replacement to
  the later atomic-save ticket.

## Upstream Discovery
UI architecture sections 12.3, 12.5, 20.2, 20.3, 20.4, 22, 45, and 48 define
the native-only visibility and failure boundary. Developer task 307 is the
derived backlog item. `src/core/wz_tape.h` already distinguishes native TAP
records from standard TAP/TZX data, and CR-0310/0311 provide the presentation
and block-operation boundaries. No required applicability rule remains
undispositioned.

## Disposition
`IMPLEMENT_NOW`: add a toolkit-neutral applicability model for the five native
maintenance operations. The model will report operation identity, label,
availability, and stable unavailable reason without claiming that the later
mutation/serialization implementation exists.

## Zero-Gap Exit Scan
Confirm all five native operations are represented, ordinary TAP/TZX media never
advertises them, unavailable reasons are stable, and applicability evaluation
has no file, machine-state, or GUI side effects.
