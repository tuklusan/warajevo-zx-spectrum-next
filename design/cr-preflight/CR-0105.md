# CR-0105 Preflight: Multicolor Memory-Write Versus Fetch Regression

Status: CLOSED

## Objective

Add an early deterministic multicolor-style regression proving that memory
writes become visible at the correct raster fetch positions without software
recognition or host timing.

## Functional Inventory

- Define a minimal attribute/data write-versus-fetch fixture.
- Verify same-edge ordering and the first subsequent fetch visibility.
- Verify writes after a fetch do not retroactively alter that fetch.
- Keep output represented as canonical raster samples and timing events.
- Preserve behavior across frame and visible-area boundaries.

## Upstream Completeness Gate

Rescan the preserved reference memory-write, ULA-fetch, raster, and timing paths
and the architecture rules for multicolor effects. Account for write ordering,
fetch visibility, contention, and invalid addresses; assign omissions to named
later tasks.

## Upstream Discovery

Existing core contracts already define timed writes, ULA fetch events, floating
bus behavior, and canonical samples. This CR adds a focused regression joining
those contracts for an early multicolor-style case.

## Disposition

Add a synthetic deterministic fixture using ordinary memory and ULA-fetch APIs.
Do not identify software patterns or move multicolor policy into host code.

## Zero-Gap Exit Scan

Before closure, rescan write timing, bitmap/attribute fetch order, same-edge
visibility, frame wrap, contention, and canonical sample ownership. Confirm no
scoped regression rule remains implicit.

## Verification Plan

- Local static gates and source scan only; no local build or test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux build/test with the regression and complete corpus.
- Hosted platform smoke across all supported labels.
- Compare deterministic fetch/event evidence across supported hosts.
