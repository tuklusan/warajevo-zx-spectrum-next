## Change Request
CR-0314: Enforce atomic failure behavior for tape mutation

Status: CLOSED
Priority: medium

## Functional Inventory
- Add a caller-owned tape mutation transaction over the existing Tape Manager
  edit backend.
- Preserve the original block image until an explicit commit succeeds.
- Reject invalid, malformed, read-only, or insufficient-capacity operations
  without changing the original image or transaction state.
- Make commit deterministic and idempotent only where the frozen contract
  permits it; no partial output or implicit file replacement is performed.
- Keep file I/O and atomic host replacement in the later shared output workflow.

## Upstream Discovery
UI sections 12.5, 20.1, 45, 47, and 48 require original-image preservation
on unsupported, malformed, read-only, and save failures. Developer task 309 is
the derived backlog item. CR-0311 supplies the existing caller-owned edit
backend, while CR-0313 establishes the manager presentation/report boundary.
The implementation must not add a second media format model or mutate the
source block array during failed preparation.

## Disposition
`IMPLEMENT_NOW`: add a bounded in-memory transaction that copies source blocks
into caller-owned working storage, exposes the existing edit operations against
that working copy, and commits only after explicit validation. Host file
replacement remains deferred.

## Zero-Gap Exit Scan
Confirm failed preparation and commit preserve source blocks byte-for-byte,
successful commit replaces the caller's destination only once, malformed/null
blocks are rejected, capacity limits are enforced, and no file or machine state
is touched.
