# CR-0216 Reconcile the Single Networking-Mode State

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Represent networking selection with one deterministic enum/state value only.
- Preserve exactly `NONE`, `INTERFACE1`, and reserved `EAR_MIC` values.
- Remove or reject any future implementation path that could represent
  independent Interface-1 and Ear+Mic booleans.
- Define fresh-machine and destroyed-machine initialization as `NONE`.
- Ensure the enum is the sole canonical state used by serialization and hash
  participation; do not add host transport state to the core value.
- Preserve the distinction between authentic Interface-1/ZX Net and the later
  Architecture-#3 routed MIC/EAR environment.

## Upstream Completeness Gate

Compare the current enum, machine initialization/destruction, native state
serialization, tests, and all mode-selection call sites against sections 24.1,
24.2, 24.6, and 25 of the core architecture, sections 5 and 23.5 of the UI
architecture, the frozen CR-0215 companion specification, and preserved
Interface-1 activation state in `SPECSIM.ASM`. Confirm no independent flags,
implicit defaults, or host transport state remain undispositioned.

## Upstream Discovery

The preserved source uses one Interface-1 activation state (`OPTIONE`) and
separate ROM-variant/presence state. The new architecture requires one public
networking mode, with Interface-1 device ownership only in `INTERFACE1` and
the routed mode reserved until Architecture #3. Existing `wz_machine_t` already
contains a single enum and initializes it to `NONE`; this CR audits and closes
the remaining contract boundary without claiming the later transitions.

## Disposition

- Single enum/state representation and default: `IMPLEMENT_NOW`.
- Structural mutual exclusion: `IMPLEMENT_NOW` through the enum boundary.
- `EAR_MIC` availability and cold reconfiguration: ordered follow-on CRs.
- Interface-1 device, Microdrive, and original ZX Net behavior: ordered
  follow-on CRs after CR-0215.
- Architecture-#3 routed networking and host transport: `DEFERRED`.

## Zero-Gap Exit Scan

Before closure, rescan all mode fields, setters/getters, state readers/writers,
hash inputs, UI availability projections, and tests. Confirm every mode is
represented once, initialization is deterministic, invalid values fail without
mutation, and no implementation silently activates Architecture #3 behavior.

## Evidence and Exit Gates

- Exact-SHA CODE, DOCUMENTATION, and independent bootstrap reviews pass with
  zero confirmed findings.
- Static repository gates and `git diff --check` pass locally; no local build or
  test is performed.
- Remote Linux, Windows 10/11, Intel Mac, and hosted matrix validation pass.
- A second upstream zero-gap scan is recorded before closure.
