# CR-0123 Preflight: Canonical Raster Presentation

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Upload and present the canonical raster through Sokol without modifying core
raster contents or changing deterministic machine behavior.

## Functional Inventory

- Define the host-facing raster upload boundary.
- Present the canonical source buffer without conversion in core code.
- Keep presentation enabled/disabled from changing headless raster hashes.
- Preserve lifecycle and failure behavior across supported host platforms.

## Upstream Completeness Gate

Compare the architecture raster contract, existing canonical raster/evidence
APIs, pinned Sokol capabilities, and preserved upstream behavior. Record every
format, dimension, ownership, and synchronization assumption before coding.

## Upstream Discovery

CR-0106 through CR-0108 define canonical raster evidence and diagnostics; CR-0121
defines the host shell. This CR adds only the presentation upload boundary.

## Disposition

Implement host presentation using the canonical raster as input. Do not move
pixel generation into Sokol or add scaling, shaders, or backend policy here.

## Zero-Gap Exit Scan

Close only when presentation-on/off equivalence, raster ownership, lifecycle,
and core isolation are evidenced on remote and hosted paths.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
