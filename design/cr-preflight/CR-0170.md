# CR-0170 Preflight: Deterministic WAV/PCM Tape Decode

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Implement the accepted WAV/PCM tape-input forms as deterministic canonical EAR
edges, without allowing host audio playback state, wall-clock pacing, or
device behavior to enter core tape state.

## Functional Inventory

- Validate RIFF/WAVE structure, chunk bounds, format fields, channel count, sample rate, and sample width before publication.
- Accept only the architecture-approved PCM integer forms and reject floating-point, companded, malformed, truncated, and overflowing input with controlled errors.
- Convert multi-channel samples to the defined deterministic mono level, including signedness and width handling.
- Apply the frozen threshold and hysteresis policy to emit canonical EAR transitions at exact master-time positions.
- Preserve sample-rate conversion determinism, fractional accumulation, silence, clipping, and end-of-input behavior.
- Use two-pass sizing and no-partial-publication semantics consistent with TAP and TZX loaders.
- Add adversarial fixtures for chunk ordering, padding, truncation, overflow, channel disagreement, threshold boundaries, hysteresis, and identical cross-host output.

## Upstream Discovery

The current project has no WAV decoder implementation. The architecture/media
matrix identifies WAV input as required and defines PCM, threshold, hysteresis,
mono, and canonical-time constraints. The preserved upstream source tree was
scanned for WAV/tape-input behavior; any source-level divergence must be
recorded during implementation rather than inferred from host playback code.

## Disposition

Implement a core WAV parser and deterministic edge generator only. Do not add
host playback, change TAP/TZX behavior, or publish partially decoded tape state.

## Upstream and Existing-Gate Comparison

Compare every accepted container/sample form and each threshold, hysteresis,
rounding, and end-of-stream rule against the architecture and upstream evidence.
Unresolved upstream behavior remains explicitly assigned rather than silently
omitted.

## Zero-Gap Exit Scan

Before closure, rescan the parser, tests, architecture matrix, and upstream
reference for every accepted PCM form, chunk-boundary case, conversion edge,
and failure path. Closure requires serialized review, remote and hosted
validation, clean publication evidence, and no undispositioned gap.

## Verification Plan

- Static repository gates and source inspection locally only.
- Serialized CODE and DOCUMENTATION reviews.
- Remote Linux and Windows smoke builds/tests through the approved harness.
- Hosted platform matrix and exact-run publication gate.
- Final upstream comparison and documentation review.

## Exit Gate

Close only when all inventory items are implemented or assigned to a later
ordered task, all required tests pass remotely and in hosted validation, and
the evidence is bound to one immutable published commit.
