# CR-0182 Isolated Temporary Snapshot State

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Own temporary snapshot bytes independently of the live machine.
- Use the canonical WZSN serialized representation and its exact length.
- Validate candidate bytes into a zeroed temporary machine only.
- Reject malformed length, version, profile, register, state, and memory data
  without changing the live machine.
- Preserve a validated candidate for a later atomic commit operation.
- Reject null objects and null/short input deterministically.
- Keep the object bounded and allocation-free for deterministic parser use.
- Keep historical SNA/Z80 parsing and commit integration in their ordered CRs.
- Preserve canonical headers, private artifacts, and remote-only execution.

## Upstream Discovery

The upstream snapshot implementation was scanned in
`src/environment/SNAPSHOT.PAS`, including its header reads, 48K loading,
decompression, register restoration, memory-page handling, and error paths.
The current project has no SNA/Z80 parser or writer, so this CR establishes
only the isolated state boundary required before those format parsers.

## Disposition

- Temporary serialized state object: `IMPLEMENT_NOW`; prerequisite task 170.
- Candidate validation away from live machine: `IMPLEMENT_NOW`; atomicity
  boundary for future parsers.
- SNA/Z80 byte parsing and compression: `DEFERRED_WITH_CR`; tasks 171-176.
- Atomic replacement of live state: `DEFERRED_WITH_CR`; task 177.
- Product behavior outside state validation: `NOT_APPLICABLE`.

## Zero-Gap Exit Scan

The second scan revisited the WZSN serializer, deserializer, machine ownership,
temporary storage bounds, null/short input behavior, upstream snapshot error
paths, and the ordered parser/commit tasks. No undispositioned behavior remains
for this boundary; no historical format parser is introduced here.

## Closure Requirements

- Static repository gates pass.
- Exact-SHA CODE and DOCUMENTATION reviews pass.
- Remote Linux and Windows smoke evidence passes.
- Hosted validation reaches its accepted cross-platform terminal evidence.
- Tests prove failed candidate validation leaves the live machine unchanged.
