# CR-0140 Preflight: Atomic Host Configuration Writes

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Prevent concurrent WZSN processes from corrupting a shared host preferences
file while preserving a complete old or complete new configuration view.

## Functional Inventory

- Acquire an interprocess exclusive lock before writing.
- Fail cleanly when another writer owns the lock; never overwrite its transaction.
- Write through a same-directory temporary file with restricted permissions.
- Flush the complete temporary file before replacement.
- Atomically replace the destination and clean up lock/temp files on success or failure.
- Handle zero-length data and invalid arguments deterministically on POSIX and Windows.
- Keep the primitive host-only and exclude dynamic runtime values from persistence callers.

## Upstream Completeness Gate

Inspect the preserved upstream configuration and preference persistence paths.
Compare file ownership, replacement, failure, and concurrent-process behavior;
retain the architecture's stronger host-data safety rule without introducing
configuration into canonical machine state.

## Upstream Discovery

The preserved upstream code treats user preferences as host data. The new
primitive therefore owns only transaction safety; preference schema, defaults,
and exclusion of dynamic Control Port values remain caller responsibilities.

## Disposition

Add a small C host primitive using `O_EXCL`/`rename` on POSIX and
`CREATE_NEW`/`MoveFileEx` on Windows. It deliberately uses a sidecar lock and
same-directory temporary file so a second writer cannot pass a check-then-write
race.

## Zero-Gap Exit Scan

Close only when simultaneous writers, lock contention, replacement atomicity,
failure cleanup, permissions, cross-platform behavior, and canonical-state
isolation have no undispositioned gaps.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
