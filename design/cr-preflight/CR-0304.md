## Change Request
CR-0304: Add screenshot pixel-source equivalence coverage

Status: CLOSED
Priority: medium

## Functional Inventory
- Encode the same completed presentation raster through GUI and Telnet-facing shared paths.
- Prove byte-identical PNG output for equivalent raster input.
- Prove host chrome, destination selection, and temporary-path naming are not pixel inputs.
- Preserve the canonical Spectrum raster sample values during encoding.
- Keep the test independent of a GUI toolkit, desktop, cursor, and window chrome.
- Do not alter screenshot runtime behavior or frozen harnesses.

## Upstream Discovery
UI Sections 8.4, 34.6, 47, and the frozen equivalence contract require GUI
Screenshot and Telnet SCREENSHOT to share the same raster capture and PNG
encoding path while differing only in host destination policy. Task 298 is the
derived backlog item. The preserved upstream source has no portable GUI/Telnet
pixel-equivalence test; the project-owned screenshot service is the canonical
boundary. No upstream behavior remains undispositioned.

## Disposition
`IMPLEMENT_NOW`: extend the shared screenshot-service regression with two
independently allocated output buffers and equivalent raster inputs, proving
identical PNG bytes and unchanged raster data. Destination/path and GUI chrome
are intentionally absent from the encoder input by architecture.

## Zero-Gap Exit Scan
Confirm identical raster inputs produce identical complete PNG bytes, raster
inputs remain unchanged, and the test contains no GUI chrome or destination
metadata in the pixel-source path.
