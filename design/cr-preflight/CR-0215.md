# CR-0215 Freeze Interface 1, Microdrive, and ZX Net Specification

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Freeze the single `NONE`/`INTERFACE1`/`EAR_MIC` networking-mode contract.
- Freeze Interface-1 low-byte port aliases `$E7`, `$EF`, and `$F7` and unrelated
  port preservation.
- Freeze Interface-1 ROM presence, identity, activation, paging, old/new ROM
  distinction, and atomic snapshot compatibility behavior.
- Freeze the `$EF` control latch bits, reset value, falling-edge motor shift,
  one-hot motor selection, and master-tick event boundary.
- Freeze MDR image validation, 543-byte sector geometry, header/data phases,
  checksum/GAP behavior, eight-slot ownership, and 9..254 sector limits.
- Freeze Microdrive read/write/protection/erase, motor position, cache, dirty
  state, flush, final-window truncation, and atomic failure behavior.
- Freeze original ZX Net states, data/control transitions, bounded block/bit
  collection, loopback boundary, deterministic timing fields, and serialization.
- Freeze canonical serialization/hash participation and explicit host/core
  boundaries without implementing device behavior in this CR.

## Upstream Completeness Gate

Read the complete preserved `MDRIVE.ASM` source line-by-line and re-read all
Interface-1 dispatch, activation, ROM-variant, and snapshot-restore paths in
`SPECSIM.ASM`. Reconcile every routine, state variable, port alias, reset value,
buffer boundary, checksum, cache transition, network state, and error path with
`design/interface1-microdrive-zxnet.md`. Any behavior not classified as
implemented, intentionally replaced at a host boundary, or explicitly deferred
blocks closure.

## Upstream Discovery

The preserved implementation uses `$E7` Microdrive data, `$EF` status/control,
and `$F7` network/serial data dispatch; a `$EE` control-latch initialization;
an eight-bit motor shift register; 543-byte sectors; 15-byte headers; 528-byte
blocks; eight-sector cache windows; write-protect and checksum/GAP state; and
`CLAIM`, `IDLE`, `BUSY`, `FREE`, `COLLREAD`, and `COLLWRITE` network states.
`SPECSIM.ASM` also proves Interface-1 ROM presence/variant state and activation
through `OPTIONE`, `ZXI1P`, `ZXI1OLD`, and `SETZXI1`.

## Disposition

- Companion specification and byte-level behavioral freeze: `IMPLEMENT_NOW`.
- Portable Interface-1/Microdrive/ZX Net C implementation: ordered follow-on
  CRs 0216 and later, after this specification gate closes.
- Interface-1 ROM acquisition/redistribution: ordered separate CR.
- Physical RS232, Architecture-#3 MIC/EAR routing, host Control Port, and
  unlicensed ROM embedding: `DEFERRED` or `OUT_OF_SCOPE`.

## Zero-Gap Exit Scan

Before closure, independently scan the complete `MDRIVE.ASM`, the relevant
`SPECSIM.ASM` dispatch and activation paths, the architecture sections, the UI
networking/media sections, the migration ledger, and the test authorities.
Confirm that the companion specification has no unresolved decision and that
every upstream behavior has a recorded disposition without silently importing
host file or packet timing into the deterministic core.

## Evidence and Exit Gates

- Exact-SHA DOCUMENTATION review and independent bootstrap review pass with
  zero confirmed findings.
- Static repository gates, JSON validation, and `git diff --check` pass locally;
  no local build or test is performed.
- The review packet identifies the exact specification and tracker changes.
- Remote and hosted validation are completed when the implementation CRs begin;
  this documentation-only CR does not claim device implementation evidence.
- A second upstream zero-gap scan is recorded before closing CR-0215.
