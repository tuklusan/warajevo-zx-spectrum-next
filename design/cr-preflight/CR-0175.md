# CR-0175: Genericize External Review Gate Artifact Names

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Replace provider-specific names in the active external review gate entrypoint,
test module, and authoritative workflow document with stable generic names. The
review endpoint, model, credentials, protocol, evidence format, and review
semantics remain unchanged.

## Functional Inventory

- Preserve the executable review-gate CLI commands and exit behavior.
- Preserve the configured NVIDIA NIM endpoint, model, and environment key.
- Rename the active gate script to a provider-neutral filename.
- Rename the active gate test module and update its imports and build hook.
- Rename the authoritative gate document and update every active authority path.
- Update remote-harness source validation and requirement-source receipts.
- Keep historical design material and closed-CR provenance accurate as history;
  do not rewrite old provider-era evidence into claims it never made.
- Ensure the canonical header and banned-word/publication gates still pass.
- Make no upstream product-code change; the preserved upstream tree has no
  authority over this project-specific reviewer naming convention.
- Perform static validation only on this machine; builds and tests remain remote
  or hosted activities.

## Upstream Discovery

The preserved upstream source was scanned for review-gate tooling, project
workflow, and reviewer artifact naming. It contains no corresponding project
review harness or authority for this repository's external-review workflow.
The migration is therefore a project-infrastructure naming change, not missing
upstream emulator behavior.

## Disposition

- `IMPLEMENT_NOW`: rename the active script to `tools/reviewer/review_gate.py`.
- `IMPLEMENT_NOW`: rename the active unit test to `tests/test_review_gate.py`.
- `IMPLEMENT_NOW`: rename the active authority document to
  `design/review-gate.md`.
- `IMPLEMENT_NOW`: update active imports, CMake registration, workflow text,
  requirement-source checks, command examples, and authority digests.
- `PRESERVE`: historical provider-era architecture material and closed-CR
  source-authority records, because they document prior decisions and evidence.
- `NOT_APPLICABLE`: emulator behavior and upstream compatibility behavior.
- `NOT_APPLICABLE`: local build or test execution.

## Zero-Gap Exit Scan

After implementation, rescan all active code, tests, harnesses, workflow
documents, and public authority references for the old filenames. Confirm that
only intentionally preserved historical provenance remains, that all active
paths resolve, and that the reviewer API/model configuration is byte-for-byte
unchanged apart from the authority-path constant.

- Run the renamed unit test and hosted matrix only through approved remote or
