# CR-0090 Preflight: Non-Raster Differential Scenarios

Status: CLOSED

## Objective

Run a small, deterministic set of non-raster programs and compare compatible
CPU, memory, I/O, and timing-visible outcomes against the preserved Warajevo
2.50 reference, classifying every divergence rather than silently treating it
as either a defect or an accepted difference.

## Functional Inventory

- Define stable program inputs, initial state, and termination checkpoints.
- Compare registers, flags, program counter, stack/memory effects, and
  canonical master-tick outcomes where the reference exposes them.
- Compare bus-visible memory/I/O operations using the CR-0087 classifications.
- Record exact reference identity and scenario provenance for each result.
- Classify matches, WZSN defects, legacy-reference approximations, and
  hardware-authority overrides.
- Keep raster, floating-bus, and model-specific peripheral behavior outside
  this non-raster scenario set.
- Ensure repeated runs produce identical normalized result records.

## Upstream Completeness Gate

Architecture section 39 requires differential testing against preserved
Warajevo 2.50 while treating real-hardware evidence as authoritative when the
legacy approximation disagrees. The preserved reference source under
`reference/original-warajevo/source/` is the source-level authority and its
identity is already recorded by the project. Existing CPU acceptance coverage
defines compatible register, memory, and timing outcomes but does not yet
provide a Phase-3 scenario manifest with divergence classifications.

Authorities are architecture sections 11, 36, 39, 44, and 51; task 076;
`design/cpu-acceptance-coverage.md`; CR-0089; and the preserved reference
source tree.

## Upstream Discovery

The project has complete Fuse Z80 conformance and project-owned CPU fixtures,
plus preserved reference source and timing evidence. It does not yet have a
tracked non-raster program manifest that binds each scenario to initial state,
termination, compared fields, reference boundary, and divergence disposition.

## Disposition

Add a compact scenario manifest and deterministic comparison fixture using
only portable, non-raster cases. Record classified outcomes as machine-readable
evidence. If a discrepancy is found, investigate it against the preserved
source and available hardware/reference evidence; do not weaken the comparison
to force a match.

## Zero-Gap Exit Scan

Before closure, rescan scenario loading, initial memory/register state,
instruction execution, bus records, contention, I/O, interrupts, termination,
hashing/normalization, preserved-reference identity, and divergence reporting.
Every discovered behavior must be implemented, covered, classified, or
explicitly deferred to a named later task.

## Verification Plan

- Local static gate and source scan only; no local build or test execution.
- Remote Linux differential harness plus complete pinned Fuse suite.
- Hosted platform smoke across Linux, Windows, and macOS targets.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Repeat normalized scenario runs and compare machine-readable records.
