# CR-0065 Migration Preflight

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Decode primary opcode `F9` as `LD SP,HL`: replace SP with HL while preserving
  all general registers, flags, MEMPTR, interrupt state, memory, and I/O state.
- Retain exactly one primary opcode fetch, advance PC and R once, and account
  for six T-states with no internal, memory, or I/O cycle after that fetch.
- Confirm `DD F9` and `FD F9` select IX and IY respectively. Their existing
  prefix path must retain its prefix fetch, PC/R progression, flags, MEMPTR,
  and no-write/no-I/O behavior.
- Remove only `f9` from the pinned Fuse unresolved baseline. Add deterministic
  primary and DD/FD regression coverage for state, timing, and bus traces.

## Upstream Discovery

The upstream primary dispatch table maps `F9` to `LDSPHL`; the DD and FD
tables map it to `LDSPIX` and `LDSPIY`. The shared `LDSP&RP` routine executes
`RF 6`, copies the selected register pair to SP, and returns. Its neighboring
`F0` through `FF` entries independently cover conditional return, POP AF,
branch, DI, conditional call, PUSH AF, OR immediate, restart, CP immediate,
and EI.

## Disposition

| Functional aspect | Disposition | Evidence |
| --- | --- | --- |
| Primary LD SP,HL | IMPLEMENT_NOW | Fuse `f9`, upstream `LDSPHL` |
| DD/FD LD SP,IX/IY retention | VERIFY_AND_REGRESS | upstream `LDSPIX` and `LDSPIY`, existing index-prefix path |
| Flags, MEMPTR, memory, and I/O preservation | IMPLEMENT_NOW | upstream register-copy-only routine and bus regression coverage |
| F0-F8 and FA-FF neighboring operations | FOLLOW_ON_CR | separate baseline entries and independently implemented families |

## Zero-Gap Exit Scan

Re-scan upstream primary, DD, and FD `F9` entries and the shared `LDSP&RP`
routine, plus the full `F0` through `FF` dispatch family. Close only when the
primary and prefixed forms pass remotely, exactly `f9` is removed from the
baseline, no extra bus activity occurs, and no undispositioned LD SP behavior
remains.
