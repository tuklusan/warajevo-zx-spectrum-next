## Change Request
CR-0331: Redesign external review packets around deterministic evidence indexes

Status: CLOSED
Priority: high

## Functional Inventory
- Preserve fail-closed review behavior for CODE, DOCUMENTATION, and
  TEST_ARTIFACT reviews while reducing redundant semantic transmission.
- Deterministically enumerate, classify, hash, and bind the complete evidence
  universe before packet construction.
- Send minimum-sufficient discovery packets, with exact bounded retrieval for
  indexed source, document, requirement, scope, and test-artifact evidence.
- Make a clean ordinary review one logical semantic discovery invocation when
  complete coverage is available; distinguish logical calls from transport
  retries and schema repair.
- Add complete hosted 20-lane evidence indexing, lane/group identity, anomaly
  detection, and exact ARTIFACT_SLICE resolution.
- Preserve immutable snapshot, provenance, data-policy, candidate,
  falsification, adjudication, receipt, lock, retry, deadline, and final-PASS
  invariants.
- Add conservative per-review-type budgets and telemetry proving local
  coverage, compact transmission, bounded expansion, and final revalidation.
- Ensure indexed evidence and reviewer telemetry remain private and ignored.
- Establish an independent maintenance/bootstrap trust chain; the modified
  normal gate must not certify itself.

## Upstream Discovery
- The attached operator-approved external review redesign is the behavioral
  authority for minimum-sufficient packets, deterministic indexes, bounded
  retrieval, telemetry, and regression coverage.
- `design/review-gate.md` defines the current review phases, verdict rules,
  data policy, and receipt contract.
- `tools/reviewer/review_gate.py` is the implementation under change.
- `tools/reviewer/legacy_bootstrap_gate.py` is the independent maintenance
  path and must be checked for dependency contamination.
- `tools/harness/verify_platform_evidence.py` and
  `.github/workflows/platform-smoke.yml` define the hosted evidence universe
  and its 20-lane publication contract.
- `WORKFLOW.md`, `tools/harness/harness-lock.json`, and existing reviewer
  tests/fixtures define local-only evidence, authorization, and frozen-harness
  boundaries.
- Existing CODE, DOCUMENTATION, and TEST_ARTIFACT fixtures were inspected;
  no unrelated workflow or product behavior is in scope.

## Disposition
`IMPLEMENT_NOW`: introduce a versioned deterministic index/manifest and
minimum-sufficient packet path inside the reviewer. Extend the resolver and
schema only where needed for exact bounded requests. Do not alter the external
review model, endpoint, key name, product code, hosted workflow, or locked
harnesses except where a later explicitly authorized correction proves required.

## Zero-Gap Exit Scan
After implementation, re-read the complete operator directive and every cited
project authority. Verify that each review type has complete local identity
binding, compact discovery, exact retrieval, final revalidation, and a
correctness-preserving fuller fallback. Verify that no candidate, request,
coverage assessment, or generated index can create a false PASS, and that all
required regression cases are represented by tests or an explicit retained
gap.

## Exit Gates
- Independent maintenance/bootstrap authorization must pass without relying
  on the modified normal gate.
- Exact CODE review of the redesign must pass before protected execution.
- All reviewer unit and regression tests must pass on approved remote/hosted
  systems; local execution is limited to static repository validators.
- Documentation must describe the new protocol and pass final review.
- No product matrix is required for a reviewer-only change unless the changed
  protocol affects protected execution; the workflow decision must be recorded.
