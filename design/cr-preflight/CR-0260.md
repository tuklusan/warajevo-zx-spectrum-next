# CR-0260 Add Application Diagnostic Block Load and Save Boundary

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Provide a bounded application-facing load operation for diagnostic/state
  blocks supplied by caller-owned memory.
- Provide a bounded application-facing save operation into caller-owned
  memory with explicit capacity and length results.
- Delegate format validation and state serialization to the existing state
  service; do not create a second machine or serialization implementation.
- Preserve atomicity: malformed or undersized input must not publish partial
  machine state or partial output.
- Keep file selection, host paths, dialogs, and UI presentation outside the
  deterministic core boundary.

## Upstream Discovery

- Re-read the complete `LOAD`, `SAVE`, `SAVEBLOCK`, `LOADFORMON`, `SAVEERR`,
  and related monitor branches in `SPECMON.ASM`.
- Compare their accepted/rejected block and error behavior with the existing
  snapshot/state serialization APIs and the architecture snapshot workflow.
- Re-read Architecture 1 sections 41, 44, 49.2, and 55.7 plus UI Architecture 2
  sections 13, 21, and 27.
- Inventory every existing state serializer, loader, diagnostic file writer,
  and application host boundary before implementation; classify each as the
  single shared route or explicitly local-only.

## Disposition

| Surface | Disposition | Reason |
|---|---|---|
| Caller-memory diagnostic block API | IMPLEMENT_NOW | Required shared application boundary |
| Existing state serializers | PRESERVE_AND_DELEGATE | Already validated format services |
| Host file I/O and dialogs | UI_OR_HOST_BOUNDARY | Must not enter deterministic core |
| Malformed/partial input | REJECT_ATOMICALLY | Preserve live machine state |
| Private paths and evidence files | LOCAL_ONLY | Workflow privacy rule |

## Zero-Gap Exit Scan

Before closure, compare every accepted and rejected `LOAD`/`SAVE` branch with
the new boundary, including empty, undersized, malformed, unsupported-format,
and successful blocks. Confirm that every format path has one owner and that
no host path or UI callback enters the core serializer.

## Required Evidence

- Shared bounded API and focused load/save, malformed-input, capacity, and
  atomicity regressions.
- Updated Phase-11 matrix naming the passing diagnostic-block regression.
- Serial CODE, TEST_ARTIFACT, and DOCUMENTATION reviews for the exact commit.
- Remote lab and hosted matrix validation with inspected manifests and private
  closure evidence.

## Exit Gates

CR-0260 may close only after the upstream zero-gap scan, exact-SHA reviews,
remote/hosted validation, evidence inspection, and publication gate pass.
