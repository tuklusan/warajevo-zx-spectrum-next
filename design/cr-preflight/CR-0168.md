# CR-0168 Preflight: Bind Hosted Matrix Publication to One Run

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Prevent a hosted validation result from being reported as green when it
belongs to a different run, commit, or incomplete matrix. The workflow must
publish one explicit aggregate gate for the exact GitHub run and commit that
triggered it, and that gate must fail when any matrix lane is not successful.

## Functional Inventory

- Preserve the complete configured runner matrix and `fail-fast: false`.
- Record the triggering `github.run_id` and `github.sha` in the aggregate gate.
- Require the matrix result to be exactly `success`; failed, cancelled, skipped,
  or incomplete lanes must not pass the aggregate gate.
- Query the current run's individual job records and require exactly the
  declared 18 lane names, each with the triggering SHA and `success` result.
- Keep per-lane artifacts available on failure for diagnosis.
- Do not infer green status from email subject, run ordering, or a prior run.

## Upstream Discovery

The existing hosted workflow and project workflow rules were inspected before
implementation. The hosted matrix had no aggregate publication boundary that
could bind its result to the triggering run and commit.

## Disposition

Implement only the hosted publication aggregate. Preserve the runner matrix,
per-lane artifact upload, and emulator/build behavior; do not change runner
selection or test semantics.

## Upstream and Existing-Gate Comparison

No emulator behavior is in scope. The existing workflow was inspected and had
per-lane execution but no single SHA-bound aggregate publication job. This CR
adds only the missing fail-closed publication boundary.

## Zero-Gap Exit Scan

Before closure, rescan the workflow, project gate validator, and hosted run
metadata to confirm run identity, commit identity, matrix completeness, and
failure propagation are all covered without relying on notification ordering.

## Verification Plan

- Static repository gates on the development machine only.
- Serialized CODE and DOCUMENTATION review.
- Remote smoke validation on Linux and Windows.
- Hosted validation of the exact commit, including the aggregate gate and all
  configured matrix lanes.

## Exit Gate

Close only after the exact hosted run has a successful aggregate gate, every
matrix lane is successful, review evidence is bound to the same commit, and
the project tracker records any earlier non-green evidence separately.
