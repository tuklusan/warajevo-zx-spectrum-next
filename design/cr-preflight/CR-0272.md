# CR-0272 Lock and Track All Working Harnesses

Status: APPROVED_FOR_IMPLEMENTATION
Priority: HIGH
Execution order: WORKFLOW_FIRST_OUT_OF_ORDER
Blocking: NO

## Functional Inventory

- Track every working local, hosted, remote-build, remote-test, screenshot,
  cleanup, transport, and parser harness in one lock manifest.
- Mark the manifest locked and require explicit operator authorization before
  any listed harness or governing gate is modified.
- Preserve proven behavior unless a concrete blocker is identified and the
  authorized correction is recorded in the active CR evidence.
- Separate interactive TTY command execution from non-TTY binary artifact
  transfer so Mac SSH authentication does not corrupt ZIP evidence.
- Keep private credentials and raw evidence outside tracked objects.

## Upstream Discovery

- Scan all tracked harness scripts and their workflow call sites.
- Compare the Mac authentication and artifact-pull paths with the proven
  manual SSH behavior and the existing project path/size rules.
- Perform a second scan after implementation to prove every listed harness is
  tracked and no binary transfer uses an interactive TTY.

## Required Evidence

- Exact-SHA CODE and DOCUMENTATION reviews.
- Published Mac smoke evidence proving a valid pulled archive and manifest.
- Hosted matrix publication gate with all lane evidence inspected.
- No local build or test activity.

## Exit Gates

Close only after the lock manifest, authorization rule, tracking inventory,
Mac binary transfer, serial reviews, remote/hosted validation, and publication
gates pass.
