# CR-0265 Freeze Phase-12 UI Toolkit and Integration Boundary

Status: CLOSED

## Functional Inventory

- Select one statically incorporable C UI toolkit for in-window controls.
- Keep the Spectrum viewport on the existing Sokol host presentation boundary.
- Freeze platform integration for Windows, Linux/X11, and macOS/Metal.
- Freeze text rendering, menus, file dialogs, accessibility, and settings
  persistence without changing semantic command IDs or machine state.
- Keep the deterministic core and headless tests independent of every UI and
  host dependency.

## Upstream Discovery

- Re-read the preserved Warajevo menu, setup, display, and file-selection paths
  under `reference/original-warajevo/source/src/environment` and classify their
  behavior as semantic command, native host presentation, or replaced UI.
- Compare the legacy behavior with UI Architecture 2 Sections 3, 4, 6-8,
  18, 23-25, 40, 43-45, and 49, and Core Architecture Sections 19, 27, 30,
  31, 43, 49.2, and 51.
- Verify the current Sokol pin, X11 decision, host presentation boundary, and
  command-registry contract do not require a toolkit inside deterministic core.

## Decision

| Surface | Frozen decision |
|---|---|
| In-window widgets | Nuklear, immutable revision recorded in `design/dependencies/nuklear-pin.md` |
| Spectrum viewport | Existing Sokol presentation boundary; Nuklear does not render machine truth |
| Windows | Sokol D3D11 host shell with native menu/file-dialog integration |
| Linux | Sokol X11 host shell with native file-dialog integration where available |
| macOS | Sokol Metal host shell with native menu/file-dialog integration |
| Fonts/text | UTF-8 application text converted at the host boundary; one bundled project font policy is deferred to the implementation CR |
| Menus | Semantic registry is canonical; native menus may relocate standard items, while in-window menu presentation is used for portable project actions |
| Accessibility | Keyboard navigation, focus order, labels, and actionable states are project-owned acceptance requirements; platform accessibility exposure is an implementation obligation of the host shell |
| Settings | Host-only, versioned, interprocess-safe settings store; never persist canonical machine state |

## Disposition

| Requirement | Disposition | Reason |
|---|---|---|
| Exact C toolkit | IMPLEMENT_NOW | Required Phase-12 entry decision |
| Native platform integration | IMPLEMENT_NOW | Required for host menus, dialogs, and accessibility exposure |
| New semantic commands | REJECT | Command-registry contract already owns semantics |
| Toolkit in deterministic core | REJECT | Violates the core dependency boundary |
| Full widget implementation | DEFER_TO_FOLLOWING_CR | This CR freezes the boundary only |

## Zero-Gap Exit Scan

The legacy source scan must account for menu placement, action enablement,
keyboard operation, file-dialog cancellation, text display, settings behavior,
and shutdown presentation. The exit scan must confirm each behavior has either
a frozen Phase-12 destination or an explicit architecture disposition, and that
no toolkit header, window handle, filesystem dialog, host clock, or persistence
path enters deterministic core code.

## Required Evidence

- Immutable toolkit pin and dependency provenance record.
- Updated Core and UI architecture decision sections.
- Serial CODE and DOCUMENTATION review of the exact decision snapshot.
- No build/test run is required for this documentation-only gate; implementation
  CRs must provide the full remote and hosted evidence gates.

## Exit Gates

CR-0265 may close only after the upstream zero-gap scan, exact-SHA reviews, and
the architecture documents agree with this decision. It does not authorize
higher-level UI implementation by itself.
