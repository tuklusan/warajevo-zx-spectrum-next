# CR-0233 Deterministic ZX Net Loopback Harness

Status: CLOSED

## Functional Inventory

- Provide a deterministic two-endpoint loopback harness for original ZX Net.
- Exercise claim and acceptance, BUSY/FREE repetition, collision read/write,
  block identifiers, bounded 256-byte payloads, and fixed timing counters.
- Drive both endpoints only through canonical device operations, never host
  sockets, files, wall-clock time, or thread scheduling.
- Emit reproducible state snapshots and failure diagnostics for every scenario.
- Reject malformed or overlong blocks without mutating either endpoint.

## Upstream Discovery

The complete upstream `MDRIVE.ASM` network state handlers and constants were
re-read for task 215. The loopback harness must reproduce the observable six
states and `BUSYLEN=5`, `FREELEN=5`, `NETDELAY=30` behavior without reproducing
the reference shared `.NET` file operation.

## Disposition

- In-process deterministic loopback harness and scenario manifest: `IMPLEMENT_NOW`.
- Host shared-file and future cross-process transport: defer to orchestrator work.

## Zero-Gap Exit Scan

Before closure, re-read the complete network handlers and verify every state,
counter, block-bound, collision, malformed-input, and reproducibility behavior
has a named scenario and retained evidence.
