# CR-0276 Separate Windows TTY Execution From Binary Archive Transport

Status: APPROVED_FOR_IMPLEMENTATION
Priority: HIGH
Execution order: WORKFLOW_FIRST_OUT_OF_ORDER
Blocking: YES

## Functional Inventory

- Preserve the existing TTY path for Windows interactive commands and
  screenshot/session operations.
- Use a non-TTY SSH channel for binary/base64 archive transport.
- Preserve strict base64 and ZIP integrity validation after transport.
- Keep parser-first PowerShell validation and all project-directory guards.
- Record transport failures separately from product build/test failures.

## Upstream and Regression Discovery

- Compare the successful Mac TTY/non-TTY separation in CR-0272 with every
  Windows `run_windows` and `pull_windows` call site.
- Confirm only the archive pull changes its allocation mode.
- Add a source-level regression assertion that `pull_windows` explicitly uses
  non-TTY execution and that `run_windows` retains its interactive default.
- Repeat the call-site scan after implementation for any other binary stream.

## Acceptance Gates

- Exact CODE review must pass on the authorized candidate.
- Windows 10 and Windows 11 remote smoke runs must complete archive pull,
  extraction, build/test, and evidence manifest generation.
- Hosted matrix and publication gate must pass for the exact commit.
- Serial TEST_ARTIFACT and DOCUMENTATION reviews must pass.
- Update the tracked harness lock evidence; no harness change is permitted
  outside this authorized CR.

## Exit Gates

Close only after both Windows lanes prove the corrected transport, all required
evidence is inspected, and the final documentation review passes.
