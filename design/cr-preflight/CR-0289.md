# CR-0289 Host-Only Recent File Metadata

Status: IN_PROGRESS
Priority: MEDIUM
Execution order: ARCHITECTURE_2_PHASE_12L
Blocking: NO

## Functional Inventory

- Maintain a bounded local Recent list for successfully selected paths.
- Keep newest entries first and de-duplicate an existing path.
- Bind every entry to the existing `file.open_run` semantic command.
- Support explicit removal without affecting machine state.
- Keep Recent metadata host-only and out of deterministic state or remotely
  discoverable registry metadata.

## Upstream And Architecture Discovery

- UI Architecture Sections 8.2, 39.1, and 44 require host-only Recent
  convenience metadata, clean removal of missing entries, and no remote path
  disclosure.
- The legacy reference Start workflow keeps a selected filename as an input
  to its common loader; the modern list preserves the common command seam and
  drops DOS-era global state and hidden path disclosure.
- CR-0287 supplies `file.open_run` dispatch. Persistence and file-dialog
  integration are separate later tasks.
- No deterministic core, transport, local/hosted harness, or wrapper changes
  are allowed.
