# CR-0087 Preflight: Deterministic Memory and I/O Trace Fixtures

Status: CLOSED

## Objective

Make deterministic bus fixtures record the complete bus-visible evidence
required by task 073: address, value, direction, canonical master tick,
contention delay, and data source. Prove that repeated fixture execution is
semantically identical without making host timestamps or host file I/O part of
the deterministic core.

## Functional Inventory

- Classify every bus request as read, write, or non-data/internal activity.
- Identify whether a value came from memory, ULA, a synthetic data source, the
  compatibility input provider, or the defined fallback.
- Preserve the contention-adjusted master tick and inserted delay in the
  recorded request.
- Preserve address and final bus value for reads and writes.
- Keep observer ordering identical to the existing trace ordering.
- Keep existing callers source-compatible where practical and preserve reset,
  null-callback, and invalid-request behavior.
- Compare complete fixture records deterministically across repeated runs.
- Do not alter canonical machine state or introduce host-clock dependence.

The acceptance fixture is the in-memory `bus_log_t` and
`record_bus_request` observer in `tests/wz_tests_placeholder.c`; it copies
complete `wz_bus_request_t` records into a fixed-size array and performs no
host file I/O, wall-clock sampling, or pointer-value serialization.

## Upstream Completeness Gate

The architecture's observability contract requires every externally visible
memory and I/O operation, contention delay, and floating-bus source/value to be
recoverable from deterministic trace evidence. The preserved Warajevo source
was scanned for memory/I/O dispatch and timing annotations; it has no portable
structured source identity contract that can be reused directly.

Authorities are architecture sections 13, 15.6, 36, 44, and 51; task 073;
`design/machine-timing-evidence.md`; CR-0086; and the preserved source under
`reference/original-warajevo/source/`.

## Upstream Discovery

WZSN already emits a structured bus observer request and a CPU bus trace event.
The request contains cycle, address, value, canonical tick, T-state duration,
and contention delay, but direction and value-source identity are implicit in
the cycle and dispatch code. The fixture cannot prove source identity without
making those classifications explicit at the bus boundary.

## Disposition

Add explicit direction and source classifications to the bus request, assign
them in the single bus dispatch path, and expose the same classifications to
the deterministic observer fixture. Preserve the existing binary trace layout
in this ticket; a later trace-schema ticket may extend serialized records once
the source taxonomy is frozen. Defer ULA fetch scheduling and final floating-
bus values to their named later tasks.

## Zero-Gap Exit Scan

Before closure, rescan all memory reads/writes, opcode fetches, I/O reads/
writes, interrupt acknowledge, synthetic data-source claims, compatibility
fallbacks, observer emission, structured trace emission, contention adjustment,
reset, and repeated fixture comparison. Every discovered behavior must be
implemented, covered, or explicitly deferred to a named later task.

## Verification Plan

- Local static gate and source scan only; no local build or test execution.
- Remote Linux CMake/CTest and complete pinned Fuse suite.
- Hosted platform smoke across Linux, Windows, and macOS targets.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Deterministic fixture vectors covering each direction/source combination,
  contention-adjusted timing, and repeated-record equality.
