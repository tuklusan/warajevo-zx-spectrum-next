# CR-0283 Control Port Status Label Reconciliation

Status: IN_PROGRESS
Priority: MEDIUM
Execution order: ARCHITECTURE_2_PHASE_12G
Blocking: NO

## Functional Inventory

- Always render a stable Control Port field in the status line.
- Render the selected numeric port when a listener is available.
- Render `Control Port: unavailable` after listener exhaustion or when no
  selected listener is available.
- Source the value from the shared UI layout state, preserving the transport
  and session-state ownership boundaries.
- Keep the behavior keyboard-safe and free of machine-state mutation.

## Upstream And Architecture Discovery

- UI Architecture Sections 25, 47, and 48.57-59 require the exact status
  alternatives, first-free transport ownership, and non-persistence of the
  selected port. The legacy reference contributes the visible listener
  concept; the modern contract is defined by the UI architecture.
- `wz_ui_layout_status_line` already implements both exact alternatives, and
  `wz_ui_layout_tests` covers unavailable and selected-port output. This is a
  reconciliation CR, not permission to add another Control Port store.
- No deterministic core, transport, harness, or wrapper change is allowed.

## Exit Gates

Close only after exact CODE reconciliation, focused TEST_ARTIFACT, final
DOCUMENTATION, remote/hosted validation, visual evidence where supported, and
publication inspection pass. No local build or test is permitted.
