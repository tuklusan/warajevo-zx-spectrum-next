# CR-0084 Preflight: Profile-Driven Maskable Interrupt Line Scheduling

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Implement deterministic profile-defined assertion and deassertion of the
48K maskable interrupt line at frame boundaries. Preserve the line as a
machine-level, level-triggered signal; CPU sampling and acceptance remain the
scope of task 071.

## Functional Inventory

- Define interrupt assertion and deassertion positions in each machine profile.
- Assert the 48K line once per 69888-T-state frame at the frame boundary.
- Hold the line low for exactly 32 CPU T-states, represented in master ticks.
- Reset the line deterministically with the machine.
- Advance and dispatch line edges through the deterministic headless runner.
- Record line edges with their exact master tick and preserve state across
  canonical serialization and deserialization.
- Keep CPU interrupt acceptance separate so the line can be tested before
  task 071 freezes same-edge sampling order.
- Reject invalid profiles and avoid arithmetic overflow at frame boundaries.

## Upstream Completeness Gate

The authoritative 48K reference states that the ULA generates one frame-
synchronized interrupt and holds `/INT` low for precisely 32 T-states. It also
states that the frame is 69888 T-states and that the CPU only samples the
level at instruction boundaries. The preserved Warajevo source was scanned
for its interrupt setup, `INT_8`, `PROCINT`, `IFF`, and frame/timing state.
The architecture authorities are sections 10, 14, 36, 44, and 51 of
`design/warajevo-zx-spectrum-next-architecture.md` plus tasks 070 and 071.

## Upstream Discovery

The preserved implementation uses a host timer interrupt to enter its
simulated interrupt path; it does not provide a portable master-tick event
model. The project scheduler and runner already provide the deterministic
master-tick boundary needed for migration. No upstream behavior is omitted:
periodicity, 32-T-state low duration, level semantics, IFF-gated CPU sampling,
and IM-specific acceptance are split between this CR and task 071 by design.

## Disposition

Implement only the profile/machine/runner line schedule in this CR. Add no
CPU acceptance shortcut and no host-clock dependency. Use 48K values of
assert-at-frame-start and deassert-after-32 T-states. Preserve the existing
128K profile as an explicit profile-defined schedule pending its later timing
evidence. Record the line edges in the existing timing trace and state format.

## Zero-Gap Exit Scan

Before closure, rescan the profile definitions, machine reset path, runner
tick path, trace taxonomy, state serialization, CPU interrupt helpers, task
071 ordering requirements, and the preserved reference interrupt/frame paths.
Every discovered behavior must be implemented here, explicitly deferred to
task 071, or explicitly deferred to later profile evidence. No implicit
host-time or CPU-side schedule is permitted.

## Verification Plan
