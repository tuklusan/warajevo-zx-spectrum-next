## Change Request
CR-0320: Implement Microdrive Manager overview

Status: APPROVED_FOR_IMPLEMENTATION
Priority: medium

## Functional Inventory
- Present all eight Interface 1 Microdrive slots in a stable manager overview.
- For each mounted cartridge, expose host image identity, logical cartridge name,
  sector count, write-protection state, current/default drive state, and
  format/validation status.
- Preserve an explicit empty/unmounted state for each slot without inventing
  host paths or silently selecting a drive.
- Source availability and disabled reasons from the shared command/state model;
  do not create a manager-only Microdrive backend or duplicate media semantics.
- Keep mount, eject, default, catalog, format, optimize, allocation, rename,
  and write-protect workflows owned by the manager as subsequent CRs.
- Keep logical-file and advanced-sector views as subsequent manager surfaces;
  this CR is the overview contract only.
- Preserve cross-process writable-media ownership and dirty/invalid media state
  as visible validation or unavailable status, without mutating media.
- Make current and default drive state distinguishable when they differ.
- Keep destructive operations out of this read-only overview and preserve the
  `MEDIA_DESTRUCTIVE` policy for later operations.
- Provide deterministic keyboard/focus order and labels for all eight rows.

## Upstream Discovery
Reference implementation: upstream Warajevo source and the project's retained
architecture authorities must be inspected before implementation. The required
legacy Microdrive Manager information set is UI architecture Section 15.1:
host image identity, logical cartridge name, sector count, write-protection
state, current/default drive state, and format/validation status. Sections 14,
15.2-15.5, 24, 45, 47, 48, and 51 constrain eight-slot preservation, shared
command ownership, destructive confirmation, accessibility, and state/error
behavior. Developer task 315 is the implementation scope.

## Disposition
`IMPLEMENT_NOW`: add the read-only eight-slot overview contract and regression
coverage, consuming existing Microdrive image metadata without adding media
mutation or a duplicate backend.

## Required Interfaces
- Stable manager row/control identifiers and labels must be documented before
  implementation.
- The overview must consume the shared Microdrive/media state contract and
  expose an explicit no-mutation/read-only presentation boundary.
- Any unavailable or invalid state must carry a stable reason suitable for GUI,
  tests, and future Telnet projection.
