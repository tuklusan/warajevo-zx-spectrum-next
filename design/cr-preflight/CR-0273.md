# CR-0273 Preserve External Command Handles After Output Truncation

Status: IN_PROGRESS
Priority: HIGH
Execution order: WORKFLOW_FIRST_OUT_OF_ORDER
Blocking: NO

## Functional Inventory

- Preserve the live process/session identifier when the first response exceeds
  the wrapper's output budget.
- Bound or redirect verbose first output without losing machine-readable handle
  metadata.
- Correlate wrapper responses with durable process state so recovery can poll,
  inspect, or terminate the original process rather than starting a duplicate.
- Distinguish an observation/serialization failure from command failure.
- Add a regression test for an intentionally oversized first response and a
  recovery test for a slow long-running command.

## Upstream and Tooling Discovery

- Inspect the execution-wrapper contract and current session serialization
  path before changing project harnesses.
- Compare the existing reviewer lock/state recovery path with the wrapper
  behavior; the reviewer lock remains authoritative during recovery.
- Do not change locked project harnesses unless the operator authorizes the
  concrete modification under CR-0272.

## Acceptance Gates

- CODE review must pass against the exact candidate snapshot.
- Documentation review must pass after the preflight and closure record are
  complete.
- TEST_ARTIFACT review must cover the wrapper regression evidence.
- No local build or test may be run; validation belongs on remote or hosted
  machines as applicable.
- No parallel reviewer packets may be active.

## Scope Note

The defect is in the outer execution wrapper, not in the Warajevo product
harness. This CR tracks the correction and prevents a lost handle from being
misclassified as a product, remote-machine, or reviewer failure.

## Implementation Boundary

- The outer execution wrapper is not a repository-owned source component and
  cannot be patched from this project.
- The project-owned correction is the tracked recovery and classification
  contract in `WORKFLOW.md`: bounded first responses, durable reviewer state,
  no duplicate launch, and explicit indeterminate observation handling.
- Any future repository-owned wrapper or launcher must be added to the locked
  tracked harness set before implementation and must satisfy this contract.

## Implementation Record

- Added `tools/harness/run_durable_session.py` as the tracked project-owned
  session boundary.
- It redirects verbose output to files, atomically records a running session
  before waiting, emits a bounded start event, and supports state-based
  polling or termination on Windows and Unix-like hosts.
- Added source-contract regression coverage and registered the wrapper in the
  locked harness manifest under explicit operator authorization.
