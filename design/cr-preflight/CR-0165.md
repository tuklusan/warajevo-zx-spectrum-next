# CR-0165 Preflight: Warajevo-Native TAP Writing

Status: CLOSED

## Objective

Implement bounded writing of the preserved Warajevo-native TAP container as a
separate format path from standard TAP. The writer must expose a caller-owned
output boundary, preserve defined native metadata, and never publish partial
output on sizing or validation failure.

## Functional Inventory

- Emit the native first-record pointer followed by the two little-endian
  `0xFFFFFFFF` marker words used by the preserved format.
- Write linked records with previous and next offsets, stored length, flag, and
  ordinary record type bytes using the native little-endian layout.
- Preserve the native special forms: length `65534` for sampled metadata and
  length `65535` for compressed metadata, including decompressed, compressed,
  and signed-length fields where supplied by the caller.
- Recompute all links from the final serialized offsets and terminate the last
  record with the native terminal link value.
- Validate representability, record ordering, payload lengths, and output
  capacity before exposing bytes; support sizing with a null output buffer.
- Keep standard TAP writing unchanged and reject invalid native input without
  silently routing it through the standard format.
- Add deterministic round-trip, metadata, sizing, capacity, and rejection
  coverage for ordinary and special native records.

## Upstream Discovery

The preflight source scan covers `reference/original-warajevo/source/src/environment/TAPES.PAS`
and `reference/original-warajevo/source/src/spectrum-kernel/TAPE.ASM`, with
special attention to `prazna`, `prepis`, `Readblocks`, `load`, `save`, `pack`,
and `unpack`. The scan confirms the native header, linked traversal, ordinary
record type byte, special sample/compressed metadata, and terminal-link
conventions. Maintenance transforms, compression algorithms, host file I/O,
and interactive tape editing are outside this CR and remain later ordered
work unless directly required to serialize caller-provided metadata.

## Disposition

Implement only native serialization, validation, sizing, round-trip fixtures,
and the controlled public API. Do not alter standard TAP routing, add native
compression/decompression algorithms, implement TZX/WAV support, or add host
file-system behavior.
