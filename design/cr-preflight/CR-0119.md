# CR-0119 Preflight: Pin Sokol Revision

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Select and pin the exact Sokol revision and record its source, license,
provenance, and intended dependency boundary before host implementation.

## Functional Inventory

- Identify the exact upstream Sokol repository and immutable revision.
- Record the applicable license and provenance notice.
- Define the vendored or fetched dependency boundary.
- Keep Sokol outside the deterministic core and headless test path.
- Document reproducible acquisition for remote and hosted builds.

## Upstream Completeness Gate

Compare the architecture host-shell requirements with the reference project,
existing dependency policy, and Sokol upstream licensing/provenance. Record any
unresolved version or distribution question as a follow-up CR.

## Upstream Discovery

The architecture requires Sokol host integration but no Sokol dependency is
currently permitted inside core machine, timing, raster, or trace modules.

## Disposition

Add only the pin and provenance records required for later host work. Do not
implement host callbacks or move deterministic behavior into the dependency.

## Zero-Gap Exit Scan

Close only when revision identity, integrity, license, provenance, acquisition,
and core-boundary rules are explicit and reviewable.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote and hosted repository validation.
- Final upstream zero-gap scan and publication evidence.
