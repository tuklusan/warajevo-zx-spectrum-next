# CR-0253 Enforce Complete UDP-Only Forwarding for Traces and Logs

Status: OPEN

## Scope

Follow up CR-0244 by proving that every approved project trace and diagnostic
log emission path is connected to one controlled forwarding boundary. Forward
records only over UDP to
`sanyalnet-oracle-vps2.duckdns.org:65514`, encoded as Unix syslog records.

## Functional Preflight

- Inventory every trace producer, diagnostic log producer, dump utility, host
  callback, and application-facing diagnostic path.
- Classify each record as forwardable, local-only, or explicitly excluded.
- Route every forwardable class through `wz_syslog_udp`; no second network
  transport, TCP fallback, implicit broadcast, or direct socket path is allowed.
- Preserve the full binary circular trace as a private local artifact; never
  transmit machine state, ROM bytes, memory contents, host paths, credentials,
  or personal data.
- Use bounded RFC 5424-style Unix syslog records with deterministic facility,
  severity, source metadata, sanitization, and oversize behavior.
- Keep DNS resolution, socket activity, failure handling, and backpressure
  non-blocking and unable to alter canonical machine state or halt execution.
- Make enablement explicit and default-safe; no record may be sent before the
  forwarding boundary is intentionally enabled.

## Upstream and Architecture Gates

Before implementation approval, re-read the complete preserved diagnostic and
trace paths in the upstream reference and compare them with both architecture
documents. Record every source, mapping, exclusion, and failure rule in the
implementation audit. The zero-gap exit scan must show no unclassified trace
or log producer and no behavior silently bypassing the sole transport.

## Required Evidence

- Static inventory showing all trace and diagnostic-log producers and their
  disposition.
- Contract tests for routing, Unix syslog framing, UDP-only behavior,
  sanitization, bounded packets, disabled mode, and failure isolation.
- Remote and hosted build/test results for applicable lanes.
- Inspected manifests, traces, and screenshots where supported, retained only
  in the private closure record under `test-artefacts`.
- Serial CODE, TEST_ARTIFACT, and DOCUMENTATION review packets for the exact
  implementation commit.

## Exit Gates

CR-0253 may close only after the upstream zero-gap scan, exact-SHA reviews,
remote/hosted validation, evidence inspection, and publication gate all pass.
Until then, CR-0244 remains the closed record for the existing transport
adapter and CR-0253 remains an open integration/completeness item.
