# CR-0264 Add Refresh and Monitor Presentation Boundary

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Provide an explicit read-only presentation snapshot boundary for monitor/UI
  consumers after a canonical raster projection is available.
- Expose stable frame dimensions, source raster identity, and frame sequence
  without allowing presentation code to mutate machine or raster state.
- Make refresh publication deterministic and idempotent, with replacement of a
  previously published snapshot only after the complete source frame is valid.
- Keep window scheduling, GPU upload, refresh pacing, and host event-loop work
  outside deterministic machine state and outside the presentation snapshot.
- Ensure presentation consumers can use the same source as later screenshots,
  while retaining the existing host crop/scaling boundary.

## Upstream Discovery

- Re-read the legacy `Screen`/video refresh, `drawview`, `video`, and teardown
  paths in `reference/original-warajevo/source/src/environment/WARAJEVO.PAS`
  and related video units; classify redraw triggers, frame replacement, and
  host-window responsibilities.
- Compare those behaviors with the current canonical raster buffer, read-only
  machine projection, Sokol raster upload, host presentation rectangle, and
  lifecycle boundary.
- Re-read Architecture 1 sections 16, 19, 27, 30, 31, 36, 37, and 49.2 and
  UI Architecture 2 sections 3.3, 3.4, 18, 24, 25, 40, 45, and 47.
- Confirm no UI refresh path becomes a second implementation of raster truth,
  no host timestamp becomes emulated time, and no Sokol type enters core APIs.

## Disposition

| Surface | Disposition | Reason |
|---|---|---|
| Presentation snapshot publication | IMPLEMENT_NOW | Missing Phase-11 monitor boundary |
| Frame replacement and sequence | IMPLEMENT_NOW | Deterministic consumer contract |
| Machine/raster mutation from presentation | REJECT | Violates core ownership |
| Sokol/GPU refresh scheduling | PRESERVE_HOST_BOUNDARY | Platform-specific host work |
| Scaling/crop policy | REUSE_EXISTING_BOUNDARY | Already covered by host presentation CRs |
| PNG/file output | DEFER_TO_SCREENSHOT_CR | Host write concern |

## Zero-Gap Exit Scan

Before closure, compare upstream redraw and refresh branches with initial,
repeated, replacement, invalid-source, and consumer-read cases. Confirm source
identity and frame sequence are stable, publication is atomic, consumers cannot
mutate the source, and no GUI, Sokol, socket, or wall-clock dependency enters
the deterministic core.

## Required Evidence

- Shared presentation snapshot API and focused refresh/publication regressions.
- Updated Phase-11 coverage matrix naming the passing refresh tests.
- Serial CODE, TEST_ARTIFACT, and DOCUMENTATION reviews for exact commits.
- Four remote lab harness runs and the complete hosted matrix with inspected
  manifests, visual evidence where supported, and private closure evidence.

## Exit Gates

CR-0264 may close only after the upstream zero-gap scan, exact-SHA reviews,
remote/hosted validation, evidence inspection, and publication gate pass.
