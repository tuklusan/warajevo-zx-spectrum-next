# CR-0178: Serialize Networking Mode in Native State

Status: CLOSED

## Objective

Bind the architecture's single `NONE`/`INTERFACE1`/`EAR_MIC` networking mode to
the WZSN-native canonical state format. Reject invalid enum values during
serialization and deserialization, while leaving mode transitions and device
behavior to their ordered Phase-10 work.

## Functional Inventory

- Define one machine-owned networking-mode enum with exactly three values.
- Initialize new machines to `NONE`.
- Expose validated set/get accessors without implementing later device behavior.
- Include the mode in canonical serialization and hashing.
- Validate the mode before publishing a restored machine state.
- Reject values outside the enum and preserve atomic failure of deserialization.
- Preserve canonical headers, banned-word checks, private artefact rules, and
  the local no-build/no-test rule.

## Upstream Discovery

The preserved upstream source has no WZSN-native state format or networking-mode
enum. Upstream networking behavior is documented separately and is not imported
as an implementation shortcut for this task.

## Upstream and Existing-Gate Comparison

Architecture Section 24 requires one mutually exclusive mode and Section 25
requires canonical state to retain deterministic machine state. Existing native
state serialization currently omits networking mode; this CR adds only the
missing state field and validation. Interface-1 devices, Microdrive, ZX Net,
Ear+Mic routing, and cold reconfiguration remain later ordered work.

## Disposition

- `IMPLEMENT_NOW`: enum, initialization, accessors, native-state field, and validation.
- `PRESERVE`: existing state ordering, explicit little-endian encoding, and atomic restore behavior.
- `DEFER`: networking devices, transitions, and Architecture-3 behavior.

## Zero-Gap Exit Scan

Re-scan the architecture's networking and native-state requirements, the
serializer/deserializer, canonical hash path, and related tests. Confirm that
the mode is represented exactly once, invalid values are rejected, and no
later networking implementation is silently introduced.

## Verification Plan

- Static repository gates and diff checks locally only.
- Exact-SHA CODE and DOCUMENTATION reviews.
- Remote smoke on approved machines.
- Hosted matrix validation across all configured lanes and publication-gate.
