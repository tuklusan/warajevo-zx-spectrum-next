# CR-0231 Exclusive Writable-Media Ownership

Status: CLOSED

## Functional Inventory

- Resolve a writable media identity using host identity rather than only the
  user-supplied path where the platform permits.
- Allow only one WZSN process to hold a writable claim for an image at a time.
- Reject a second writable mount deterministically without mutating media.
- Permit an explicit read-only fallback only when the caller selects it.
- Release the claim on normal unmount and process termination.
- Keep ownership state outside the deterministic core and independent of
  emulated timing or serialized Spectrum state.
- Cover MDR first while leaving the boundary extensible to other writable
  media formats.

## Upstream Discovery

The upstream Interface 1/Microdrive implementation uses a shared host media
file and does not provide a portable process-lock abstraction. Its observable
media behavior therefore remains the authority for image contents and flush
ordering, while the modern architecture adds host safety around that shared
file. The complete scoped architecture requirements in sections 24.3 and
28.7, plus companion-spec sections 6 and 8, require exclusive writable claims,
controlled rejection or deliberate read-only fallback, and no core exposure of
host handles or paths.

## Disposition

- Host-side media ownership abstraction: `IMPLEMENT_NOW`.
- MDR integration at the application-controlled flush/mount boundary:
  `IMPLEMENT_NOW`.
- Additional writable formats and distributed-lock coordination: defer until
  their media adapters are introduced.

## Zero-Gap Exit Scan

Before closure, re-read the complete scoped architecture and upstream media
paths and verify platform identity resolution, second-writer rejection,
explicit read-only fallback, release behavior, failure atomicity, and core
isolation are all represented by implementation and evidence.
