# CR-0044 Migration Preflight

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- IM0 obtains its first opcode from interrupt acknowledge, not an M1 memory fetch.
- The injected opcode may be any supported primary or prefixed instruction.
- Immediate/displacement bytes following the injected opcode are read from the
  interrupted PC through normal bus phases.
- R, IFF, HALT-release PC, stack, MEMPTR and exact cycle offsets must match the
  selected injected instruction path.
- Unsupported injected opcodes must leave deterministic, diagnosable state and
  must not be silently substituted with a memory opcode.
- Tests must cover non-RST primary, CB, ED, DD/FD and RST forms.

## Upstream Discovery

Authority: Architecture section 11 and CR-0041 reconciliation. Reference
examined: `upstream/main:src/spectrum-kernel/Z80.ASM`; TABLE1 dispatch,
PREFIXCB/PREFIXDD/PREFIXED/PREFIXFD, PREFDDCB, RF/RC timing macros, IFF state,
and HALT were scanned with their neighboring control paths. The upstream
design uses dispatch tables rather than a RST-only IM0 substitution.

## Disposition

| Functional aspect | Disposition | Evidence |
| --- | --- | --- |
| Bus-supplied first opcode | IMPLEMENT_NOW | Architecture interrupt acknowledge and upstream dispatch |
| Primary and prefix dispatch | IMPLEMENT_NOW | TABLE1 and PREFIX handlers |
| Immediate/displacement bus reads | IMPLEMENT_NOW | Existing CPU bus decomposition |
| Unimplemented opcode behavior | IMPLEMENT_NOW | Existing result/error contract |
| Device interrupt scheduling | DEFERRED_WITH_CR | Device/scheduler CRs own interrupt edges |

## Zero-Gap Exit Scan

The second scan covered all prefix handoff paths and the HALT/IFF/refresh
neighbors. No additional CPU-side IM0 behavior remains undispositioned; future
device interrupt generation is explicitly outside this entry-path CR.
