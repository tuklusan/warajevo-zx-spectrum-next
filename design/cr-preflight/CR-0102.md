# CR-0102 Preflight: Deterministic FLASH Phase

Status: CLOSED

## Objective

Implement FLASH phase from emulated frame/time state so attribute inversion is
deterministic and never depends on host wall-clock time.

## Functional Inventory

- Define the emulated frame-period cadence for FLASH phase.
- Return stable phase at frame boundaries and across repeated frames.
- Keep phase independent of host clocks, presentation callbacks, and speed
  settings.
- Apply FLASH inversion only for attributes with bit 7 set; preserve ordinary
  attributes unchanged.
- Keep phase, BRIGHT, and INK/PAPER selection integrated with the decoder.
- Cover reset, frame wrap, phase transition, and long-run arithmetic.

## Upstream Completeness Gate

Architecture sections 17.1, 17.3, 18, 36, and 51 require FLASH to be behavior
of emulated time rather than an extra color or host animation. Rescan preserved
display timing and FLASH paths, frame geometry, attribute semantics, and host
boundaries. Every scoped rule must be implemented, tested, or assigned to a
named later task.

## Upstream Discovery

The preserved reference supplies legacy attribute FLASH behavior. The current
core already has canonical master ticks and pure attribute decoding; the
missing slice is a machine-time phase query and controlled INK/PAPER swap.

## Disposition

Add a pure phase query and FLASH-aware pixel decoder driven by canonical master
ticks. Keep host presentation and wall-clock time outside the core.

## Zero-Gap Exit Scan

Before closure, rescan FLASH bit handling, phase cadence, frame boundaries,
reset, BRIGHT interaction, host independence, invalid inputs, and later-task
assignments. Confirm no scoped FLASH rule remains implicit.
