## Change Request
CR-0313: Replace tape print-to-screen with manager presentation and export report

Status: APPROVED_FOR_IMPLEMENTATION
Priority: low

## Functional Inventory
- Treat the Tape Manager block/details presentation as the replacement for
  legacy Print-to-Screen; do not create a second screen-print pathway.
- Provide the retained optional `Export Tape Report...` operation as a
  portable, deterministic text report over the manager view and block rows.
- Include source identity, format, loading mode, transport state, position,
  selection, and every visible block's stable metadata.
- Use caller-owned bounded output and report buffer exhaustion without partial
  success; exporting is observational and must not mutate media or machine state.
- Preserve the legacy Print-to-Printer disposition as dropped and keep report
  generation toolkit-neutral for later GUI/file-dialog integration.

## Upstream Discovery
UI sections 12.4, 12.5, 20.1, 45, 47, and 48 define the report replacement,
failure, state-preservation, and acceptance boundaries. Developer task 308 is
the derived backlog item. The existing Tape Manager view and block row APIs
from CR-0310/0311 are the single presentation source; no second legacy print
model is permitted.

## Disposition
`IMPLEMENT_NOW`: add a bounded text report serializer over the existing
manager view and block presentation rows. File selection and atomic file
replacement remain deferred to the shared host output workflow.

## Zero-Gap Exit Scan
Confirm legacy Print-to-Screen is represented by manager data, report output
contains all required manager state and block metadata, ordinary and malformed
inputs fail deterministically, small buffers return `WZ_RESULT_BUFFER_TOO_SMALL`,
and report generation has no machine/media mutation or GUI dependency.
