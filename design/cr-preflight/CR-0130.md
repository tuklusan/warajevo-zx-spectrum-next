# CR-0130 Preflight: Deterministic Input Timestamps

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Assign input event timestamps at the deterministic boundary so input ordering
is reproducible and host wall-clock behavior cannot enter the emulated core.

## Functional Inventory

- Define the timestamp unit and its relationship to the core master clock.
- Assign timestamps monotonically at event acceptance.
- Preserve ordering for equal-clock events with an explicit stable sequence rule.
- Clamp stale requested ticks to the last assigned tick; accept the maximum
  representable tick, and reject assignment when the sequence counter is
  exhausted rather than wrapping.
- Keep host wall-clock values and UI event types outside the core.
- Preserve source ownership semantics established by CR-0128.
- Provide tests for ordering, equal timestamps, release, and boundary values.

## Upstream Completeness Gate

Inspect preserved upstream event timing, keyboard polling cadence, scheduler
clock units, and any input queue behavior. Compare every timing and ordering
assumption with the architecture and current input boundary; record all gaps,
including behavior not implemented by upstream, before implementation.

## Upstream Discovery

The current core is master-clock driven and the existing keyboard state is read
at ULA port scans. This CR must establish the event-to-core timestamp contract
without importing a host clock; later focus-loss and pacing work remains out of
scope.

The normalized event contract is deliberately scalar-only: source identity,
normalized key identity, and pressed state. It contains no host timestamp, wall
clock value, UI event object, pointer, thread identifier, or platform handle;
the assigned master tick and sequence are the only timing metadata.

An input release is represented by the normalized event with `pressed` false.
The assigner does not alter that payload; it timestamps releases identically to
presses. A stale requested tick is deterministically clamped, and sequence
exhaustion is a hard failure before any output event is written.

## Disposition

Add the smallest deterministic timestamp contract needed by the input boundary.
Do not implement focus-loss policy, keyboard ghosting, Kempston decoding, or
host-specific clock acquisition here.

## Zero-Gap Exit Scan

Close only when timestamp units, monotonic ordering, equal-time ordering,
overflow behavior, and source interaction are evidenced by tests and the final
upstream comparison finds no unresolved gap. Boundary tests and the dependency
gate must also evidence that no host clock or UI type crosses the core boundary.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
