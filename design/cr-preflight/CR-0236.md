# CR-0236 Dirty Microdrive Guard During Networking-Mode Changes

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Detect dirty writable Microdrive state before leaving Interface 1.
- Permit an explicit successful flush or explicit discard/cancellation path.
- Reject or defer a mode change when dirty media cannot be safely resolved.
- Preserve the original machine context, dirty state, and mounted image after
  flush failure or rejected mode change.
- Keep idempotent selection of the active mode unchanged.
- Keep EAR_MIC unavailable before Architecture 3 and prevent silent device loss.
- Add regression coverage for clean, dirty-success, dirty-failure,
  explicit-discard, repeated-request, and allocation-failure paths.

## Dispositions

| Behavior | Disposition | Reason |
|---|---|---|
| Clean mode change | PRESERVE | Existing cold reconfiguration contract |
| Dirty writable media with successful flush | IMPLEMENT_NOW | Companion specification §8 |
| Dirty writable media with failed flush | IMPLEMENT_NOW | Must retain original and dirty state |
| Explicit discard/cancellation | IMPLEMENT_NOW | Required operator-controlled resolution |
| Host wall-time or hidden writes | NOT_APPLICABLE | Canonical device boundary |
| Cross-process ownership policy | PRESERVE | CR-0231 authority |
| EAR_MIC mode activation | DEFERRED_WITH_CR | Architecture 3 boundary |

## Zero-Gap Exit Scan

Re-read every mode-change caller, Microdrive dirty/flush/discard helper,
upstream transition routine, and companion-spec acceptance bullet. Confirm each
dirty-media outcome has exactly one disposition, no failure mutates the old
context, explicit discard is distinguishable from successful flush, and all
callers handle the guarded result.
