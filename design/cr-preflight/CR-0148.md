# CR-0148 Preflight: Host Push-Audio Boundary

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Provide a bounded host push-audio queue so canonical PCM is produced by the
emulation/orchestrator and host device callbacks only consume existing samples.

## Functional Inventory

- Push canonical PCM blocks from the producer side without invoking host audio APIs.
- Let a consumer pop already-produced samples without access to machine state.
- Bound queue storage and report dropped samples deterministically on overflow.
- Return underflow as fewer available samples without synthesizing machine progress.
- Preserve sample ordering and exact signed fixed-point values.
- Keep queue fill/drop counters host-only and outside canonical state.
- Leave WASAPI, ALSA, CoreAudio, and Sokol device plumbing at the host boundary.

## Upstream Completeness Gate

Inspect preserved upstream sound callback and speaker delivery paths. Compare
whether device demand can drive emulation, and retain only output behavior while
enforcing the architecture's producer-driven deterministic timeline.

## Upstream Discovery

The preserved upstream sound path is host-device driven and tied to legacy
speaker delivery. WZSN instead requires canonical audio to continue headlessly;
the host callback may consume queued samples but must never advance machine time.

## Disposition

Add a fixed-capacity host-only FIFO with explicit push/pop, underflow, and
overflow/drop accounting. Device-specific callback adapters remain subsequent
platform work.

## Zero-Gap Exit Scan

Close only when producer/consumer ownership, order, capacity, underflow,
overflow, host-only counters, callback isolation, and upstream comparison have
no undispositioned gap.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
