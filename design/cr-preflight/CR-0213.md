# CR-0213 Differential-Test Representative 128K State Behavior

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Define representative deterministic 128K machine-state scenarios covering
  paging, screen/ROM selection, interrupt timing, raster position, AY state,
  snapshot state, and reset-adjacent behavior.
- Compare normalized observable results against preserved Warajevo behavior
  wherever the historical implementation is authoritative and comparable.
- Use hardware/reference evidence as the winning authority where the legacy
  implementation contains an emulator shortcut or differs from documented
  hardware behavior.
- Record exact input state, output state, timing trace, and disposition for each
  disagreement; unexplained differences are failures.
- Keep differential execution outside the deterministic core and make the
  comparison reproducible without host wall-clock or GUI dependencies.

## Source Authority

- `design/warajevo-zx-spectrum-next-architecture.md` sections 36, 38, 39, 40,
  and 49.1.
- `design/wzsn-architectures-1-2-developer-tasks.md` task 198.
- Current 128K machine, bus, raster, AY, and snapshot tests.
- `reference/original-warajevo/source/src/environment/SNAPSHOT.PAS` and
  `reference/original-warajevo/source/src/spectrum-kernel/SPECSIM.ASM`.
- Frozen hardware/reference evidence recorded by the project.

## Upstream Discovery

- Inventory comparable upstream inputs and observables at function/state level.
- Identify historical shortcuts and explicitly mark where hardware evidence
  supersedes them.
- Confirm no differential test imports host timing or treats presentation output
  as deterministic machine state.

## Disposition

- Representative 128K differential fixtures and discrepancy records:
  `IMPLEMENT_NOW`.
- Unavailable or non-comparable upstream behavior: `DEFERRED_WITH_CR` with an
  explicit reason and evidence requirement.

## Pre-Implementation Gates

- Enumerate scenarios, normalization rules, expected observables, and authority
  for every comparison before editing.
- Perform a second upstream zero-gap scan after implementation covering all
  selected scenarios, disagreement handling, and evidence provenance.
- Require exact-SHA CODE, DOCUMENTATION, and independent bootstrap reviews with
  zero findings before remote execution.
- Use local static gates only; all builds and tests run remotely or hosted.

## Evidence and Exit Gates

- Remote Linux sanitizer, Intel Mac, Windows 10, and Windows 11 validation pass.
- Hosted `platform-smoke` housekeeping, full matrix, and publication pass.
- Closure records scenario manifests, discrepancy dispositions, commit range,
  review results, remote run IDs, hosted run ID, and the second upstream scan.

## Zero-Gap Exit Scan

- Confirm every selected comparable 128K behavior has a deterministic fixture,
  authority assignment, and recorded result.
- Confirm every non-comparable or deferred behavior is explicit and not silently
  ignored.
