# CR-0177: Make Remote-Harness Compatibility Fixtures Queue-Independent

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Keep remote-harness compatibility tests deterministic after the real CR queue
advances or becomes fully closed. The test fixture must model its own active
reviewed CR instead of depending on the production tracker having an item in
progress.

## Functional Inventory

- Preserve the production remote gate requirement for a uniquely active CR.
- Make the extended-precision receipt compatibility test create a synthetic
  active tracker record in isolated fixture data.
- Preserve tracker, authority, scope, receipt, snapshot, and diff identity
  checks in that test.
- Keep the test valid when every real project CR is closed.
- Do not weaken rejection tests or remote execution authorization.
- Preserve canonical headers, banned-word checks, and private artefact rules.

## Upstream Discovery

The preserved upstream source has no project remote-harness authorization
tests or tracker semantics. This is a project-infrastructure test-fixture
correction and does not change migrated emulator behavior.

## Upstream and Existing-Gate Comparison

The existing production gate intentionally requires an active CR for remote
execution. The failing test incorrectly borrowed that live queue state for a
compatibility fixture. The correction isolates only the test data and leaves
the production authorization rule unchanged.

## Disposition

- `IMPLEMENT_NOW`: make the compatibility fixture self-contained.
- `PRESERVE`: production active-CR authorization and all rejection behavior.
- `NOT_APPLICABLE`: emulator behavior and upstream runtime compatibility.
- `NOT_APPLICABLE`: local builds or tests; validation remains remote or hosted.

## Zero-Gap Exit Scan

Confirm the test no longer reads live queue status to establish its fixture,
while production authorization still rejects closed or ambiguous CR records.
Run the hosted matrix after the correction and retain the failed run as
non-green diagnostic evidence.

## Verification Plan

- Static repository gates and diff checks locally only.
- Exact-SHA CODE and DOCUMENTATION reviews.
- Remote smoke validation on approved machines.
- Hosted matrix validation across all configured lanes and publication-gate.
