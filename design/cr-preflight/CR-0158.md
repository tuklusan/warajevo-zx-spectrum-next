# CR-0158 Preflight: In-Memory Tape Object and State

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Implement the core tape object and playback state independently of host file
handles so synthetic tapes can be mounted, advanced, queried, and rejected
without partially mutating the machine.

## Functional Inventory

- Represent immutable tape media and mutable playback position separately.
- Represent EAR level, pulse/edge position, pause, and end-of-tape state.
- Mount validated in-memory tape data without host path or file-handle state.
- Reset, stop, rewind, and query operations with defined boundary behavior.
- Keep tape state serializable and excluded from host I/O implementation details.
- Make malformed or oversized input fail before publication.

## Upstream Completeness Gate

Compare preserved upstream tape position, motor, EAR, pause, rewind, and
end-of-media behavior. Record every applicable observable rule before adding
portable core ownership, while excluding DOS/file-handle mechanics.

## Upstream Discovery

The preserved upstream implementation couples media access to host file
operations. The migration retains its observable tape transport behavior but
introduces an explicit validated in-memory boundary for deterministic core use.

## Disposition

Add a small core media/state API and synthetic fixtures only. Do not parse a
host file, open a dialog, or introduce normal-mode timing execution in this CR.

## Zero-Gap Exit Scan

Close only when synthetic mount, playback-state transitions, rewind/end
boundaries, invalid-input rejection, and host-state isolation are covered.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
