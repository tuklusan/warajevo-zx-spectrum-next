# CR-0230 Atomic MDR Save and Flush

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Provide an explicit application-controlled flush for dirty MDR data.
- Preserve the original image if preparation, writing, replacement, or commit
  fails.
- Clear dirty state only after successful atomic replacement.
- Keep the pending in-memory buffer recoverable after any failed flush.
- Reject flushes for invalid, unmounted, protected, or non-dirty media with
  controlled results and no partial mutation.
- Keep cross-process writer ownership in the later ownership CR.

## Upstream Discovery

The complete upstream `FLUSH`, `MDV_CACHE`, `MOTOR`, and shutdown paths were
read and cross-checked against companion-spec section 8. The reference flushes
dirty buffered data before cartridge/window changes, preserves the original on
failure, truncates the final cache window to validated length, and clears dirty
state only after successful media commit.

## Disposition

- Explicit flush result contract and failure atomicity: `IMPLEMENT_NOW`.
- Portable host-file replacement boundary: `IMPLEMENT_NOW`.
- Cross-process ownership and lock policy: defer to task 213.

write ordering, original-image recovery, final-window bounds, explicit flush
invocation, and controlled failure behavior are all represented.
