# CR-0201 Hosted Artifact Upload Retry

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Preserve the existing hosted matrix, housekeeping, build, test, and artifact
  path contracts.
- Retry a transient hosted artifact upload failure up to two additional times.
- Keep the first successful upload sufficient and avoid duplicate uploads when
  no failure occurs.
- Fail the lane if all upload attempts fail or if the artifact path is absent.
- Preserve exact matrix lane names used by the publication gate.

## Upstream Completeness

Not applicable: this is hosted-runner workflow resilience and has no upstream
emulator behavior. The existing GitHub Actions upload contract is the complete
authority for this project-local gate.

## Upstream Discovery

The upstream reference repository was not searched because artifact upload
retry behavior is specific to this project workflow and has no legacy emulator
equivalent. The hosted workflow, GitHub artifact action contract, and local
housekeeping helper were inspected instead.

## Disposition

- Hosted upload failure retry: `IMPLEMENT_NOW` in the workflow.
- Missing artifact path: `IMPLEMENT_NOW` remains fatal through
  `if-no-files-found: error`.
- Persistent upload failure: `IMPLEMENT_NOW` remains fatal on the final
  attempt.
- Matrix identity and publication semantics: `NOT_APPLICABLE` to change;
  preserve the existing job names and count.

## Zero-Gap Exit Scan

The workflow was scanned for the matrix lane identifiers, publication-gate
job-count logic, artifact path, `if: always()` behavior, and failure handling.
The retry names are unique and do not alter the matrix job names consumed by
publication validation.

## Evidence

Static repository gates and `git diff --check` are required locally. No local
build, test, or soak is permitted. Hosted validation must await all lanes and
must include at least one retry-path execution or a documented reason why the
normal successful upload path was sufficient.
