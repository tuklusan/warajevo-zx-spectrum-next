# CR-0269 Forward Secured Lab and Hosted Harness Diagnostics

Status: APPROVED_FOR_IMPLEMENTATION
Priority: MEDIUM
Execution order: AFTER_WORKFLOW_CRS
Blocking: NO

## Functional Inventory

- Forward complete runner-matrix and local-lab harness diagnostics over UDP
  only to `sanyalnet-oracle-vps2.duckdns.org:65514`.
- Encode records in the project-approved Unix syslog format.
- Include enough run, lane, machine, phase, and failure classification data to
  diagnose queue, SSH, build, test, transport, and publication problems.
- Preserve non-blocking, best-effort behavior and never change product or test
  execution because the endpoint is unavailable.
- Forward secrets, private binaries, screenshots, and raw test artifacts when
  the operator has explicitly authorized the secured lab endpoint. Preserve
  only the transport credential itself as a local secret; it must not be
  embedded in source or packet payloads.
- Do not forward unrelated personal data or unreviewed machine data.
- Keep local evidence retention and the secured network forwarding path
  separate and auditable.
- Attach the syslog callback to the bounded circular trace-file append path so
  each successfully committed trace event is forwarded immediately, without
  waiting for file freeze or run completion.

## Upstream Discovery

- Reconcile the existing product diagnostic adapter and routing boundary with
  the runner and local-box harness record schemas.
- Scan all current hosted workflow and remote harness log producers so no
  approved diagnostic path is missed.
- Confirm the secured endpoint is fixed, UDP-only, and does not provide a
  delivery acknowledgement.

## Disposition

| Surface | Disposition | Reason |
|---|---|---|
| Product diagnostics | EXTEND_APPEND_BINDING | Forward at circular-file commit |
| Harness diagnostics | IMPLEMENT_NOW | Current gap identified |
| Sensitive evidence | FORWARD_WHEN_AUTHORIZED | Secured lab endpoint authorization |
| Endpoint and transport | PRESERVE_FIXED_UDP | Existing project requirement |

## Zero-Gap Exit Scan

The hosted lane result tree and every local remote-harness session directory
are the approved harness producer scope. Their records, logs, traces,
screenshots, and raw test artifacts are forwarded as bounded base64 syslog
chunks after explicit operator authorization. Credentials used to establish
transport are never included in payloads. The existing product adapter remains
the separate product-diagnostics boundary.

## Required Evidence

- Exact-SHA CODE, TEST_ARTIFACT, and DOCUMENTATION reviews.
- Hosted matrix and available remote-lab validation.
- Inspected sanitized packet-format and routing evidence retained privately.
- No local build or test activity.

## Exit Gates

Close only after the complete producer inventory, implementation, privacy and
UDP-only routing tests, remote/hosted validation, evidence inspection, and
publication gates pass.
