## Change Request
CR-0302: Add cancellation and failure state-preservation regressions

Status: CLOSED
Priority: high

## Functional Inventory
- Assert GUI screenshot file-dialog cancellation leaves destination and raster unchanged.
- Assert invalid screenshot destination leaves destination and raster unchanged.
- Assert screenshot output-capacity failure leaves destination and raster unchanged.
- Assert invalid snapshot load leaves committed snapshot and machine state unchanged.
- Assert snapshot destination cancellation/error paths leave host workflow state unchanged.
- Keep all checks deterministic and independent of GUI toolkit or host chrome.
- Do not add runtime behavior or modify frozen harnesses.

## Upstream Discovery
UI Section 45 requires cancellation and non-destructive error paths to leave
machine/media state unchanged; Section 47 requires regression coverage, and
task 297 derives the screenshot/snapshot subset. Existing workflow code already
uses transactional destination and pending-state boundaries. The preserved
upstream source was searched for equivalent cancellation and failure tests; no
portable test exists there. No upstream behavior remains undispositioned.

## Disposition
`IMPLEMENT_NOW`: strengthen the existing screenshot and snapshot workflow
tests with immediate state snapshots around every cancellation and error path.
No product behavior, host integration, or harness changes are required.

## Zero-Gap Exit Scan
Confirm each screenshot cancellation/error and invalid snapshot path is tested
against unchanged workflow state plus unchanged raster or machine state, and
confirm the successful paths remain covered.
