# CR-0149 Preflight: Host Audio Enable Policy

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Make host audio delivery audible only from 0.5x through 2.0x inclusive while
leaving deterministic emulated audio progression independent of host muting.

## Functional Inventory

- Enable host output at 0.5x, 1.0x, and 2.0x.
- Mute host output below 0.5x, above 2.0x, and in Unlimited mode.
- Keep the decision in the host layer and independent of canonical audio state.
- Treat invalid speed values as muted.
- Ensure changing the policy cannot reset, discard, or rewrite emulated audio state.

## Upstream Completeness Gate

Compare the preserved runtime speed and sound-delivery paths for every speed
mode, including their treatment of sound suppression and machine progression.
Retain output behavior while applying the architecture's explicit inclusive
range and host-only boundary.

## Upstream Discovery

The preserved speed path does not provide this WZSN host policy as a standalone
contract. The architecture explicitly defines the inclusive audible range and
requires mute outside it without stopping beeper or AY progression.

## Disposition

Add a pure host policy predicate backed by the existing canonical speed enum.
Device adapters will consult this predicate when the host delivery path is
connected; no machine or canonical audio API is changed by this request.

## Zero-Gap Exit Scan

Close only when all seven speed modes, invalid input, inclusive boundaries,
Unlimited behavior, host-only ownership, and preservation of emulated audio
progression have no undispositioned gap.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
