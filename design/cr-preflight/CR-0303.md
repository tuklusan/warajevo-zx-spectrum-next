## Change Request
CR-0303: Harden hosted publication-lane verification

Status: APPROVED_FOR_IMPLEMENTATION
Priority: high

## Functional Inventory
- Validate exactly the 20 expected product lane jobs and no housekeeping/publication job.
- Validate every lane head SHA equals the matrix commit.
- Validate every lane has a terminal successful conclusion.
- Require at least one successful Intel macOS lane and one successful ARM macOS lane.
- Make validation independent of API job ordering and shell tab/newline parsing quirks.
- Emit actionable diagnostics when the publication check fails.
- Reuse the completed all-green product matrix when only the publication instrumentation changes.
- Do not alter product build/test execution or frozen local/remote harnesses.

## Upstream Discovery
The hosted publication gate is project-owned workflow infrastructure. The
current run `34160498964` produced 20 successful product lanes but the
line-oriented publication check failed, so its result is a false negative.
The required matrix lanes and macOS acceptance rule are defined in
`.github/workflows/platform-smoke.yml` and `WORKFLOW.md`. No upstream legacy
behavior applies; the gate itself is the authority for this workflow invariant.

## Disposition
`IMPLEMENT_NOW`: replace brittle shell membership/row parsing with explicit
normalized lane-name, SHA, and conclusion sets and diagnostic output. This is
post-matrix instrumentation only; the completed run `34160498964` remains the
product evidence and must not be rerun solely for this correction.

## Zero-Gap Exit Scan

successful terminal conclusions, Intel/ARM macOS coverage, and diagnostics for
each rejection path.
