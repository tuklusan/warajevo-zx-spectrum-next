# CR-0138 Preflight: Runtime Speed Changes

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Make runtime speed changes take effect without discontinuity in canonical
emulated master time or an artificial host catch-up delay.

## Functional Inventory

- Preserve the current machine tick and all core timing state across a speed change.
- Apply a changed policy at a well-defined pacing observation boundary.
- Re-anchor host and machine observations together so the new policy governs future progress only.
- Cover changes among finite policies, transitions to and from Unlimited, repeated changes, and a change before the next wait.
- Keep host pacing state outside canonical machine serialization, hashing, and event ordering.
- Handle a clock or machine-tick regression at the boundary without inventing a delay.

## Upstream Completeness Gate

Inspect the preserved upstream run loop, delay, fast-forward, and cassette
timing paths. Compare whether any upstream speed control changes emulated
timers, CPU phase, tape position, audio, raster, or input scheduling. Retain
only host wall-clock pacing behavior; canonical progress remains unchanged.

## Upstream Discovery

The preserved upstream implementation exposes speed as a host execution
concern rather than a machine-state mutation. No upstream behavior authorizes
resetting the machine tick, CPU phase, scheduler ordering, media position, or
audio/raster timelines when the host rate changes.

## Disposition

Add a pending policy boundary to the host pacing seam. `set_speed` records the
requested policy; the next `wait` atomically adopts it and re-anchors the two
observations. No core API or canonical state is modified.

## Zero-Gap Exit Scan

Close only after finite-policy changes, Unlimited transitions, repeated changes,
boundary regression, canonical-state isolation, and deterministic future timing
are tested with no unresolved upstream gap.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
