## Change Request
CR-0297: Shared screenshot capture service

Status: APPROVED_FOR_IMPLEMENTATION
Priority: high

## Functional Inventory
- Accept the completed host-visible Spectrum raster as the only image source.
- Encode deterministic PNG output without reading a platform framebuffer.
- Preserve raster samples and machine state by using a read-only input boundary.
- Exclude menus, toolbars, status overlays, debugger windows, cursors, and desktop chrome.
- Reject invalid raster samples and report required output capacity safely.
- Make the encoder reusable by GUI, remote control, and application tests.

## Upstream And Architecture Discovery
Core architecture Section 19.6 and UI Section 8.4 require one shared capture/PNG
path for GUI and remote-control front ends. The source is the completed logical or
selected presentation raster, before host chrome. The service must not advance time or
mutate emulated state.

## Upstream Discovery
The preserved legacy source provides display behavior but no portable modern PNG
boundary. The migration preserves the display-only result through the canonical raster
and does not reproduce host-window capture behavior. No additional upstream behavior
remains undispositioned for this service boundary.

## Disposition
Implement a host-independent indexed PNG encoder over `wz_raster_buffer_t`. The API is
read-only, caller-buffered, deterministic, and contains no window, toolkit, or desktop
capture dependency.

## Zero-Gap Exit Scan
The implementation must cover dimensions, all valid sample classes, palette output,
large output block handling, insufficient capacity, invalid samples, and no-input
mutation. A final scan must confirm the service is the sole encoder boundary and that
no GUI or remote front end duplicates it.
