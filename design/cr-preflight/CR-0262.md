# CR-0262 Add Explicit Application Quit and Lifecycle Boundary

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Provide one application-level quit/lifecycle command boundary for the
  monitor workflow without placing host teardown in deterministic core code.
- Make repeated quit requests idempotent and make lifecycle state observable
  without depending on a GUI, socket, wall clock, or host thread identifier.
- Preserve the one-live-machine ownership rule and reject invalid lifecycle
  transitions without partial state changes.
- Keep platform window/event translation outside the application command
  boundary, with a narrow host callback for final teardown notification.

## Upstream Discovery

- Re-read the complete `QUIT`, warm-reset, and monitor command-dispatch paths
  in `reference/original-warajevo/source/src/spectrum-kernel/SPECMON.ASM`.
- Compare normal quit, repeated quit, abort, and restart behavior with the
  current runner, reset, debugger access, and host lifecycle boundaries.
- Re-read Architecture 1 sections 31, 41, 45, and 49.2 and UI Architecture 2
  sections 21, 27, and 45.
- Inventory current application lifecycle entry points and classify each as
  deterministic-core, application-boundary, or host/UI-only.

## Disposition

| Surface | Disposition | Reason |
|---|---|---|
| Quit request and lifecycle state | IMPLEMENT_NOW | Required monitor workflow |
| Repeated quit request | IDEMPOTENT | Safe command semantics |
| Machine reset/restart | PRESERVE_EXISTING_BOUNDARY | Already implemented by CR-0259 |
| Window/event translation | HOST_UI_BOUNDARY | Platform-specific input |
| Process/thread/socket teardown | HOST_ONLY | Excluded from canonical state |

## Zero-Gap Exit Scan

Before closure, compare every accepted and rejected upstream lifecycle branch
with regression cases for initial, running, paused, and already-terminating
states. Confirm no host resource or process termination is performed by the
deterministic core and no second machine owner is introduced.
