# CR-0164 Preflight: Warajevo-Native TAP Parsing

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Implement signature-detected parsing of the preserved Warajevo-native TAP
container without conflating it with standard TAP. Validate its linked block
records and expose the supported logical payloads through a controlled,
caller-owned compatibility boundary before any tape state is published.

## Functional Inventory

- Detect the native format only from its documented three-word
  little-endian `0xFFFFFFFF` header chain.
- Parse linked previous/next block offsets, record length, flag, and record
  type with strict bounds, alignment, cycle, and termination checks.
- Distinguish ordinary records, compressed records, sample records, and the
  terminal link according to the preserved reference behavior.
- Preserve native record metadata and payload boundaries for later maintenance
  operations without treating the format as standard TAP.
- Reject malformed links, truncated records, impossible lengths, unknown
  required record forms, and non-terminating chains without partial output.
- Keep compatibility parsing independent of host paths, file handles, GUI,
  wall clock, and machine state.
- Add deterministic fixtures for valid chains, empty/native headers, bad links,
  cycles, truncation, oversized records, and standard/native identification.

## Upstream Completeness Gate

Read the preserved native format paths line-by-line in `TAPES.PAS`,
`TAPE.ASM`, `TAPE2TAP.ASM`, `KONVTAP.PAS`, and related `READTAPE` code.
Record exact header, link, record-type, compressed/sample, error, and
termination behavior. Reconcile every applicable rule with
`design/media-format-support.md`, while preserving standard TAP parsing and
writing as separate paths.

## Upstream Discovery

The preserved implementation identifies native media with three consecutive
32-bit all-ones words, then follows linked records containing previous/next
offsets, a length, and a flag/type byte. Native records include ordinary,
compressed, and sampled forms with distinct metadata. CR-0162 and CR-0163
cover standard TAP only; this CR addresses native identification and strict
record traversal, while decompression and advanced maintenance behavior remain
separate ordered work where required.

## Disposition

Implement only native signature detection, strict linked-record parsing,
metadata/payload views, and deterministic rejection tests. Do not implement
standard TAP routing changes, native writing, compression/decompression,
TZX/WAV support, host file I/O, instant loading, trap detection, or networking.

## Zero-Gap Exit Scan

Before closure, repeat the upstream comparison against native TAP detection,
linked records, record types, bounds, and termination paths. Close only when
every applicable behavior in this scope is implemented or assigned to a later
ordered task, with serialized CODE and DOCUMENTATION reviews, remote
validation, the full hosted matrix, clean repository gates, and published
evidence.

## Verification Plan

- Static repository gates and source inspection on the development machine only.
- Serialized pre-development and final CODE/DOCUMENTATION reviews.
- Remote Linux and Windows smoke tests, including sanitizers where useful.
- Full hosted platform matrix.
- Headless native/standard identification and malformed-chain fixtures.
