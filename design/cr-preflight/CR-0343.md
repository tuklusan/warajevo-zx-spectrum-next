# CR-0343 Phase 12F Input Settings Reconciliation

Status: CLOSED
Priority: medium
Execution order: ARCHITECTURE_2_PHASE_12F
Blocking: NO

## Functional Inventory

- Own host-to-normalized input mapping in the application layer.
- Support host Kempston bindings without placing host key identities in core
  state.
- Preserve independent local, Telnet, script, and reserved input ownership.
- Release local keys on focus loss without releasing independently owned keys.
- Reject invalid bindings and preserve deterministic joystick semantics.

## Upstream And Architecture Discovery

- UI Architecture Section 23.3 requires host-owned normalized input and
  explicitly excludes host identities from the Spectrum core.
- The preserved upstream input path was inspected for keyboard and joystick
  behavior; its historical host key handling is not a portable settings API.
- Existing `wz_input_arbiter`, `wz_input_focus`, and `wz_kempston_mapping` paths
  implement the required ownership and mapping boundaries. Existing regression
  coverage exercises focus release, source isolation, binding, unbinding, and
  Kempston application.
- No additional host identity or core input state is warranted for task 333.

## Zero-Gap Exit Scan

- Requirement-to-implementation and requirement-to-test scans are complete in
  the cited application input modules and regression suite.
- Existing remote/hosted validation evidence covers the unchanged input paths.
- Remaining Phase 12F work begins with task 334 ROM/Firmware settings.

## Exit Gates And Closure Evidence

This reconciliation closes by reuse of prior exact-head implementation and
validation evidence. No new code, harness, wrapper, build, or test was needed;
no local build or test was performed.
