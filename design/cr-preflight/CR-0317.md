## Change Request
CR-0317: Complete Tape UI acceptance subset

Status: APPROVED_FOR_IMPLEMENTATION
Priority: medium

## Functional Inventory
- Prove the complete five-action Tape surface is stable: Insert, Eject,
  Normal, Instant / Trap, and Open Tape Manager.
- Prove each Tape action dispatches through its registered semantic command ID,
  with no private UI handler path.
- Preserve the existing toolbar Tape control, mounted/unmounted presentation,
  normal-loading default, and disabled-state reason behavior.
- Keep the acceptance evidence headless, deterministic, and independent of the
  frozen remote and hosted harnesses.

## Upstream Discovery
UI acceptance contract §48 requires the canonical Tape quick operations, visible
normal-loading default, detailed Tape Manager ownership, toolbar quick-control
presence, shared command-registry convergence, and consistent availability
predicates. The upstream-oriented implementation queue identifies task 312 as
the acceptance subset after tasks 301–311. Existing `tests/wz_ui_layout_tests.c`
checks labels and dispatches only `media.tape.insert`; the other four Tape
actions lack equivalent dispatch evidence.

## Disposition
`IMPLEMENT_NOW`: extend the existing UI layout contract test to register and
exercise every canonical Tape action through the shared registry, while keeping
the current production layout unchanged. No harness or wrapper changes are
permitted.

## Zero-Gap Exit Scan
Recheck UI §48 Tape-related criteria, Section 11 quick controls, Section 12
manager ownership, and Section 47 regression expectations. Confirm all five
stable IDs and labels are covered, all dispatches reach the common registry,
the normal mode remains the initialized default, and unavailable commands
retain deterministic disabled reasons.
