# CR-0263 Add Read-Only Screen Inspection Projection

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Provide one read-only projection of the current Spectrum display from the
  deterministic machine state into the canonical raster sample encoding.
- Cover the complete host-visible 448x312 raster, including border and blanking,
  while preserving the 256x192 active display geometry and stable palette indices.
- Decode bitmap, attribute, BRIGHT, FLASH phase, border, and 48K/128K screen-bank
  selection through existing machine timing and memory boundaries.
- Reject invalid machine, destination, dimensions, and storage without partial
  writes; never mutate machine state, wall-clock state, or host presentation state.
- Keep the projection independent of Sokol, GUI chrome, sockets, and host pixel
  formats so later presentation and screenshot commands consume the same source.

## Upstream Discovery

- Re-read the complete legacy `Screen`, video initialization, raster geometry,
  border, and screen-capture paths in `reference/original-warajevo/source/src`,
  including `environment/WARAJEVO.PAS`, `environment/KONVTAP.PAS`, and the
  spectrum-kernel video state.
- Compare active-pixel address decoding, attribute semantics, border coverage,
  screen dimensions, and 128K display-bank behavior with the canonical raster
  and machine profile contracts already implemented here.
- Re-read Architecture 1 sections 15, 16, 17, 18, 19.1, 19.6, 36, 37, and
  49.2, plus UI Architecture 2 sections 3.3, 8.4, 24, 40, and 47.
- Inventory existing `wz_raster_buffer`, raster evidence, Sokol upload, host
  crop, and screenshot-related boundaries; classify each as reusable core,
  host-only, or still missing.

## Disposition

| Surface | Disposition | Reason |
|---|---|---|
| Read-only complete-frame projection | IMPLEMENT_NOW | Required monitor/screen inspection workflow |
| Bitmap and attribute decoding | REUSE_CORE_CONTRACT | Existing canonical color semantics |
| Border/blanking projection | IMPLEMENT_NOW | Existing buffer encoding needs machine projection |
| 128K display-bank selection | IMPLEMENT_NOW | Must follow machine paging boundary |
| Sokol texture upload and GUI chrome | PRESERVE_HOST_BOUNDARY | Not deterministic screen truth |
| PNG/file destination selection | DEFER_TO_SCREENSHOT_CR | Separate host write workflow |

## Zero-Gap Exit Scan

Before closure, compare every accepted and rejected upstream screen/video branch
with projection behavior for 48K and 128K profiles, active pixels, border,
blanking, FLASH, BRIGHT, and invalid inputs. Confirm the projection is fully
read-only, uses no host RGB assumptions, and is the sole pixel source for later
presentation/screenshot work.

- Updated Phase-11 coverage matrix naming the passing screen inspection tests.
- Serial CODE, TEST_ARTIFACT, and DOCUMENTATION reviews for exact commits.

## Exit Gates
