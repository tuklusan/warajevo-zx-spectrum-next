# CR-0154 Preflight: Audio Speed-Boundary Transitions

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Prove that changing runtime speed across the host-audio audible boundary does
not stop or alter emulation, while host submission changes exactly according to
the frozen speed policy.

## Functional Inventory

- Transition from an audible speed to a muted speed without changing machine
  timing or state ownership.
- Transition from a muted speed back to an audible speed without stale audio
  enable state or stale pacing anchors.
- Re-anchor host pacing at each accepted speed change without a timing spike.
- Keep canonical machine execution independent of host-audio mute state.
- Reject invalid speed values without changing the active policy.

## Upstream Completeness Gate

Compare the preserved upstream runtime-speed and speaker behavior for speed
selection, pacing, mute boundaries, and emulation continuation. Preserve every
observable behavior that applies to the new host boundary, while keeping host
audio policy outside machine state.

## Upstream Discovery

The preserved upstream source has speed and speaker paths, but no WZSN
host-audio boundary. The applicable behavior is represented by the existing
speed policy and pacing contracts; this CR adds boundary-crossing regression
coverage rather than a second speed implementation.

## Disposition

Add deterministic tests that cross 2.0x-to-4.0x and 4.0x-to-0.5x boundaries,
observe host mute changes and pacing re-anchors, and advance the headless
machine between transitions.

## Zero-Gap Exit Scan

Close only when audible-to-muted, muted-to-audible, invalid-input, pacing
continuity, and continued-emulation cases have no undispositioned gap.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
