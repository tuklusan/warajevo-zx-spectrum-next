# CR-0086 Preflight: Timed Bus-Visible Data Source

Status: CLOSED

## Objective

Add a deterministic bus-visible data-source boundary that receives the fully
timed bus request and may claim a read cycle with a supplied value. This is the
mechanism required by later floating-bus work, without deciding ULA fetch
values or implementing a program-specific floating-bus rule.

## Functional Inventory

- Expose a source callback that sees cycle, address, master tick, duration, and
  contention delay after bus timing has been resolved.
- Permit a synthetic device to claim memory reads, I/O reads, and interrupt
  acknowledge reads with a deterministic byte value.
- Preserve existing ROM/RAM, ULA port-FE, legacy input callback, and fallback
  behavior when the new source does not claim a request.
- Keep writes observable through the existing bus request path without
  allowing a read source to mutate machine state implicitly.
- Preserve exact request and trace values after contention adjustment.
- Keep reset, null installation, and invalid-argument behavior deterministic.
- Preserve ABI-independent canonical machine state by keeping the source
  callback host wiring outside serialized emulation state.

## Upstream Completeness Gate

The architecture requires floating-bus results to derive from actual timed ULA
bus activity, and task 072 explicitly requires a synthetic device to supply
timed bus data before ULA fetch values are finalized. The preserved reference
sources were scanned for floating-bus reads, port input dispatch, memory-bus
ownership, and timing-visible bus activity. No reusable callback contract was
found; the project therefore defines a new boundary rather than copying a
host-specific implementation.

Authorities are architecture sections 12, 15.6, 36, 44, and 51; task 072;
`design/machine-timing-evidence.md`; and the preserved source under
`reference/original-warajevo/source/`.

## Upstream Discovery

The preserved implementation routes CPU and peripheral reads through concrete
memory and I/O paths, while the current WZSN bus already supports an observer
and an untimed compatibility input callback. Neither path supplies the
contention-adjusted request to a device, so neither can express a timed
bus-visible source without changing the bus contract.

## Disposition

Implement a request-aware claiming callback in the bus layer. Invoke it only
after contention timing has been applied and before the existing cycle-specific
fallbacks. Keep the existing input callback as the compatibility fallback.
Defer ULA fetch scheduling, floating-bus value selection, raster visibility,
and model-specific source arbitration to named later tasks.

## Zero-Gap Exit Scan

Before closure, rescan memory read, opcode fetch, I/O read, interrupt
acknowledge, write, contention, observer, trace, reset, and state
serialization paths, plus the preserved reference dispatch paths. Every result
must be implemented, covered by a fixture, or explicitly deferred to a named
later task.

## Verification Plan

- Local static gate and source scan only; no local build or test execution.
- Remote Linux CMake/CTest and complete pinned Fuse suite.
- Hosted platform smoke across Linux, Windows, and macOS targets.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Synthetic source vectors for claimed and unclaimed reads, post-contention
  timing visibility, interrupt acknowledge, null reset, and trace preservation.
