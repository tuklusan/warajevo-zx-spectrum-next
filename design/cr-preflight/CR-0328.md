## Change Request
CR-0328: Implement Compatibility Tools container and availability rules

Status: APPROVED_FOR_IMPLEMENTATION
Priority: medium

## Functional Inventory
- Provide one Compatibility Tools container below `Tools`, separate from ordinary
  machine and media workflows.
- Expose the initial category identities: Tape Converter, Snapshot Converter,
  Spectrum Data Converter, Microdrive Tools, and Legacy Database Converter.
- Represent each tool with a stable shared command-registry ID, a visible label,
  an availability predicate, and a machine-readable unavailable reason.
- Keep unavailable or later tools visibly unavailable or explicitly marked later;
  never present a non-working conversion as available.
- Keep native loading of supported TAP, TZX, WAV, SNA, Z80, and MDR media in the
  normal file/media workflows; conversion remains an explicit preservation action.
- Require conversion metadata to identify source format, destination format,
  warnings, and whether machine state, timing, metadata, or other capabilities
  may be lost before an output is written.
- Preserve atomic host-file behavior: rejected, unsupported, malformed, or failed
  conversions must not partially replace the source or destination.
- Keep Compatibility Tools host-side and presentation-owned; they must not mutate
  canonical emulated machine state or duplicate media/emulation semantics.
- Ensure GUI, Telnet discovery, automated tests, and future front ends project the
  same semantic command identities and availability results.

## Upstream Discovery
- UI architecture section 3.3 defines the single semantic command registry.
- UI architecture sections 3.5, 3.6, 7.1, 12.3, 15.5, 17, 19, 20.3,
  20.6-20.18, and 22 define grouping, legacy disposition, conversion boundaries,
  and the complete initial category structure.
- Core architecture sections 2.5, 28.7, 41, 44, 49.1, and 49.2 define the
  legacy-feature disposition, host-data safety, failure isolation, and ticket
  acceptance contract.
- `design/migration-ledger.md` is the provenance and clearance authority for
  legacy routines and retained utilities; no historical implementation is copied
  by this CR.
- Existing `src/app/wz_command_registry.[ch]`, `src/app/wz_ui_layout.[ch]`,
  and current command-surface tests are the implementation seams. No separate
  Compatibility Tools container currently exists.
- The preserved Warajevo reference implementation and its conversion menu/routines
  must be inspected before implementation. Every relevant operation is classified
  as retained, later, dropped, or replaced, with no unexplained omission.

## Disposition
`IMPLEMENT_NOW`: add the project-owned Compatibility Tools presentation model and
shared command metadata/availability contract. Do not implement format converters
whose architecture and clearance are not yet frozen; expose them as later or
unavailable with explicit reasons instead.
