## Change Request
CR-0307: Implement the Tape Insert quick action

Status: CLOSED
Priority: medium

## Functional Inventory
- Expose the stable `media.tape.insert <path>` application workflow boundary.
- Accept already-parsed tape segments from the owning media parser.
- Treat a cancelled file chooser as a no-op with no machine or source-state mutation.
- Reject empty, overlong, or malformed media without replacing an existing tape.
- Mount valid media atomically through the canonical machine tape API.
- Retain the selected source identity for toolbar/status presentation.
- Reject ordinary tape transport while `Ear+Mic` owns cassette signals with a stable reason.
- Keep the workflow independent of GUI toolkit and host file-dialog implementation.

## Upstream Discovery
UI Sections 8.1, 11.1, 11.4, 20.1, 45, and 48 define Insert Tape as the
universal quick action and require cancellation/error state preservation. Task
301 is the derived backlog item. The preserved upstream source was searched for
the legacy tape selection behavior; the project core already owns validated
tape mounting, but no project-owned UI transaction boundary existed. No
upstream behavior remains undispositioned.

## Disposition
`IMPLEMENT_NOW`: add an application-level Tape Insert workflow that delegates
validated segment ownership to `wz_machine_mount_tape`, records source identity
only after successful mounting, and provides the stable transport availability
reason required by the registry layer.
