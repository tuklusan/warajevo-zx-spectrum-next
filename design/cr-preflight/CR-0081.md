# CR-0081 Preflight: ULA Port-FE Output Latches

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Implement the normalized 48K ULA port-FE output state required by task 067:
border color, beeper/speaker output, and MIC output must be latched by decoded
I/O writes at the requesting master tick, with deterministic same-edge ordering.

## Functional Inventory

- Accept only ULA-selected port-FE writes through the existing partial-address
  decode path; leave odd-port writes available to other devices.
- Latch border color from data bits 0..2.
- Latch MIC output from data bit 3.
- Latch beeper/speaker output from data bit 4.
- Preserve the complete last output byte or equivalent canonical fields for
  deterministic inspection and future audio/video consumers.
- Apply writes in bus order at the supplied master tick without host-time
  decisions or reordering.
- Reset all output fields to the documented power-on values.
- Preserve output fields through canonical state serialization and restore.
- Emit a trace-visible output transition with address, value, source, and
  master-tick ordering when the trace facility is enabled.
- Keep fixture-only I/O decode bypass behavior unchanged.
- Reject invalid machine pointers consistently and avoid undefined behavior.

## Upstream Completeness Gate

Before implementation, inspect the preserved reference implementation and
architecture documents for every port-FE write consumer and side effect,
including border, speaker, MIC, tape EAR interactions, and ordering with CPU
bus operations. The primary source is
`reference/original-warajevo/source/src/spectrum-kernel/SPECSIM.ASM`; related
authority is sections 12, 15, 20, 36, and 44 of
`design/warajevo-zx-spectrum-next-architecture.md`.

## Upstream Discovery

Discovery targets are the reference port-FE output write routine, all callers
that depend on border, speaker, or MIC state, and all existing project bus,
trace, state, and test interfaces that can observe those effects. Record exact
source locations and behavior here before implementation; do not infer missing
behavior from the new code.

## Disposition

Implement the three classic 48K output latches and their canonical state in
this CR. Defer rasterized border presentation, canonical audio mixing, tape
EAR edge generation, contention, and host presentation to their named later
architecture tasks while preserving the output bits needed by those tasks.

## Zero-Gap Exit Scan

After implementation, repeat a line-by-line scan of the upstream routine,
related call sites, architecture sections, changed production code, tests, and
serialization. Every discovered behavior must be marked implemented here,
deferred to a named CR, or proven inapplicable. This section is not complete
until the scan has no unclassified behavior.

The implementation exit gate is a second deep scan of those sources and the
changed code, with each discovered behavior classified as implemented here,
explicitly deferred to a named later CR, or proven inapplicable. No implicit
host behavior is an acceptable disposition.

## Verification Plan

  round-trip.
- Linux remote CMake, CTest, complete pinned Fuse suite, and evidence summary.
- Hosted platform smoke across all configured targets.
- CODE and DOCUMENTATION advisory reviews against this preflight and the
