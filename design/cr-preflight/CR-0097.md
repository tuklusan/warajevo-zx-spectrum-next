# CR-0097 Preflight: Timed Floating-Bus Values

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Derive the 48K floating-bus read value from the actual timed ULA bitmap and
attribute fetch state, rather than from program identity or frame-level
approximations.

## Functional Inventory

- Expose the ULA data-bus value at a specified canonical master tick.
- Return bitmap or attribute bytes during their exact fetch windows.
- Return the frozen open-bus value outside an active ULA fetch.
- Preserve fetch ordering when bitmap and attribute events are adjacent.
- Use current display memory values selected by the timed fetch model.
- Keep floating-bus reads side-effect free and independent of host time.
- Reject or define unsupported machine profiles deterministically.
- Cover active display, blanking, non-display lines, frame wrap, and changed
  display-memory values.
- Keep border, pixel decoding, FLASH, presentation, and network state outside
  the deterministic floating-bus API.

## Upstream Completeness Gate

Architecture sections 15.6, 18, 36, and 44 require floating-bus behavior to
derive from real timed ULA bus activity. Rescan preserved ULA display paths,
floating-bus assumptions, port-read routing, fetch event timing, and the
architecture’s open-bus boundary. Every scoped rule must be implemented,
tested, or assigned to a named later task.

## Upstream Discovery

The preserved reference supplies the legacy ULA display and bus context. The
current core now exposes profile-driven bitmap/attribute fetch events and the
port-FE bus boundary, but has no public floating-bus projection. This ticket
connects those timed fetch values to a side-effect-free query without adding
program-specific compatibility rules.

## Disposition

Add a core query that resolves floating-bus data from the same fetch scheduler
used by raster events. Return a deterministic open-bus value when no ULA fetch
owns the requested tick. Do not add host or software-recognition behavior.
Tasks 084-095 retain ownership of sample encoding, raster buffer, pixels,
FLASH, diagnostics, and Phase-4 acceptance.

## Zero-Gap Exit Scan

Before closure, rescan preserved ULA/bus paths, fetch timing and values,
open-bus behavior, profile boundaries, and later-task assignments. Confirm no
scoped floating-bus behavior remains implicit or approximated.

## Verification Plan

- Local static gates and source scan only; no local build or test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux build/test with exact bitmap/attribute/open-bus fixtures and the
  complete pinned corpus.
- Hosted platform smoke across the supported matrix.
- Repeat floating-bus values and fetch traces across supported hosts.
