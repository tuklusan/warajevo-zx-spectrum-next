# CR-0161 Preflight: SAVE/MIC Tape Output

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Implement the deterministic core-side SAVE/MIC output path as emulated-time
transitions. The core must expose MIC waveform transitions caused by the
authentic machine path without opening files or depending on host wall clock;
host recording and export remain a separate adapter responsibility.

## Functional Inventory

- Preserve the ULA port-FE MIC output latch as a distinct machine-visible state.
- Record MIC transitions at their exact canonical master ticks and in request
  order, including repeated writes and transitions that do not change beeper
  output.
- Keep SAVE/MIC capture driven by emulated execution and not by host pacing,
  audio callbacks, GUI state, or filesystem activity.
- Define capture start, stop, reset, empty-capture, and bounded-capacity
  behavior without partially mutating published output on failure.
- Preserve the existing cassette ownership boundary and reject ordinary tape
  capture when the reserved `EAR_MIC` networking mode owns the signal path.
- Expose a stable core-owned transition representation that a host adapter can
  serialize later without changing timing or machine state.
- Add headless fixtures for exact tick ordering, MIC-only changes, repeated
  levels, overflow/error behavior, and capture isolation from host pacing.

## Upstream Completeness Gate

Before implementation, compare the upstream SAVE, MIC, port-FE, tape, and
loader paths line-by-line in `WARAJEVO.PAS`, `LOADER.ASM`, `SPECCOMP.ASM`,
`TSZ80.ASM`, and `Z80_C.ASM`. Inventory every applicable observable rule for
SAVE initiation, bit-4 MIC writes, timing, edge ordering, stop/error behavior,
and the separation between normal emulation and accelerated paths. Also
compare the current port-FE, audio-event, tape, ownership, and state APIs so
no existing behavior is duplicated or bypassed.

## Upstream Discovery

The current migrated layers already retain the port-FE MIC latch and
timestamped output/audio events, while CR-0158 through CR-0160 establish
validated in-memory tape state and canonical playback time. The remaining
ordered gap is a core-owned, deterministic output transition stream suitable
for SAVE/MIC capture. File export, format writing, and loader acceleration are
not part of this CR and must remain explicitly assigned to later tasks.

## Disposition

Implement only the core capture state, exact transition publication, bounded
error behavior, and deterministic headless tests. Do not implement standard
TAP writing, Warajevo-native writing, TZX/WAV parsing, instant loading, trap
detection, host file export, or networking-mode behavior beyond enforcing the
existing ownership boundary.

## Zero-Gap Exit Scan

Before closure, repeat the upstream comparison against changed port-FE,
machine-state, audio-event, tape-ownership, runner, and test paths. Close only
when every applicable SAVE/MIC rule is implemented or assigned to a later
ordered task, with serialized CODE and DOCUMENTATION reviews, remote
validation, the full hosted matrix, clean repository gates, and published
evidence.

## Verification Plan

- Static repository gates and source inspection on the development machine only.
- Serialized pre-development and final CODE/DOCUMENTATION reviews.
- Remote Linux and Windows smoke tests, with sanitizer coverage where useful.
- Full hosted platform matrix.
- Headless fixtures proving canonical ticks, ordering, isolation, bounded
  failure behavior, and ownership rejection.
