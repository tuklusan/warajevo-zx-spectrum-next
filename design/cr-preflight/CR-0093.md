# CR-0093 Preflight: Implement 48K ULA Raster Coordinate Timing

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Implement the canonical 48K ULA raster coordinate and timing state over the
full 312-line frame and 448 raster-clock positions per line, with deterministic
boundary behavior and canonical serialization. Do not implement bitmap fetches,
border rendering, or floating-bus behavior in this ticket.

## Functional Inventory

- Represent line, raster-clock, frame phase, and master-tick conversion using
  the frozen 48K PAL timing baseline.
- Advance and wrap coordinates deterministically across line and frame edges.
- Expose boundary positions needed by later ULA fetch and raster consumers.
- Define reset, serialization, hashing, and invalid-state behavior for the new
  canonical raster timing state.
- Cover first/last raster clocks, first/last lines, frame wrap, and repeated
  multi-frame advancement.
- Keep host wall clock, Sokol, pixel presentation, and software-specific hacks
  outside the core timing state.

## Upstream Completeness Gate

Architecture sections 15.1-15.2 and 49.1 require a full raster-time coordinate
system before scheduled ULA fetches. Scan preserved `SPECSIM.ASM` ULA entry and
frame/timer paths plus the architecture timing evidence; every scoped counter,
origin, wrap rule, and conversion must be implemented or explicitly deferred.

## Upstream Discovery

The preserved source contains selectable ULA simulation and timer-driven state,
but its host-era representation is not a portable canonical raster contract.
The project already freezes the 7 MHz master domain, 448 raster clocks per line,
312 lines per frame, and 69,888 CPU T-states per frame. The missing slice is an
explicit project-owned raster coordinate state with tested boundaries.

## Disposition

Add the smallest portable core state and APIs needed for raster coordinates,
with deterministic tests and state participation. Preserve the bus boundary;
ULA memory fetch scheduling, border semantics, pixel decoding, FLASH, and
floating bus remain separately owned by Tasks 080-095.

## Zero-Gap Exit Scan

Before closure, rescan preserved ULA/timer paths, frame geometry, master-tick
conversion, reset, wrap, serialization, hashing, and later-task boundaries.
Every discovered behavior must be implemented, covered, classified, or assigned
to a named later task.

## Verification Plan

- Local static gates and source scan only; no local build or test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux build/test plus complete pinned corpus.
- Hosted platform smoke across the supported matrix.
- Repeat the raster boundary fixture and compare canonical serialized/hash
  results across supported hosts.
