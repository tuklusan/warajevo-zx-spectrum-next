## Change Request
CR-0329: Distinguish native load/run from explicit conversion workflows

Status: APPROVED_FOR_IMPLEMENTATION
Priority: medium

## Functional Inventory
- Classify initial supported native-open formats as TAP, TZX, WAV, SNA, Z80,
  and MDR according to the frozen media architecture.
- Distinguish a native load/run action from an explicit preservation conversion;
  native support must never silently invoke a converter.
- Return stable machine-readable classifications for native load, explicit
  conversion, unsupported conversion, and unknown format.
- Keep conversion output host-side and atomic, with no canonical machine-state
  mutation and no implicit lossy transformation.
- Preserve the Compatibility Tools catalog and shared command identity while
  making native-load eligibility independently queryable by file format.
- Reject ambiguous or unsupported formats with stable reasons rather than guessing.

## Upstream Discovery
- UI architecture sections 7.1, 8.1, 12.3, 15.5, 17, 20.6-20.18, and 22.2
  define native media entry and explicit conversion boundaries.
- Core architecture sections 2.5, 23, 28.7, 41, 44, 49.1, and 49.2 define
  format support, host-data safety, atomic failure behavior, and ticket gates.
- `design/media-format-support.md` and `design/migration-ledger.md` are the
  format and provenance authorities.
- Existing `src/app/wz_file_open_run.[ch]`, snapshot/media managers, and the
  Compatibility Tools catalog are the implementation seams.
- Inspect the preserved Warajevo file dispatch and conversion routines before
  implementation; classify every relevant route as native, explicit conversion,
  unsupported, or deferred with no silent gap.

## Disposition
`IMPLEMENT_NOW`: add a pure format-routing classification API over the existing
native media boundaries. It must not implement converters or change native media
load behavior.

## Zero-Gap Exit Scan
Re-read the cited architecture sections, media-format support, migration ledger,
and relevant upstream dispatch/conversion paths after implementation. Confirm
that every initial format has one unambiguous route, conversion is never implicit,
unknown/unsupported formats have stable reasons, and no state or file-safety rule
is bypassed.
