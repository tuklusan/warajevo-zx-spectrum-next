# CR-0133 Preflight: Kempston Port Decode

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Freeze the hardware-visible Kempston joystick port address and bit decoding
contract before implementing deterministic joystick state.

## Functional Inventory

- Identify the canonical Kempston port address and decode mask.
- Freeze direction and fire bit positions and active-high semantics.
- Define behavior for unrelated ports and simultaneous direction bits.
- Separate joystick state from keyboard matrix state.
- Record upstream and architecture provenance for every bit.
- Provide direct read/decode tests for all bits and combinations.

## Upstream Completeness Gate

Inspect preserved upstream port tables, input routines, constants, and tests for
Kempston behavior. Compare all address aliases, bit meanings, masking, and
unrelated-port behavior with the architecture and current bus decode; record
every retained or intentionally excluded behavior.

## Upstream Discovery

The architecture requires a separate deterministic Kempston device, not
keyboard-matrix shortcuts. This CR freezes decode semantics only; state
ownership and machine integration remain the next ordered task.

The preserved `SPECCOMP.ASM` and `SPECSIM.ASM` identify the Kempston read as
port 31 decimal (`0x1F`) and preserve the active-high conversion table
`RIGHT=0x10`, `LEFT=0x08`, `DOWN=0x02`, `UP=0x01`, `FIRE=0x04`. The five bits
are independently readable and may be combined. No other port is a Kempston
read for this initial contract; unrelated ports retain their existing device
decode.

## Disposition

Produce a documented decode contract and focused tests. Do not implement host
controller mappings, keyboard behavior, networking, or timing in this CR.

## Zero-Gap Exit Scan

Close only when address selection, all five input bits, simultaneous-bit
behavior, unrelated ports, and upstream provenance are explicitly evidenced.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux and Windows smoke validation for implementation changes.
- Hosted platform matrix validation for implementation changes.
- Final upstream zero-gap scan and publication evidence.
