# CR-0291 Transactional Load Snapshot workflow

Status: IN_PROGRESS
Priority: high
Execution order: architecture_2_phase_12n
Blocking: no

## Functional Inventory

- Accept a complete native snapshot byte stream for the Load Snapshot action.
- Validate the full stream before replacing the committed snapshot.
- Preserve the prior committed snapshot after malformed, truncated, or
  unsupported input.
- Expose a stable success/error result for UI reporting.
- Keep loading separate from saving, inspection, and host file-dialog concerns.

## Upstream And Architecture Discovery

- UI Architecture Sections 8.3 and 13.1 require `snapshot.load` to be a direct
  front end to the snapshot subsystem and require atomic failure behavior.
- The core snapshot loaders already validate SNA and Z80 streams through
  temporary candidate state; this CR supplies the application transaction seam
  around the validated snapshot payload.
- The legacy reference snapshot workflow reports malformed and unsupported
  input without presenting a partially loaded machine state.
- No deterministic core, transport, local/hosted harness, or wrapper changes
  are allowed.
