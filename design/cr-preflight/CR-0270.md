# CR-0270 Implement the Phase-12B Main Application Layout Boundary

Status: CLOSED
Priority: HIGH
Execution order: ARCHITECTURE_2_PHASE_12B
Blocking: NO

## Functional Inventory

- Provide the semantic main-window composition: menu bar, compact toolbar,
  Spectrum viewport, optional Machine/Media status panel, status indicators,
  and on-demand panel slots.
- Register the exact top-level menu order and IDs: File, Machine, Media, View,
  Tools, Settings, and Help.
- Freeze the toolbar semantic order: Open/Run, Pause/Resume, Reset, speed,
  Tape, Load Snapshot, Save Snapshot, MDV 1, Screenshot, Fullscreen, Debugger.
- Expose default 48K, 100% speed, running, audible, no-media state and explicit
  status text for model, speed, pause state, audio, tape, MDV 1, and Control
  Port unavailable/number state.
- Keep the Spectrum viewport visually primary and keep layout state separate
  from deterministic machine state, toolkit objects, sockets, and host dialogs.
- Make all future menu and toolbar actions consume the shared command registry;
  this CR does not create duplicate semantic handlers.

## Upstream Discovery

- Re-read the preserved menu, toolbar, status, and application-start paths in
  `reference/original-warajevo/source/src/environment/WARAJEVO.PAS`,
  `DOSMENU.PAS`, `MENUCONS.PAS`, and `SETUP.PAS`.
- Retain the upstream capability inventory while deliberately replacing DOS-era
  navigation with the modern UI Architecture 2 menu and manager boundaries.
- Compare every layout requirement against UI Architecture 2 Sections 3, 4,
  6, 7, 18, 24, 25, 40-45, 47-49 and Core Architecture Sections 19, 27,
  30, 31, 41, 49.2, and 51.
- Perform a second upstream zero-gap scan after implementation, including
  legacy start/status/menu behavior, applicability/disabled state, keyboard
  focus, platform menu relocation, and no-core-mutation presentation rules.
