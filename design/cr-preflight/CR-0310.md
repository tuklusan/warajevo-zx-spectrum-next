## Change Request
CR-0310: Implement Tape Manager block list/details presentation

Status: CLOSED
Priority: medium

## Functional Inventory
- Present mounted tape source identity, format, loading mode, current block/position,
  playback/loading state, and selection state.
- Present an ordered block list with block type, logical length, stored length where
  meaningful, and applicable flags/metadata.
- Keep presentation data derived from the media subsystem; do not duplicate tape
  transport or emulator state.
- Represent standard TAP/TZX and native tape metadata without exposing unsupported
  mutation operations as if they were available.
- Keep the model suitable for the later manager mutation operations and GUI surface,
  without coupling it to a toolkit or host dialog.

## Upstream Discovery
The UI architecture sections 12.1, 12.2, 12.4, 12.5, 20.1, 20.2, 45, and 48
define the manager presentation and its failure boundary. Developer task 305 is
the derived backlog item. The current media subsystem already exposes TAP, native
TAP, and TZX parsed block metadata in `src/core/wz_tape.h`; the current UI has no
manager model. No required presentation field remains undispositioned.

## Disposition
`IMPLEMENT_NOW`: add a toolkit-neutral Tape Manager presentation model that
normalizes the existing parser metadata into bounded, inspectable block rows and
stable source/state details. Mutation, persistence, and host-dialog behavior remain
outside this ticket and are reserved for the later tasks in the same phase.

## Zero-Gap Exit Scan
Confirm every Section 12.1 field has a representation, standard/native/TZX block
metadata is mapped without loss where the parser supplies it, ordering and
selection are deterministic, unsupported/unknown metadata is explicit, and no
manager presentation path mutates machine or media state.
