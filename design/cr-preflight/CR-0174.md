# CR-0174: Restore Lab Endpoint Authority and Hosted-Runner Waiting Rules

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Track the lab endpoint restoration and the synchronized workflow clarification
that hosted jobs which are queued or slow remain active until GitHub reports a
terminal result. This is infrastructure and project-governance work; it does
not alter emulator behavior or replace any upstream product behavior.

## Functional Inventory

- Keep one authoritative SSH target for each approved lab machine.
- Record the current Linux, macOS/Intel, Windows 10, and Windows 11 addresses.
- Keep each machine's approved remote project directory unchanged.
- Keep the macOS one-GiB confinement and private-key handling requirements.
- Keep private host-key and credential records under ignored
  `test-artefacts/` paths only.
- Keep unavailable-host transport failures environmental and non-fatal to
  multi-platform correctness evidence.
- Require the complete hosted runner matrix for multi-platform proof.
- Preserve `fail-fast: false` and wait for queued or slow hosted lanes.
- Prevent a queued lane from being classified as failed, canceled, or replaced
  before GitHub reports a terminal conclusion.
- Keep the aggregate publication gate bound to all expected jobs and one exact
  commit SHA.
- Keep Windows PowerShell execution behind the parser-first harness.
- Keep all local build and test execution prohibited.
- Keep public artifacts limited to the documented workflow and harness files;
  private connection data and pulled results remain ignored.

## Upstream Discovery

The controlling project authorities are `WORKFLOW.md`,
`test-artefacts/README.md`, `README-GIT-GITHUB.md`,
`tools/harness/README.md`, `tools/harness/invoke_remote_harness.py`,
`.github/workflows/platform-smoke.yml`, and
`tools/validate_project_gates.py`. Private connection evidence is limited to
the ignored files under `test-artefacts/`.

The preserved upstream Warajevo source was checked for this infrastructure
change. It contains no authority for current lab IP addresses, SSH policy,
host-key storage, hosted CI capacity, or this project's publication aggregate.
There is therefore no upstream product behavior to migrate for this CR.

## Disposition

- `IMPLEMENT_NOW`: synchronize the four current lab SSH targets and status
  records across the shared harness and public workflow documents.
- `IMPLEMENT_NOW`: record the current private host-key aliases and connection
  notes without publishing secrets.
- `IMPLEMENT_NOW`: state terminal-state waiting and non-fatal unavailable-host
  handling in the workflow and hosted-runner documentation.
- `NOT_APPLICABLE`: upstream emulator behavior; this CR changes no product
  execution path.
- `NOT_APPLICABLE`: local build or test execution; project policy forbids it.

## Zero-Gap Exit Scan

The authority scan was repeated across the shared harness configuration, all
workflow documents, the static validator, the private connection records, and
the hosted workflow. Every endpoint, directory confinement, privacy rule,
availability rule, parser-first rule, hosted waiting rule, and publication
identity rule has an explicit disposition above. No undispositioned behavior
was found.

## Verification Plan

- Static repository gates and whitespace checks on the development machine.
- Serialized remote probes through the approved harness for all four lab hosts.
- Hosted platform matrix for the exact published commit, waiting for every
  configured lane to reach a terminal state.
- External review of the exact committed change and documentation artifacts.
- Final cross-document reconciliation before closure.
