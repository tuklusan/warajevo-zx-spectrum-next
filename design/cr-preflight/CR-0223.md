# CR-0223 Windows ARM Hosted Validation and Evidence Gate

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Add hosted `windows-11-arm` and `windows-11-vs2026-arm` matrix lanes.
- Keep each lane on the exact workflow commit and retain its logs and artifacts.
- Discover and record the ARM compiler, CMake, CTest, Python, and build-helper paths.
- Require a successful CMake build/test result and a machine-readable result manifest.
- Capture visual evidence when the lane and application support an interactive display.
- Inspect every produced screenshot and trace for existence, non-zero size, and hash.
- Record unsupported visual/trace capabilities explicitly rather than silently skipping them.
- Preserve inspected evidence in private `test-artefacts` closure material.

## Upstream and Workflow Completeness Gate

Re-read the hosted runner matrix, publication gate, remote evidence policy, and
the architecture visual-validation requirements before implementation. Confirm
that adding ARM lanes does not weaken the existing exact-SHA, housekeeping,
artifact, macOS, or failure semantics. Keep hosted runners ephemeral and do not
introduce self-hosted runner dependencies.

## Upstream Discovery

The current workflow runs 18 hosted labels and verifies only job conclusions.
The public runner catalogue includes two Windows ARM labels that are not yet
exercised. Existing lane artifacts contain summary, inventory, and conformance
records, but no common publication-time inspection record. The first 20-lane
hosted run confirmed that the ordinary Windows ARM lane passed, while the
VS2026 ARM lane selected ARM64 Clang objects with x64 MSVC and SDK library
paths. The shared smoke harness therefore needs native target-architecture
selection for both developer-environment initialization and linker paths.

## Disposition

- Windows ARM hosted labels and expected-label accounting: `IMPLEMENT_NOW`.
- Per-lane result/evidence inspection and publication enforcement: `IMPLEMENT_NOW`.
- Native Windows ARM64 developer-environment and linker-library selection:
  `IMPLEMENT_NOW` after the first hosted mismatch.
- Full interactive application capture remains conditional until the UI host
  exists; supported lanes must produce and inspect it once enabled.

## Zero-Gap Exit Scan

Rescan the matrix labels, runner architecture selection, cleanup ordering,
result-manifest creation, artifact upload retries, screenshot and trace
inspection, and publication counting. Confirm no lane can pass without a
result manifest and that unsupported visual capture is explicit.

## Exit Gates

- Static repository gates and `git diff --check` pass locally; no local build or test.
- Exact-SHA CODE, DOCUMENTATION, and independent bootstrap reviews pass.
- Hosted matrix reports 20 expected lanes with both Windows ARM labels present.
- Every lane has a passing result manifest and retained inspection record.
- Any supported visual lane has an inspected screenshot; any produced trace is inspected.
- The CR closure record references the hosted run and private evidence paths.
