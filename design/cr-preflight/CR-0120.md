# CR-0120 Preflight: Freeze Linux Graphics Backend

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Freeze the initial Linux graphics backend within the architecture's X11
baseline before Linux host code is implemented.

## Functional Inventory

- Record the selected Linux window/context backend and rationale.
- Keep backend selection in host infrastructure, not deterministic core code.
- Define hosted and remote validation expectations for the decision.
- Identify unavailable or deferred backend requirements explicitly.

## Upstream Completeness Gate

Compare the architecture's X11 baseline, pinned Sokol capabilities, existing
remote Linux environment, and preserved upstream behavior. Record every
backend-specific assumption that host implementation must honor.

## Upstream Discovery

The architecture names X11 as the initial Linux baseline. CR-0119 pins Sokol;
this CR freezes the platform backend choice without adding host callbacks.

## Disposition

Document X11 as the initial Linux backend and defer other backends unless a
later architecture-approved task requires them. Do not alter core behavior.

## Zero-Gap Exit Scan

Close only when the backend, boundary, rationale, deferred alternatives, and
validation contract are explicit and consistent with upstream evidence.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux smoke and hosted matrix validation.
- Final upstream zero-gap scan and publication evidence.
