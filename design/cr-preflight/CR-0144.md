# CR-0144 Preflight: Canonical Internal Audio Sample Rate

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Freeze and document one deterministic internal PCM sample rate before mixer
implementation, independently of host device rates.

## Functional Inventory

- Freeze one explicit integer canonical sample rate for core PCM generation.
- Expose the decision through a project-owned audio policy boundary.
- Make master-tick-to-sample conversion a later deterministic integer/rational concern.
- Keep host device rate, callback size, resampling, and delivery outside canonical policy.
- Ensure the policy cannot vary by operating system or compiler.
- Add a regression assertion binding the documented rate to the source constant.

## Upstream Completeness Gate

Inspect preserved upstream sound configuration and compare its PC-speaker/host
device assumptions with the new canonical audio boundary. Retain emulated
timing intent but do not inherit host sound-card rates as deterministic state.

## Upstream Discovery

The preserved upstream project exposes host speaker configuration rather than a
portable canonical PCM timeline. The architecture requires a new fixed core
policy; 44,100 Hz is frozen for initial implementation, while physical host
rates remain delivery concerns.

## Disposition

Add `WZ_CANONICAL_AUDIO_SAMPLE_RATE` at 44,100 Hz and document it in the audio
architecture section. No mixer or host resampler is implemented by this CR.

## Zero-Gap Exit Scan

Close only when the numeric choice, source declaration, architecture wording,
host-rate separation, cross-platform invariance, and regression assertion have
no undispositioned gap.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
