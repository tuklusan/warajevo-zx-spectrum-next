# CR-0094 Preflight: Scheduled ULA Bitmap and Attribute Fetches

Status: CLOSED

## Objective

Implement the 48K ULA display-memory fetch schedule as deterministic bus
events at exact master ticks. Each active display character cell must fetch
one bitmap byte and one attribute byte from the canonical 48K display layout,
with the fetch address, value, source, and timing visible to trace consumers.
This ticket does not implement pixel decoding, border output, FLASH, or
floating-bus policy.

## Functional Inventory

- Identify the active display window from the canonical raster position.
- Generate the bitmap and attribute fetch events at the frozen per-cell
  master-tick offsets.
- Calculate Spectrum bitmap addresses using the three interleaved bitmap
  bands and row-within-character ordering.
- Calculate attribute addresses in the 0x5800-0x5aff display attribute area.
- Read values through the machine memory/bus boundary and mark the ULA as the
  bus source without mutating CPU-visible state.
- Preserve deterministic ordering when bitmap and attribute events share a
  raster cell, including trace order and repeated-frame behavior.
- Keep non-display lines and horizontal blanking free of active display fetches.
- Define reset, frame-wrap, invalid-profile, and trace-disabled behavior.
- Leave CPU write versus ULA visibility, border, pixel, FLASH, and
  floating-bus semantics to their named later tasks.

## Upstream Completeness Gate

Architecture sections 15.3 and 15.5 require the ULA fetch schedule to precede
pixel decoding and floating-bus behavior. Inspect the preserved ULA display
paths and the architecture timing evidence for display origin, line window,
cell cadence, bitmap interleave, attribute layout, bus source, and same-edge
ordering. Every scoped rule must be implemented, tested, or explicitly
assigned to a later task.

## Upstream Discovery

The preserved source is the reference for the legacy display-memory layout
and ULA timing context. The current project already exposes canonical raster
coordinates, machine memory, bus requests, timing traces, and 48K PAL frame
geometry. The missing slice is a project-owned scheduled fetch stream that
connects those existing boundaries without embedding presentation behavior in
the deterministic core.

## Disposition

Add a small core fetch-event representation and a deterministic scheduler or
enumeration API backed by the existing machine memory and trace boundaries.
Use explicit profile geometry rather than host time or presentation APIs.
Tasks 081-095 retain ownership of same-edge CPU-write visibility, border,
floating bus, sample encoding, raster buffer, pixel/color/FLASH semantics,
diagnostics, and acceptance closure.

## Zero-Gap Exit Scan

Before closure, rescan the preserved display/ULA paths, architecture sections
15.3 and 15.5, frozen timing tables, memory map, raster boundaries, trace
schema, and later-task assignments. Confirm every discovered fetch behavior is
implemented and covered, or classified under a named later task with no silent
special case.

## Verification Plan

- Local static gates and source scan only; no local build or test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux build/test with exact bitmap/attribute address traces and the
  complete pinned corpus.
- Hosted platform smoke across the supported matrix.
- Repeat the fetch trace across frame wrap and supported hosts, checking exact
  event ordering and canonical values.
