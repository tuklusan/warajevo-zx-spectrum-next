# CR-0184 SNA 48K Loader

Status: CLOSED

## Functional Inventory

- Accept exactly one standard 48K SNA image: 27-byte header plus 49,152 RAM
  bytes, with no truncation or trailing data.
- Decode every header register pair in the frozen order, including I, IFF2, R,
  IM, border, SP, and the alternate register bank.
- Load RAM into a temporary initialized 48K machine and recover PC from the
  little-endian word at the temporary SP, advancing SP by two with 16-bit wrap.
- Reject invalid IFF2 encodings, interrupt modes, border values, null input,
  wrong length, and invalid temporary state without changing the snapshot
  object or any live machine.
- Publish only the canonical WZSN representation through the existing bounded
  snapshot object; leave tape, networking, and host state at deterministic
  defaults.

## Upstream Discovery

The upstream snapshot loader and header structure were compared with the frozen
matrix and current register/memory model. Upstream's 48K path restores the
header register banks and memory image; this portable implementation preserves
that behavior while adding the required isolated validation boundary.

## Disposition

- Standard SNA 48K parsing and canonical temporary-state publication:
  `IMPLEMENT_NOW`.
- SNA 128K extension, Z80 parsing, writers, and live-machine commit:
  `DEFERRED_WITH_CR` under the ordered Phase-8 tasks.
- Unsupported variants, malformed input, and trailing bytes:
  `CONTROLLED_ERROR` with no partial publication.

## Zero-Gap Exit Scan

The frozen matrix, upstream 48K load path, temporary snapshot object, CPU
register validation, and machine defaults were rescanned. All fields present
in the standard SNA 48K form have a defined destination or controlled error;
no 128K or alternate-format behavior is silently included.

## Closure Requirements

- Static repository gates pass.
- Exact-SHA CODE and DOCUMENTATION reviews pass.
- Linux and Windows remote smoke prove valid and malformed SNA cases.
