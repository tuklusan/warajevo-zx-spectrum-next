# CR-0274 Prevent Premature CR Closure Before Final Review

Status: CLOSED
Priority: HIGH
Execution order: WORKFLOW_FIRST_OUT_OF_ORDER
Blocking: NO

## Functional Inventory

- Keep a CR active while its implementation, evidence, and final review gates
  are still being processed.
- Validate that the tracker status and preflight status agree before starting
  each review.
- Permit the closed transition only after the final documentation packet has a
  passing verdict and all required evidence is recorded.
- Make a failed or refused review leave the CR active and recoverable.
- Add a regression check covering an attempted premature close.

## Acceptance Gates

- CODE review must pass on the exact candidate snapshot.
- TEST_ARTIFACT review must cover the closure evidence.
- DOCUMENTATION review must pass while the CR remains active.
- The post-review close operation must be checked for tracker/preflight
  consistency before publication.
- No local build or test may be run.

## Scope Note

This is an orchestration and state-ordering correction. It does not alter
product behavior or the locked harnesses.

## Implementation Record

- Added the handle-recovery and closure-ordering invariant to `WORKFLOW.md`.
- The wrapper remains external infrastructure; project recovery uses the
  durable reviewer lock/state and never restarts an unobserved command.
