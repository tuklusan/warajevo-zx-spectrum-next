# CR-0064 Migration Preflight

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Decode primary opcode `EB` as `EX DE,HL`, exchanging both complete register
  pairs while preserving A, BC, IX, IY, SP, flags, interrupt state, MEMPTR,
  and all memory and I/O state.
- Retain the single primary opcode fetch, advance PC and R once, and account
  for exactly 4 T-states with no internal, memory, or I/O cycle beyond the
  opcode fetch.
- Decode `DD EB` and `FD EB` as the same DE/HL exchange. The prefixes do not
  redirect either pair; they retain the exchange semantics and add only their
  documented prefix fetch timing and R progression.
- Remove exactly `eb` from the pinned unresolved baseline. Add deterministic
  primary and DD/FD regression coverage, including flags, unrelated registers,
  fetch trace, PC/R, timing, and no-write/no-I/O behavior.

## Upstream Discovery

The upstream primary dispatch table maps `EB` to `EXDEHL`; both DD and FD
dispatch tables map `EB` to that same routine rather than an IX/IY variant.
`EXDEHL` executes `RF 4`, exchanges DE and HL, and returns. The surrounding
`E8` through `EF` entries independently dispatch conditional return, branch,
stack exchange, call, push, XOR, and restart behavior.

## Disposition

| Functional aspect | Disposition | Evidence |
| --- | --- | --- |
| Primary EX DE,HL | IMPLEMENT_NOW | Fuse `eb`, upstream `EXDEHL` |
| DD/FD retained forms | IMPLEMENT_NOW | upstream DD/FD `EB` dispatch entries |
| Flags, MEMPTR, memory, and I/O preservation | IMPLEMENT_NOW | upstream exchange-only routine and bus regression coverage |
| E8-EF neighboring operations and POP IX/IY | FOLLOW_ON_CR | separate baseline entries and opcode families |

## Zero-Gap Exit Scan

Re-scan upstream primary, DD, and FD `EB` entries and `EXDEHL`, plus the full
`E8` through `EF` dispatch family. Close only when primary and prefixed forms
pass remotely, `eb` alone is removed from the baseline, the exchange leaves no
extra bus activity, and no undispositioned EX DE,HL behavior remains.
