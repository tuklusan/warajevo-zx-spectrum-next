## Change Request
CR-0296: Shared snapshot state editor routing

Status: APPROVED_FOR_IMPLEMENTATION
Priority: high

## Functional Inventory
- Provide an app-facing snapshot state editor boundary.
- Route CPU register edits through the shared debugger mutation API.
- Route memory edits through the shared debugger mutation API.
- Expose the shared explicit access-mode and register-undo controls.
- Preserve core result codes and reject unbound or invalid calls without mutation.
- Store no duplicate register, memory, or undo state in the UI adapter.

## Upstream And Architecture Discovery
The UI architecture section 13.3 requires shared debugger/state-editor machinery and
forbids a second editor implementation. Task 292 is the corresponding backlog item.
The existing debugger is the canonical machine-state authority and already owns access
mode, mutation, and register undo semantics.

## Upstream Discovery
The preserved legacy sources expose direct processor and memory editing behavior, but
not a modern host UI editor boundary. The migration therefore preserves the behavior
through the existing canonical debugger APIs rather than copying legacy editor state.
No additional upstream behavior remains undispositioned for this adapter.

## Disposition
Implement a stateless app adapter containing only a pointer to the live machine. Every
operation delegates directly to the core debugger. Access mode remains an explicit
caller decision; the adapter never silently enables mutation.

## Zero-Gap Exit Scan
The implementation must cover binding, invalid/unbound calls, read-only rejection,
explicit mutation, CPU undo, memory writes, and unbinding. The test target must exercise
each path while using the shared core result codes. A final scan must confirm no private
editor state or duplicate mutation logic was introduced.
