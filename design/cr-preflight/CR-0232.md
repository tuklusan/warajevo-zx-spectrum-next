# CR-0232 Deterministic Original ZX Net State Machine

Status: CLOSED

## Functional Inventory

- Implement the six preserved states: `CLAIM`, `IDLE`, `BUSY`, `FREE`,
  `COLLREAD`, and `COLLWRITE`.
- Implement `$F7` input/output behavior for claim, acceptance, repeated
  BUSY/FREE counts, and collision read/write collection.
- Make WAIT-latch events start or advance collection at canonical master ticks.
- Preserve the reference claim byte, block identifiers, bit counts, sequence
  positions, network delay, and BUSY/FREE lengths.
- Flush completed writes through a bounded 256-byte network-device boundary.
- Reject malformed or overlong loopback input without partial state mutation.
- Keep all network state deterministic and serializable, independent of host
  sockets, wall-clock time, or the future multi-process transport.

## Upstream Discovery

The complete scoped `MDRIVE.ASM` network tables, constants, state handlers,
claim/acceptance paths, collision collection paths, WAIT handling, bounded
buffer operations, and `SPECSIM.ASM` Interface-1 `$F7` dispatch were read.
The preserved implementation uses states `CLAIM` through `COLLWRITE`,
`BUSYLEN=5`, `FREELEN=5`, `NETDELAY=30`, and a shared host `.NET` file. The
modern core will preserve the observable state machine while replacing that
file access with a bounded loopback/device callback outside the core.

## Disposition

- Deterministic six-state core and `$F7` behavior: `IMPLEMENT_NOW`.
- Single-process loopback/device boundary: `IMPLEMENT_NOW`.
- Shared-file or cross-process ZX Net transport: defer to the later host
  orchestrator transport work.
- RS232 behavior: remain the separately specified unsupported boundary.

handling, serialization, and loopback timing are all covered without host-time
