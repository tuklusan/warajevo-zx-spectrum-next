# CR-0080 Migration Preflight

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Model the 48K Spectrum keyboard as eight active-low five-key rows.
- Accept only normalized row/key physical transitions in the core; do not add
  host key codes, source identity, or host timing to the machine API.
- Read every selected row through the existing ULA port-FE path, AND-combining
  selected rows and returning inactive bits high when no key is pressed.
- Preserve partial port decoding, bus observer ordering, fixture-mode behavior,
  and deterministic state across initialization and reset.
- Cover individual keys, no selected rows, and simultaneous multiple-row scans.

## Upstream Discovery

The preserved `SPECSIM.ASM` keyboard routine reads row-selection address bits,
starts from an active-low inactive value, and AND-combines each selected row.
The architecture independently freezes the same physical matrix contract in
Sections 22.2-22.4 and reserves host mapping/source ownership for Phase 5.
No preserved host-key identity or timing policy is migrated into the core.

## Zero-Gap Exit Scan

Re-scan machine initialization/reset, ULA port-FE reads, all bus request entry
points, keyboard state ownership, row-selection masks, input-provider fallback,
the explicit CPU fixture mode, and project-owned matrix tests. Close only when
the core implements the complete eight-row selection behavior and no host
identity enters the core API.

## Disposition

Add an initialized `0x1f` row array and a normalized physical key setter. Make
the ULA port-FE read return `0xbf` with selected active-low row bits ANDed into
the low five bits. Keep output latches, ghosting/electrical policy, host input
arbitration, timestamping, and Kempston separately scoped to their later CRs.

## Closure Evidence

Closure status: CANDIDATE
