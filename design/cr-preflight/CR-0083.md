# CR-0083 Preflight: Contention Architecture Isolation

Status: CLOSED

## Objective

Prove and enforce that Spectrum contention is applied by the bus/machine timing
layer rather than by individual CPU opcode implementations, while retaining
the cycle descriptors needed for exact operation timing.

## Functional Inventory

- Keep all contention address classification and delay tables outside CPU
  opcode execution functions.
- Ensure every memory and I/O bus operation reaches one common contention
  decision point.
- Preserve machine-model/profile selection at the timing boundary.
- Keep CPU code responsible only for operation sequence, nominal offsets, and
  register/memory semantics.
- Preserve exact effective master ticks, delay metadata, trace ordering, and
  invalid-request behavior after isolation.
- Add source-level and runtime tests that detect bypasses or duplicated tables.

## Upstream Completeness Gate

Compare the architecture’s contention boundary and the preserved reference’s
operation timing paths. Authorities are sections 13, 14, 36, 44, and 51 of
`design/warajevo-zx-spectrum-next-architecture.md`, task 069 in
`design/wzsn-architectures-1-2-developer-tasks.md`, the frozen tables in
`design/machine-timing-evidence.md`, and the preserved source under
`reference/original-warajevo/source`.

## Upstream Discovery

Scan every CPU bus call, machine bus dispatch path, profile definition, trace
record, and reference timing path. Record whether each timing decision is a
CPU operation descriptor, a bus policy, or a deferred model-specific rule.

Discovery result: all CPU timing decisions are nominal bus-cycle descriptors;
all 48K contention constants and calculations are in `src/core/wz_machine.c`,
and the single dispatch point is `wz_machine_bus_request` in
`src/core/wz_bus.c`.

## Disposition

Keep the 48K contention policy in the shared machine/bus boundary and verify
that CPU opcode files contain no Spectrum-specific contention logic. Defer
128K paging-specific contention and later ULA fetch arbitration to their named
CRs. Do not duplicate the policy in test-only production paths.

## Zero-Gap Exit Scan

Repeat a line-by-line scan of all CPU bus call sites, contention helpers,
profiles, trace records, tests, and upstream timing paths. Classify every
contention decision as shared-layer implementation, explicit later-CR
deferral, or proven inapplicable. No unclassified decision permits closure.

Exit scan disposition: no CPU opcode-level contention table or delay
calculation exists. Shared-layer implementation is complete; 128K paging and
later ULA-fetch arbitration are explicitly deferred to their named CRs.

## Verification Plan

- Static source scan proves CPU code has no contention table or direct delay
  calculation.
- Runtime vectors prove memory and I/O requests use the same shared decision
  point and retain exact delay/effective-tick metadata.
- Linux remote CMake, CTest, complete pinned Fuse suite, and evidence summary.
- Hosted platform smoke across all configured targets.
- CODE and DOCUMENTATION advisory reviews against this preflight and sources.
