## Change Request
CR-0327: Implement Diagnostics entry point for project-owned diagnostic surfaces

Status: APPROVED_FOR_IMPLEMENTATION
Priority: medium

## Functional Inventory
- Provide a first-class `Tools > Diagnostics...` entry point for project-owned
  diagnostic surfaces without duplicating emulated hardware behavior.
- Present canonical trace-file status, bounded circular-log metadata, recent
  event counts, diagnostic-block availability, raster diagnostics, and
  forwarding state through host/UI state.
- Reuse `wz_trace_file`, `wz_diagnostics_router`, `wz_diagnostic_block`, and
  existing core diagnostic APIs; never own a second machine or trace producer.
- Keep diagnostics read-only with respect to canonical machine state and make
  unavailable or failed surfaces carry explicit reasons.
- Preserve local bounded trace evidence and the opt-in UDP syslog policy;
  diagnostics must not expose credentials or arbitrary host paths.
- Register the entry point through the shared command registry so GUI, Telnet,
  and automated projections use the same semantic identity and availability.

## Disposition
`IMPLEMENT_NOW`: add a project-owned Diagnostics presentation model and command
surface over existing diagnostic APIs. Do not modify frozen harnesses or wrappers.
