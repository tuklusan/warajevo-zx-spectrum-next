# CR-0143 Preflight: Timestamped Beeper Transitions

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Record Spectrum beeper output transitions from port-FE writes at canonical
master ticks, retaining MIC output separately for later tape/audio consumers.

## Functional Inventory

- Decode the upstream 48K port-FE speaker and MIC bits without host assumptions.
- Record only beeper level changes, preserving their exact master-tick order.
- Retain current beeper level and most recent transition tick.
- Retain MIC level independently even when a write does not change the beeper.
- Bound event storage deterministically and expose a read-only event query.
- Keep host audio delivery, sample rate, and callbacks outside the core.
- Preserve canonical machine timing and bus ordering.

## Upstream Completeness Gate

Inspect the preserved upstream port-FE speaker/MIC handling and compare bit
meaning, transition semantics, and timing ownership. Retain the documented
speaker bit-3/MIC bit-4 distinction and record any host-only legacy behavior as
non-canonical.

## Upstream Discovery

The preserved assembly source identifies port-FE bit 3 as the speaker and bit 4
as the MIC output. Its sound options are host delivery policy; the migrated
core must retain the timed ULA output distinction before any later mixer.

## Disposition

Add a bounded core beeper event stream and feed it directly from the existing
timestamped ULA port-FE write path. PCM sampling and Sokol delivery remain
separate Phase-6 tasks.

## Zero-Gap Exit Scan

Close only when bit decoding, same-level writes, MIC separation, tick ordering,
capacity behavior, core isolation, and upstream timing comparison have no gap.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
