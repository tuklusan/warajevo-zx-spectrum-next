## Change Request
CR-0306: Complete File/Snapshot/Screenshot acceptance subset

Status: APPROVED_FOR_IMPLEMENTATION
Priority: medium

## Functional Inventory
- Route universal Open / Run selections to tape, snapshot, Microdrive, or conversion subsystems.
- Reject unsupported and invalid Open / Run selections without a fallback route.
- Load and commit a valid snapshot atomically.
- Reject an invalid snapshot while preserving the previously committed snapshot.
- Preserve snapshot save destination state across cancellation and bounded-output failure.
- Encode a screenshot only from the supplied Spectrum raster.
- Preserve raster samples and workflow destination state on cancellation and failure.
- Report the required PNG size for bounded output and succeed with sufficient output capacity.
- Keep the acceptance test host- and GUI-toolkit-independent.

## Upstream Discovery
UI Sections 8.1-8.4, 13, 34, 47, and 48 define the universal Open / Run,
snapshot, and screenshot acceptance behavior. Backlog task 300 is the derived
acceptance subset. The preserved upstream source was searched for the legacy
file-routing and snapshot/screenshot behavior; no portable aggregate acceptance
test exists there. Existing project tests cover the individual contracts, so
this CR adds the missing cross-subsystem acceptance proof without duplicating
runtime behavior. No upstream behavior remains undispositioned.

## Disposition
`IMPLEMENT_NOW`: add one compact acceptance regression that exercises the
already-implemented subsystem contracts together and registers it with CTest.
