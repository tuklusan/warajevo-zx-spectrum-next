# CR-0222 Harden Review Adjudication Against Compliance False Positives

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Require an adjudicated `CONFIRMED` review finding to prove an actual
  current-scope requirement violation, not merely repeat that compliant code
  exists.
- Require an adjudicated `REJECTED` or `NON_BLOCKING` result when the supplied
  evidence proves the candidate's requirement is satisfied.
- Preserve unresolved and human-decision outcomes when the evidence cannot
  distinguish compliance from a defect.
- Keep exact requirement, location, evidence, severity, and no-parallel
  review contracts unchanged.
- Add deterministic regression tests for compliant-code candidates, real
  defects, unresolved evidence, and malformed adjudication output.

## Upstream Completeness Gate

Review the current discovery, falsification, adjudication, blocker creation,
and verdict paths in `tools/reviewer/review_gate.py`, plus the review protocol
tests and `design/review-gate.md`. Compare the required evidence semantics with
the project CR protocol and prior successful review receipts. Confirm that a
model assertion of “the guard is present” cannot become a blocker whose own
evidence says the guard is present, while preserving genuine defect findings.

## Upstream Discovery

The CR-0221 code review returned a failure containing repeated findings whose
causal paths and negative checks explicitly described satisfied requirements.
The current gate validates field shape and severity but does not require the
adjudication proof to demonstrate a violation. This permits a compliance claim
to be promoted directly into `confirmed_findings`.

## Disposition

- Add an explicit adjudication outcome field that distinguishes defect proof
  from compliance proof: `IMPLEMENT_NOW`.
- Enforce the distinction in schema validation and blocker construction:
  `IMPLEMENT_NOW`.
- Preserve all unrelated review transport, lock, retry, and scope behavior:
  `IMPLEMENT_NOW`.
- Re-run CR-0221 only after this gate hardening passes its own review and
  validation gates: `DEFERRED`.

## Zero-Gap Exit Scan

Rescan discovery candidates, falsification decisions, dispute adjudication,
confirmed-finding construction, compact receipts, telemetry, and all protocol
tests. Verify that compliant evidence is rejected or marked non-blocking,
actual violation evidence can still become a blocker, ambiguity remains
unresolved or human-directed, and no review lock or deadline behavior changes.

## Evidence and Exit Gates

- Exact-SHA CODE, DOCUMENTATION, and independent bootstrap reviews pass with
  zero confirmed findings.
- Static repository gates and `git diff --check` pass locally; no local build
  or test is performed.
- Remote Linux, Windows 10/11, Intel Mac, and hosted matrix validation pass.
- A second upstream zero-gap scan is recorded before closure.
