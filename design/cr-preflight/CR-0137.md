# CR-0137 Preflight: Monotonic Host-Clock Pacing

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Implement host-side pacing against a monotonic clock with sleep/yield behavior,
while ensuring host time never enters canonical machine state or changes event
ordering.

## Functional Inventory

- Define a monotonic clock and injectable clock/sleep interfaces.
- Calculate pacing deadlines from emulated progress and selected speed.
- Sleep or yield only when the host is ahead of the emulated deadline.
- Handle clock regressions and arithmetic overflow deterministically.
- Keep pacing outside the core and avoid wall-clock serialization/hash effects.
- Provide tests for ahead, behind, equal, regression, and long-duration cases.

## Upstream Completeness Gate

Inspect preserved upstream timer, delay, fast-forward, and run-loop behavior.
Compare host pacing responsibilities with the architecture and current speed
policy; record retained timing intent and explicit platform-specific decisions.

## Upstream Discovery

The architecture explicitly separates host pacing from emulated master ticks.
CR-0136 supplies only policy values; this CR must add injectable pacing math and
clock handling without making the core query an operating-system clock.

## Disposition

Add a host-only pacing API with deterministic clock/sleep seams. Do not modify
machine timing, scheduler ordering, canonical state, or GUI toolkit behavior.

## Zero-Gap Exit Scan

Close only when monotonic clock use, deadline math, sleep/yield decisions,
regression/overflow behavior, speed interaction, and core isolation are tested
with no unresolved upstream gap.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
