# CR-0135 Preflight: Host-to-Kempston Mapping

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Map normalized host controls to Kempston controls at the host boundary without
changing the deterministic core joystick API or synthesizing keyboard presses.

## Functional Inventory

- Define independent host bindings for RIGHT, LEFT, DOWN, UP, and FIRE.
- Support remapping each control without host identity entering core state.
- Preserve source ownership and release behavior for mapped controls.
- Define unbound, duplicate, invalid, and simultaneous binding behavior.
- Keep mapping deterministic and independent of host wall clock/UI types.
- Provide tests for defaults, remapping, simultaneous controls, and release.

## Upstream Completeness Gate

Inspect preserved upstream joystick configuration, cursor-key conversion,
mouse/analog alternatives, release behavior, and input tables. Compare every
relevant mapping and precedence rule with the architecture and current arbiter
and Kempston APIs; record retained behavior and explicit exclusions.

## Upstream Discovery

The preserved conversion table maps cursor controls to the frozen Kempston bits,
while the core now accepts only normalized five-control state. This CR owns the
host mapping layer and must not add host key codes or mapping tables to core.

## Disposition

Add a host-boundary mapping API with deterministic bindings and tests. Do not
change Kempston port decode, machine state, keyboard matrix behavior, or pacing.

## Zero-Gap Exit Scan

Close only when default/remapped bindings, duplicates, unbound controls,
simultaneous presses, releases, source isolation, and core API invariance are
evidenced with no unresolved upstream gap.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
