Status: CLOSED
Priority: medium

## Functional Inventory

- Provide one shared Display settings model for the View shortcut and Settings
  surface.
- Keep integer scaling and crop presentation host-owned.
- Keep fullscreen host-owned and independent from canonical machine state,
  timing, and raster truth.
- Reject invalid settings without mutating the existing valid settings.
- Preserve keyboard-operable, cancel-safe settings semantics at the UI boundary.

- UI Architecture Sections 18.3 and 23.1 define the shared host-only Display
  settings contract; Section 7.1 defines `view.display_settings` and
  `settings.display` as the stable semantic surfaces.
- The preserved upstream source was inspected for display behavior. It contains
  historical display routines and host presentation concepts, but no modern
  cross-front-end settings registry to port.
- CR-0281 already implemented and validated the shared scale/crop settings
  model in `src/app/wz_host_scaling.*`; CR-0279 already implemented and
  validated the fullscreen host-presentation boundary in
  `src/app/wz_host_presentation.*`.
- The existing tests cover defaults, invalid scale, accepted scale, crop, and
  fullscreen transitions. No duplicate settings store or core change is
  warranted for task 331.
- No harness, wrapper, deterministic core, transport, or third-party artifact
  changes are permitted or required.
