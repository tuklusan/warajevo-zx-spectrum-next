# CR-0063 Review-Evidence Preflight

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Add a deterministic, harness-owned command that accepts only explicit pulled
  remote-run directories, a CR identity, a reviewed build identity, and named
  required Fuse case identifiers.
- Read each run's session record and complete Fuse manifest; reject missing,
  malformed, nonzero, mismatched, incomplete, or duplicate machine evidence.
- Compare unresolved cases exactly with the tracked unresolved baseline and
  report per-machine totals, passed cases, known unresolved cases, unexpected
  failures, and silent skips without copying the full case manifest.
- Produce a private JSON summary carrying the project notice, CR/build binding,
  source artifact hashes, required-case results, baseline-comparison result,
  and per-machine evidence. The generated summary is review input only and
  never replaces raw manifests or authorizes execution by itself.
- Preserve all emulator execution, remote synchronization, reviewer verdict,
  receipt, and hosted-validation behavior. A malformed source or ambiguity
  must fail closed rather than emit a plausible partial summary.

## Upstream Discovery

This CR changes only this project's review-evidence packaging. The preserved
Warajevo Z80 implementation has no equivalent host-side harness behavior, so
there is no upstream emulator functionality to migrate or modify. The upstream
comparison boundary is therefore explicit: no CPU opcode, timing, memory, I/O,
or device behavior may change as a consequence of this CR.

## Disposition

| Functional aspect | Disposition | Evidence |
| --- | --- | --- |
| Deterministic compact evidence producer | IMPLEMENT_NOW | CR-0062 evidence failure analysis and review-gate artifact rules |
| Provenance, exact baseline comparison, and fail-closed checks | IMPLEMENT_NOW | review-gate verdict and artifact rules |
| Raw manifest retention | PRESERVE | remote harness and private-artifact workflow |
| Emulator behavior and upstream CPU semantics | OUT_OF_SCOPE_NO_CHANGE | upstream comparison boundary |

## Zero-Gap Exit Scan

Re-scan every summary field against the source manifest and session contract,
including absent, duplicate, malformed, failed, mismatched-build, unexpected,
and silent-skip cases. Re-scan the upstream comparison boundary to verify that
the diff contains no emulator source, opcode baseline, or runtime behavior
change. Close only after deterministic tests, required remote validation, the
artifact review, and hosted validation prove the producer is bounded,
provenance-bound, and fail-closed.
