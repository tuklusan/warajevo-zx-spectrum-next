# CR-0066 Migration Preflight

Status: APPROVED_FOR_IMPLEMENTATION

Closure status: CLOSED

## Functional Inventory

- Establish whether primary opcode `FE` (`CP n`) remains a true Fuse
  discrepancy after the shared CP operand X/Y flag correction.
- Confirm A is preserved; the immediate byte is fetched exactly once; PC and R
  advance correctly; timing is seven T-states; flags follow subtraction with
  X/Y from the immediate operand; and MEMPTR, memory, and I/O remain unchanged.
- Confirm DD/FD retain `CP n` without selecting IX/IY and add only prefix
  fetch timing and R progression.
- Remove only `fe` from the pinned unresolved baseline if clean remote
  validation proves it passes. Otherwise retain it and create a behavior CR
  from the failed evidence.

## Upstream Discovery

The upstream primary, DD, and FD dispatch tables all map `FE` to `CP_N`.
`CP_N` executes `RF 7`, compares A with the immediate byte through the shared
subtraction flag path, advances PC by one, and returns. The current portable
implementation routes `FE` through the shared ALU CP path, which preserves A
and derives X/Y from the operand. The surrounding `F0` through `FF` family is
independently implemented or tracked.

## Disposition

| Functional aspect | Disposition | Evidence |
| --- | --- | --- |
| Primary CP immediate execution | VERIFY_NOW | upstream `CP_N`, current shared ALU path |
| DD/FD retained forms | VERIFY_NOW | upstream DD/FD dispatch tables |
| Baseline `fe` entry | REMOVE_ONLY_IF_PROVEN | isolated remote complete-Fuse evidence |
| Neighboring F0-FF operations | FOLLOW_ON_CR | separate families and baseline entries |

## Zero-Gap Exit Scan

Re-scan `CP_N`, the primary/DD/FD `FE` table entries, and the full `F0`
through `FF` dispatch family. Close only with remote evidence for the primary
and prefixed forms and either a proven baseline removal or a newly tracked
specific behavior gap.
