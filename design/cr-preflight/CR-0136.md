# CR-0136 Preflight: Runtime Speed Policy

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Define host pacing policy values 25/50/100/200/400/800/Unlimited without
overclocking or altering deterministic machine timing.

## Functional Inventory

- Represent all seven speed values explicitly.
- Define validation and default 100 percent behavior.
- Keep speed policy outside canonical machine state.
- Ensure master-tick and hardware timing are unchanged by policy selection.
- Define Unlimited as no artificial sleep, not altered emulation rate.
- Provide tests for values, invalid inputs, and unchanged core timing.

## Upstream Completeness Gate

Inspect preserved upstream speed controls, timer behavior, pause/fast-forward
paths, and user-visible values. Compare every relevant behavior with the
architecture's host-pacing contract and current runner boundary; record retained
behavior and explicit modernization decisions.

## Upstream Discovery

The architecture separates emulated master time from host pacing. This CR owns
the policy value model only; monotonic host-clock pacing and runtime transitions
remain subsequent tasks.

## Disposition

Add a host-only speed policy API with exact values and deterministic validation.
Do not modify the core scheduler, master tick, audio timing, or GUI toolkit.

## Zero-Gap Exit Scan

Close only when every speed value, default, invalid input, Unlimited semantics,
and core-timing invariance are evidenced without unresolved upstream gaps.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
