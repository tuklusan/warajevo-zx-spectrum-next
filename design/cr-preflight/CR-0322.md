## Change Request
CR-0322: Implement Microdrive logical-file workflows

Status: CLOSED
Priority: medium

## Functional Inventory
- Provide separate logical-file operations for delete, rename, hide, unhide,
  and copy to another mounted cartridge.
- Use stable lowercase dotted command IDs under the shared Microdrive Manager
  registry; do not create private front-end implementations.
- Acquire source/destination drives, selected file, and new name outside the
  semantic handler through the manager's parameter path.
- Preserve hidden-file state, logical names, source/destination validation,
  write protection, dirty state, and cross-process ownership through shared
  media services.
- Require explicit local confirmation for delete, rename, hide, unhide, and
  copy when they mutate media; deny those operations under the initial remote
  unauthenticated policy.
- Return deterministic success, cancel, unavailable, and failure results with
  stable reasons and no partial mutation on rejected operations.
- Keep raw-sector editing and verify/repair out of this CR.

## Upstream Discovery
The retained authority is `reference/original-warajevo/source/src/environment/MICROD.PAS`.
Its `fildelete`, `filrename`, `filhide`, `filunhide`, and `filcopy` procedures
are distinct operations over the selected cartridge directory; the dialog
workflow and validation paths must be retained rather than replaced by a
single generic mutation. UI architecture Sections 15.3, 24, 39, 45, 47, 48,
and 51 define the manager boundary, confirmation, remote permissions,
availability, accessibility, and evidence requirements. Developer task 317 is
the implementation scope.

## Disposition
`IMPLEMENT_NOW`: add a registry-backed logical-file workflow contract and
regression coverage, delegating actual MDR directory mutation to shared media
services. No duplicate parser or deterministic media backend belongs here.
