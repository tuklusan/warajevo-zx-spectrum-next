# CR-0054 Migration Preflight

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Keep complete pinned-Fuse corpus accounting on every approved remote platform.
- Allow an incremental migration CR to report unresolved cases outside its
  declared scope without converting an otherwise-valid platform run into a
  false failure.
- Remain fail-closed for silent skips, malformed or incomplete manifests,
  mismatched pinned revisions, and failures in the CR's declared scope.
- Produce equivalent remote-harness exit semantics on Linux and Windows.
- Preserve private acquisition of the Fuse source and all existing artifact
  containment rules.

## Upstream Discovery

This is project-local validation infrastructure with no legacy emulator
equivalent. Inspect `tools/harness/run_fuse_ed_platform.py`,
`tools/harness/run_fuse_ed_corpus.py`, and
`tools/harness/invoke_remote_harness.py`, then compare Linux
CR0053-FLAGS-LINUX-R4 with Windows CR0053-FLAGS-WIN10-R1 and
CR0053-FLAGS-WIN11-R1 evidence before implementation. All three manifests
contain the same 174 unresolved names at the pinned revision. Linux did not
propagate the corpus-process result through its remote shell, while Windows
did; neither difference may determine conformance. The implementation uses a
tracked pinned baseline to classify those exact names, with every other failed
name treated as an unexpected fatal regression.

## Disposition

| Functional aspect | Disposition | Evidence |
| --- | --- | --- |
| Complete-corpus accounting | IMPLEMENT_NOW | CR-0051 contract and CR-0053 manifests |
| Incremental-scope failure policy | IMPLEMENT_NOW | Existing migration CR workflow |
| Silent-skip and manifest-integrity failures | RETAINED_FAIL_CLOSED | Fuse-suite contract |
| Legacy emulator behavior | NOT_APPLICABLE | Project-local harness |

## Zero-Gap Exit Scan

Re-scan every platform-specific remote command path and all invoked corpus
selections. The CR may close only after Linux, Windows 10, and Windows 11
produce identical result classifications for the same pinned corpus and an
untracked failed vector remains a failing harness result. The second scan must
also confirm the baseline contains no duplicate case name and names the same
pinned Fuse revision as the corpus runner.

## Closure Evidence

The second scan confirmed that all three platform paths pass the baseline to
the same corpus runner. CR0054-HARNESS-LINUX-R2,
CR0054-HARNESS-WIN10-R2, and CR0054-HARNESS-WIN11-R2 each reported 1,182
passed, 174 known unresolved, zero unexpected failures, and zero silent skips.
All focused ED, indexed-CB, CB rotate/shift, stack/subroutine, branch,
increment/decrement, and HALT selections remained fully passing. The pinned
baseline contains 174 unique names and the pinned Fuse commit.
