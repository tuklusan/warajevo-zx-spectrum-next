# CR-0167 Preflight: TZX Timing and Control Execution

Status: CLOSED

## Objective

Execute supported TZX blocks from the CR-0166 parser on canonical master time,
preserving deterministic EAR transitions, pauses, signal levels, and bounded
control flow without changing standard or native TAP behavior.

## Functional Inventory

- Convert standard, turbo, pure-tone, pulse-sequence, pure-data, direct-
  recording, CSW, and generalized-data blocks into canonical tape edges using
  declared timing fields and byte/bit ordering.
- Apply pause and stop semantics, including the frozen 48K-only stop condition
  and explicit signal-level transitions.
- Execute jump, loop, call/return, and select control flow with validated
  targets, bounded iteration, deterministic ordering, and non-terminating-path
  rejection before tape state publication.
- Validate every Select option and follow its first option in the core when no
  host/UI choice is supplied; later UI selection must enter through an explicit
  host boundary rather than altering canonical core state implicitly.
- Keep ignored metadata blocks out of machine input while preserving traversal.
- Ensure identical TZX input yields identical tape segments and state hashes
  across hosts and runtime-speed policies; wall-clock pacing remains external.
- Add deterministic timing, control-flow, pause, signal-level, malformed-path,
  and no-partial-publication regression coverage.

## Upstream Discovery

Before implementation, rescan preserved upstream tape execution paths and the
architecture/media matrix for each supported block's timing and control
semantics. Document divergences from the frozen contract rather than inheriting
ambiguous behavior silently.

## Disposition

Implement only TZX-to-canonical-tape execution and control-flow semantics.
Do not alter TZX parsing/classification, TAP formats, WAV decoding, instant
loading, trap detection, or host file-system behavior.

## Zero-Gap Exit Scan

Before closure, repeat the upstream and matrix scan over every supported timing
field, edge transition, pause/stop rule, control path, and termination case.
Close only when each behavior is implemented or assigned to a later ordered
task, with serialized reviews, remote validation, the full hosted matrix,
clean repository gates, and published evidence.

- Serialized pre-development and final CODE/DOCUMENTATION reviews.
