# CR-0134 Preflight: Deterministic Kempston Core State

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Integrate the deterministic Kempston state into machine I/O so machine-code
reads observe the frozen five-bit joystick value independently of keyboard state.

## Functional Inventory

- Add explicit Kempston state ownership to the machine model.
- Route the exact `0x1F` read to the Kempston device.
- Preserve active-high direction/fire bits and legal combinations.
- Keep unrelated ports and keyboard ULA reads on their existing paths.
- Ensure state is deterministic, reset-safe, and excluded from host/UI state.
- Provide direct machine-code port-read and reset regression tests.

## Upstream Completeness Gate

Inspect preserved Kempston read dispatch, reset initialization, state lifetime,
and port decode behavior. Compare every relevant path with the frozen CR-0133
contract and current machine bus/ULA decode; record all retained or intentionally
excluded behavior before implementation.

## Upstream Discovery

The standalone device already freezes port `0x1F` and the five active-high bits.
This CR must connect it to the machine I/O path without synthesizing keyboard
presses or allowing host device identity into core state.

## Disposition

Extend machine state and I/O read dispatch with the standalone Kempston device.
Do not implement host mappings, timestamps, networking, or additional joystick
protocols here.

## Zero-Gap Exit Scan

Close only when reset, all bit combinations, exact port selection, unrelated
ports, keyboard separation, state serialization/hash policy, and upstream
provenance are evidenced.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
