# CR-0124 Preflight: Host Backend Upload Abstraction

Status: APPROVED_FOR_IMPLEMENTATION

## Objective

Abstract host pixel-upload and backend details so D3D, Metal, and Linux backend
selection cannot affect canonical raster generation.

## Functional Inventory

- Define a backend-neutral host upload interface.
- Keep canonical raster buffers owned by the deterministic core.
- Keep Sokol and platform handles in host implementation only.
- Preserve identical source samples across backend paths.
- Define initialization, update, failure, and destruction behavior.

## Upstream Completeness Gate

Compare the architecture backend boundary, existing canonical raster APIs,
Sokol pin, platform decisions, and preserved upstream behavior. Record every
ownership and format assumption before refactoring host upload code.

## Upstream Discovery

CR-0120 freezes X11, CR-0121 establishes the host shell, and CR-0123 adds the
initial Sokol raster upload wrapper. This CR isolates backend details without
changing raster contents.

## Disposition

Refactor the host upload path behind a narrow interface. Do not add scaling,
shaders, CRT effects, or core dependencies.

## Zero-Gap Exit Scan

Close only when the interface is backend-neutral, core isolation is preserved,
and source-raster equivalence is evidenced on remote and hosted paths.

## Verification Plan

- Local activity: static gates and source inspection only; no local build/test.
- CODE and DOCUMENTATION advisory reviews against this preflight.
- Remote Linux and Windows smoke validation.
- Hosted platform matrix validation.
- Final upstream zero-gap scan and publication evidence.
