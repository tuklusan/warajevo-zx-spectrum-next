# CR-0058 Migration Preflight

Status: APPROVED_FOR_IMPLEMENTATION

Closure status: CLOSED

Closure correction: corpus case `d3_4` confirms that `MEMPTR` is formed from
`A` and the incremented low immediate byte; the low-byte increment wraps
without carrying into `A`. This is IMPLEMENT_NOW and is guarded by the
`0xFF` immediate regression.

Validation infrastructure correction: Windows SSH sessions do not inherit a
Visual Studio developer environment. The shared remote harness must load the
installed x64 environment before CMake, build, and test processes so their
library and include search paths are deterministic. This is IMPLEMENT_NOW and
does not alter emulator behavior.

## Functional Inventory

- Decode documented primary opcode `D3` as OUT (n),A.
- Read the immediate low port byte, form port address A:n, and write A through
  the existing I/O-write bus contract.
- Preserve flags, increment PC and R correctly, set MEMPTR to port+1, and
  preserve the 11 T-state instruction timing.
- Cover d3 through d3_4 without implementing device-specific port effects.

## Upstream Discovery

`upstream/main` dispatches `D3` to `OUTNA`, which preserves the original BC,
uses A as the port high byte and output value, consumes the immediate port
byte, performs the port write, and advances PC. Pinned Fuse expected traces
establish the 4T M1, 3T immediate read, and 4T I/O write sequence.

## Disposition

| Functional aspect | Disposition | Evidence |
| --- | --- | --- |
| Primary OUT (n),A CPU semantics | IMPLEMENT_NOW | d3 through d3_4 and OUTNA |
| I/O write observation | IMPLEMENT_NOW | existing WZ_BUS_IO_WRITE contract |
| ULA/Next device side effects | DEFERRED_TO_OWNER | architecture section 15.4 |
| IN (n),A and other primary I/O | RECHECK_ONLY | separate opcodes and backlog entries |

## Zero-Gap Exit Scan

Re-scan OUTNA and the surrounding `D0` through `DF` primary family. Close only
when all five cases pass remotely, their baseline entries are removed, and no
unexpected complete-corpus failure appears.
