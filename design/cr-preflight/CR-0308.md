## Change Request
CR-0308: Implement the Tape Eject quick action

Status: CLOSED
Priority: medium

## Functional Inventory
- Expose the stable `media.tape.eject` application workflow boundary.
- Report the canonical disabled reason when no tape is mounted.
- Unmount the currently mounted tape through the canonical machine API.
- Preserve the machine state when the action is unavailable or invalid.
- Keep the workflow independent of GUI toolkit and host file-dialog behavior.

## Upstream Discovery
UI Sections 11.2, 11.4, 20.1, 45, and 48 define Eject Tape as the universal
quick action, disabled with `no-tape-mounted` when no tape is present. Task 302
is the derived backlog item. The preserved upstream source was searched for
the legacy tape ejection behavior; the project core already owns validated
tape unmounting, but no project-owned application transaction boundary existed.
No upstream behavior remains undispositioned for this task.

## Disposition
`IMPLEMENT_NOW`: add an application-level Tape Eject workflow that reports
availability from the mounted state and delegates mutation to
`wz_machine_unmount_tape`.

## Zero-Gap Exit Scan
Confirm unavailable/no-tape behavior, successful unmount, repeated eject,
invalid workflow handling, unchanged state on every rejected path, and no GUI
or host-path dependency.
