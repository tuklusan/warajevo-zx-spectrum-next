## Change Request
CR-0323: Implement Microdrive advanced sector workflows

Status: APPROVED_FOR_IMPLEMENTATION
Priority: medium

## Functional Inventory
- Provide distinct manager surfaces for sector view, verify, repair, ordinary
  data editing, and explicitly dangerous whole-sector editing.
- Preserve sector index, 543-byte sector size, logical structure, checksums,
  formatted/unformatted state, and write-protection/dirty-state checks through
  shared MDR services.
- Require explicit confirmation for repair and all edits; mark whole-sector
  editing as dangerous in labels and metadata, with MEDIA_DESTRUCTIVE remote
  denial for all mutating operations.
- Keep read-only view and verification separate, with deterministic reports,
  stable unavailable reasons, and no partial mutation after an error or cancel.
- Acquire drive, sector, edit mode, and repair confirmation outside semantic
  handlers; preserve keyboard/focus accessibility and result schemas.

## Upstream Discovery
The retained authority is `reference/original-warajevo/source/src/environment/MICROD.PAS`.
Its `view`, `verify`, and `edit` procedures expose sector viewing, validation
and optional adjustment, ordinary data editing, and whole-sector editing.
The source uses 543-byte sectors and explicit confirmation before adjustment or
write-back. UI architecture Sections 15.4, 24, 39, 45, 47, 48, and 51 define
the manager boundary, dangerous-operation distinction, permissions,
availability, accessibility, and evidence requirements. Developer task 318 is
the implementation scope.

## Disposition
`IMPLEMENT_NOW`: add registry-backed advanced-sector workflow metadata and
regression coverage, delegating validation and mutation to shared MDR services.
