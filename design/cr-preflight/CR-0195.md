# CR-0195 Verify 128K Paging-Port Decode and Lock Semantics

Status: APPROVED_FOR_IMPLEMENTATION

## Functional Inventory

- Accept base 128K paging writes for every address whose A15 and A1 bits are clear.
- Reject writes with A15 or A1 set without changing the paging latch.
- Preserve write-only behavior: I/O reads must not modify or expose the paging latch.
- Preserve the lock bit after it is set, including through accepted alias writes.
- Preserve reset initialization of the latch and lock state.
- Add deterministic headless regression coverage for all cases.

## Upstream Completeness Gate

Compare every base 128K paging decode and lock behavior in the preserved upstream
machine and snapshot paths with the frozen 128K evidence and current bus boundary.
Defer +2A/+3 decode, timing, and ULA contention to their explicitly ordered tasks.

## Upstream Discovery

The preserved 128K snapshot path records the last `7ffd` write and the machine
profile uses the base 128K page model. The hardware/reference decode is the partial
port selected by A15=0 and A1=0; bit 5 disables future writes until reset.

## Disposition

- Alias acceptance and rejected-address behavior: `IMPLEMENT_NOW` as regression gates.
- Read non-interference and lock persistence: `IMPLEMENT_NOW` as regression gates.
- +2A/+3 special decode and timing: `DEFERRED` to later scoped tasks.

## Zero-Gap Exit Scan

Before closure, rescan the upstream paging/snapshot paths, bus implementation, latch
API, and all new tests. Confirm no base-profile decode or lock behavior is omitted and
that no out-of-profile variant has been silently introduced.

## Evidence and Exit Gates

- Exact-SHA CODE review and independent bootstrap review pass with zero findings.
- Static repository gates and `git diff --check` locally; no local build or test.
- Remote Linux sanitizer, Windows 10/11, Intel Mac, and hosted matrix validation pass.
- A second upstream zero-gap scan is recorded before closure.
