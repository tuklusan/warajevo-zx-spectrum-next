# CR-0212 Add Deterministic AY Register-Write and PCM-Hash Tests

Status: CLOSED

## Functional Inventory

- Exercise AY register-select and data-write events at exact master ticks,
  including invalid register selection and register edge values.
- Verify tone, noise, envelope, mixer, and beeper contributions produce stable
  canonical PCM samples for fixed deterministic inputs.
- Hash representative PCM output and assert repeatability across repeated runs,
  supported compilers, and machine profiles.
- Verify AY state serialization and restored generator state preserve subsequent
  PCM output, not merely register bytes.
- Keep audio tests headless and independent of Sokol, host audio devices,
  wall-clock pacing, and thread scheduling.

## Source Authority

- `design/warajevo-zx-spectrum-next-architecture.md` sections 20.3, 20.4,
  20.5, 38, 49.1, and 49.2.
- `design/wzsn-architectures-1-2-developer-tasks.md` task 197.
- `src/core/audio/wz_ay.c`, `src/core/audio/wz_audio_mixer.c`,
  `src/core/audio/wz_beeper.c`, and state serialization sources.
- Existing AY event, generator, mixer, PCM, and serialization tests.
- Preserved upstream `SPECSIM.ASM` audio register/timing behavior and the
  project’s frozen deterministic audio policy.

## Upstream Discovery

- Inventory upstream AY register timing, reset values, generator clocking,
  mixer ordering, and output scaling where applicable.
- Compare each behavior with the current deterministic audio implementation;
  hardware/reference evidence wins over historical shortcuts.
- Record any behavior not representable by the current PCM policy as an
  explicit deferred scope before implementation.

## Disposition

- Deterministic register-write event and PCM-hash regression tests:
  `IMPLEMENT_NOW`.
- Host audio delivery and Sokol push-audio behavior: outside this CR.
- Unevidenced analog/hardware behavior: `DEFERRED_WITH_CR`.

## Pre-Implementation Gates

- Enumerate all event, generator, mixer, state-restore, and hash behaviors
  before editing.
- Perform a second upstream zero-gap scan after implementation covering register
  edges, tick ordering, generator phase, mixer arithmetic, serialization, and
  PCM boundary conditions.
- Require exact-SHA CODE, DOCUMENTATION, and independent bootstrap reviews with
  zero findings before remote execution.
- Use local static gates only; all builds and tests run remotely or hosted.

## Evidence and Exit Gates

- Remote Linux sanitizer, Intel Mac, Windows 10, and Windows 11 validation pass.
- Hosted `platform-smoke` housekeeping, full matrix, and publication pass.
- Closure records exact hashes, commit range, review results, remote run IDs,
  hosted run ID, and the second upstream zero-gap result.

## Zero-Gap Exit Scan

- Confirm every scoped deterministic AY/PCM behavior has a reproducible fixture
  and no host-dependent audio path enters the expected hash.
- Confirm deferred analog and host-delivery behavior is explicit and tracked.
